## 2.8.0 에서 바뀐 것

정식 ZIP의 HELLO 전곡 기록은 **2.7.3 195 FPS · 2.8.0 192 FPS, 양쪽 모두 끊김 0번**입니다(3440×1440·165Hz). 서로 다른 시점의 실행 확인이며 성능 A/B가 아니므로 개선율로 해석하지 않습니다. HELLO 같은 타일 위주 맵의 FPS 변화는 거의 없었고, 아래 장식 개선은 Arche의 특정 구간에서 확인한 결과입니다.

### 플레이 중 끊김·장식 처리

- **곡 중 무작위로 길어지던 프레임을 줄였습니다.** 곡 중에만 메인·렌더 스레드의 우선순위를 함께 높이고, 곡 밖에서는 원래대로 돌립니다. 같은 PC의 HELLO 전곡 측정에서 **30ms 넘는 프레임 12·20개 → 0·1·2개**, Arche에서는 **11개 → 3개**였습니다. 기본 켬이며, 방송·녹화 프로그램이 CPU를 덜 받을 수 있어 설정에서 끌 수 있습니다. 모든 PC에서 끊김이 없어지는 것을 뜻하지는 않습니다.
- **움직이는 장식의 매 프레임 계산을 가볍게 했습니다.** 조건에 맞는 이미지 장식은 위치·회전·크기를 마무리하는 빠른 경로를 씁니다. Arche 곡 257.7~278.8초 A/B 측정에서 장식 마무리 처리 **1.35~1.42ms → 1.06~1.07ms**, 270초 구간 **93·96 → 102·102 FPS(약 8% 증가)**였습니다. 화면은 **2560×1440, 120Hz**였고, 같은 DLL로 판마다 게임을 새로 켰습니다. 곡 전체나 다른 해상도의 개선율은 아닙니다.
- **장식의 같은 계산을 겹쳐 하지 않습니다.** 위치 X·Y 애니메이션이 나란히 있으면 한 번에 반영하고, 보이는 이미지 장식의 회전·크기는 값을 저장한 뒤 같은 프레임의 마무리 단계에서 반영합니다. 마스크·히트박스 등 조건이 맞지 않으면 기존 처리를 쓰며, 다른 모드가 위치 설정 함수를 수정했다면 X·Y 합치기를 쓰지 않습니다.
- **장식 색을 바꾸는 경로를 줄였습니다.** 계속 보이는 이미지 장식은 같은 색 계산과 그리기 반영을 더 짧은 경로로 처리합니다. Arche 곡 252~273초, 판마다 새로 켠 ABBA 측정에서 장식 애니메이션 갱신 **1.93·1.94ms → 1.82·1.80ms**였습니다. 투명해지거나 다시 나타나는 순간은 기존 경로를 씁니다.
- **같은 각도의 회전 계산을 재사용합니다.** Arche 곡 252~273초 A/B/A 측정에서 장식 마무리 처리 **1.25ms → 1.18ms**였습니다. 이 측정은 게임 업데이트 뒤 Quartz를 끈 조건입니다.
- **투명한 장식의 이미지 교체를 필요할 때까지 미룹니다.** 히트박스·마스크가 없는 등 조건을 만족할 때만 적용하며, 다시 보이거나 이미지 정보가 필요해지면 먼저 반영합니다. Arche 곡 258초의 장식 이동 효과 처리 **15ms → 6.1ms**였습니다. 프레임 전체 시간이 아니라 해당 효과의 처리 시간입니다.

위 장식 최적화는 기본 켬입니다.

- **히트음 예약 묶기와 화면 밖 파티클 멈추기를 기본 켬으로 바꿨습니다.** 타일마다 히트음을 하나씩 예약하는 대신 0.5초 단위로 합쳐 예약합니다. Arche 곡 262~277초 구간 A/B(같은 구간, 설정만 바꿈)에서 **137·136 → 143·143 FPS(약 +4.7%)**, 게임 화면 경로 전곡(판마다 새로 켬)에서 **441 → 470 FPS(+6.6%)**였고 두 판 모두 끊김 0, 사용자 지정 히트음 등으로 원래 방식에 되돌린 횟수 0이었습니다. 화면은 2560×1440, 120Hz였습니다. 소리 타이밍·음량이 아주 조금 달라질 수 있어 **저사양 페이지**에서 끌 수 있습니다. 이전 버전에서 올린 분도 이번 한 번은 켜진 상태로 바뀌고, 그 뒤에 끈 선택은 유지합니다. 화면 밖 파티클 멈추기는 파티클이 많은 맵에서 CPU를 아끼며, 화면에 다시 들어온 파티클은 멈춘 곳부터 이어가 원래와 모양·시점이 조금 다를 수 있습니다. 기능별 측정 시점과 조건이 달라 개선율을 더할 수는 없습니다.

### 타일 처리

- **화면 밖 타일의 색 바꾸기를 미룹니다.** 타일이 다시 보이거나 다른 효과가 값을 필요로 하기 전에 반영합니다. 기본 켬이며, 설정 창의 `화면 밖 타일 색 바꾸기 미루기`에서 끌 수 있습니다. HELLO 플레이어용 자동 시험 ABBA에서 **12ms 넘는 프레임 102·102개 → 66·70개**였습니다.
- **불투명도만 바꾸는 타일 이동을 가볍게 했습니다.** 위치·회전·크기를 건드리지 않는 효과는 불필요한 위치 읽기와 계산을 건너뜁니다. HELLO의 타일 8,933개를 한꺼번에 바꾸는 길이 0 효과에서 **9.2~10.1ms → 4.4ms**였습니다. 길이가 있는 불투명도 전용 효과에도 적용합니다.
- **화면 밖 타일의 발광도 함께 그리기에서 뺍니다.** 화면에 가까워지기 전에 다시 켭니다. 다중 행성 연결선이 없는 타일은 매 프레임 필요 없는 위치·크기 읽기도 줄였습니다. 모두 기본 켬이며, 기존 타일·애니메이션 최적화가 적용되는 조건에서 작동합니다.

### 맵 불러오기·미리 준비

- **맵 파일 디스크 캐시**: 이미지 압축 결과와 JSON 해석 결과를 내장 드라이브의 사용자 캐시에 저장합니다. 기본 켬, 최대 **3GB**이며 공간이 부족하면 스스로 꺼집니다. HELLO 재방문 측정에서 **12.9초 → 11.6초**였습니다. 첫 열기는 캐시를 쓰느라 **0.1~1.2초 더 걸린** 기록이 있습니다(같은 PC의 맵 시험). 원본 파일이 바뀌면 다시 만듭니다.
- 재질 값을 이름 대신 번호로 찾도록 바꾸고, 그래픽 미리 준비 중 실패한 필터 정보를 다음 준비 때 다시 확인하도록 보강했습니다. 이 변경만의 FPS 개선 수치는 확인하지 않았습니다.
- **맵 문자열 재사용·로딩 업로드 예산·장식 태그 색인**은 **플레이 > 실험**으로 옮겼으며 새 설정에서는 기본 꺼짐입니다. 이미 저장한 값은 유지합니다. 이 셋은 2.7.3 정식에 없던 기능이며, 각각의 로딩 시간 단축은 따로 확정하지 않았습니다.

### 쉐이더 내 프리셋

**쉐이더 > 켜짐 > 내 프리셋**에서 지금 쉐이더 설정에 이름을 붙여 **최대 12개 저장·적용·덮어쓰기·삭제**할 수 있습니다. `모두 끄기` 뒤에는 `다시 켜기`로 직전 설정을 되살릴 수 있어 쉐이더를 일일이 껐다 켤 필요가 줄어듭니다. LUT 파일과 경로는 프리셋에 포함하지 않습니다.

### 설정 창의 새 실험 옵션

**플레이 페이지의 다섯 번째 탭인 실험**에 아래 선택을 모았습니다. 새 설정에서는 **기본 꺼짐**이며, 이미 저장한 값은 유지합니다. 설정 창에 보이는 이름을 기준으로 적었으며 성능 개선을 보장하지 않습니다.

| 옵션 | 하는 일 |
|---|---|
| 메모리 한도 자동 조절 (실험) | 남은 RAM과 게임 사용량에 맞춰 메모리 정리 한도를 조절합니다. |
| 맵 문자열 재사용 (실험) | 맵을 읽을 때 반복되는 짧은 문자열과 검색 버퍼를 재사용합니다. |
| 로딩 업로드 예산 (실험) | 이미지 미리 읽기 동안 비동기 업로드 예산을 늘리고 끝나면 복구합니다. 비동기 업로드가 가능한 에셋에 적용합니다. |
| 미세 위치 쓰기 생략 (실험) | 각 축의 위치 변화가 아주 작으면 쓰기를 생략합니다. |
| 장식 숫자 계산 묶기 (실험) | 조건에 맞는 직선 애니메이션의 숫자 계산을 묶습니다. |
| 계산 버퍼를 비관리 메모리에 (실험) | 숫자 계산 묶기의 버퍼를 별도 메모리에서 재사용합니다. |
| 계산 버퍼를 RAM에 고정 (실험) | 해당 계산 버퍼가 메모리에서 밀려나지 않도록 요청합니다. 앞의 두 옵션이 필요합니다. |
| 장식 태그 색인 (실험) | 재생 준비 때 태그에 번호를 붙여 반복 검색을 줄입니다. 표가 바뀌거나 변경을 안전하게 확인할 수 없으면 기존 검색을 씁니다. |
| 태그 번호를 비관리 메모리에 (실험) | 태그 색인의 번호만 별도 메모리에 보관합니다. 게임 객체는 그대로 둡니다. |
| 입력 프레임 대기 보정 (실험) | 키 메시지 수신 뒤 게임이 확인할 때까지의 대기만 보정합니다. 기존 비동기 입력에는 추가 적용하지 않습니다. |
| 입자 복귀 따라잡기 (실험) | 화면 밖에서 멈춘 파티클이 돌아올 때 지난 시간을 따라잡습니다. 화면 밖 입자 멈추기와 함께 씁니다. |
| 메인 스레드 오디오 방식 예약 (실험) | 메인 스레드에 오디오 방식 예약을 씁니다. 단독 이득은 확인되지 않았으며 끄면 일반 우선순위로 돌아갑니다. |
| 고성능 코어만 사용 (실험) | 윈도우가 코어 성능 등급을 구분해 줄 때만 사용할 코어를 제한합니다. |
| 0번 논리 코어 제외 (실험) | 곡 중 사용할 코어에서 0번을 뺍니다. |
| 곡 중 물리 시뮬레이션 중지 (실험) | 곡 중 물리 시뮬레이션을 멈췄다가 복구합니다. 충돌 콜백을 쓰는 다른 모드에 영향을 줄 수 있습니다. |
| 맵별 화면 설정 저장 (실험) | 다음 맵 열기부터 색감·선명도·해상도·프레임 늘리기 설정을 맵별로 기억합니다. |
| 끊긴 타일 상위 5개 기록 (실험) | 기존 모니터가 잡은 끊김의 타일 번호와 시간을 기록합니다. |
| 중립 필터 건너뛰기 | 픽셀 대조를 통과한 필터만 중립 값일 때 건너뜁니다. |
| 타이머 0.5ms 요청 (실험) | 윈도우에 더 짧은 타이머 간격을 요청합니다. 이미 짧은 환경에서는 변화가 없을 수 있습니다. |
| 보간 업로드 버퍼 재사용 (실험) | GPU가 사용을 끝낸 프레임 보간용 버퍼를 재사용합니다. 프레임 늘리기와 함께 씁니다. |
| 장식 목록 정리 생략 (실험) | 끝난 장식 애니메이션이 없으면 목록 정리를 생략합니다. 단독 끊김 개선은 확인되지 않았습니다. |

메인·렌더 스레드 우선순위는 플레이 > 기본에 남으며 기본 켬입니다. 장식 마무리 빠른 경로(TightLate)·색 직통 경로(ColorFast)·같은 각도 회전 재사용(EulerMemo)도 기본 켬입니다. `장식 목록 정리 생략`은 FastLane의 Compact 생략 선택이며 새 설정의 기본값은 꺼짐입니다.

개발자용: 연구 활성 파일 6종은 개발·자동 시험 빌드에서만 읽도록 정리했습니다.

### 게임 업데이트 대응·주의

- **Unity 6000.3.25f1 게임 업데이트의 입력 API 변경에 대응했습니다.** 입력 함수가 예상한 모양과 다르면 StutterFix의 해당 비동기 키 입력 최적화만 끄고 로그를 남깁니다.
- 게임 업데이트(Unity 6000.3.25f1) 뒤 Quartz 등 일부 모드가 입력 API 변경으로 예외를 내고 프레임이 크게 떨어질 수 있으며, 확인된 Quartz 사례는 StutterFix와 별개인 입력 패치 문제로 모드 폴더에서 Quartz를 꺼 정상 진행을 확인했습니다.
- 모드 다시 불러오기 뒤 맵을 열 때 게임이 종료된 기존 기록이 있습니다. 업데이트 적용은 게임을 완전히 껐다 켜 주세요.
- 위 수치는 기존 시험 기록이며 맵·PC·화면 조건에 따라 달라집니다. 새 버전 전체에 대해 모든 해상도·모드 조합의 끊김 제거를 보장하지 않습니다.

자동 업데이트를 켜 둔 분은 설치 알림 후 게임을 다시 켜면 적용됩니다. 문제가 있으면 설정 창의 `로그 내보내기`로 만든 ZIP을 보내 주세요.

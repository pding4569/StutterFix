# StutterFix 2.8.0 기능·토글 감사

조사일: 2026-10-19. 최종 검토 소스 기준: 642c28c(d362352의 기능 추가와 후속 입력칸·여백 변경 포함). **정적 조사만 수행했다.** 이 문서의 성능 수치는 기존 기록의 인용이며 새 측정이 아니다. 권고는 사용자의 정리 결정을 위한 제안이다. 이번 작업에서 기능을 켜거나 끄지 않았다.

## 먼저 볼 요약

### ① 정식 Player 신규 설정에서 기본 켬인 기능 — 이름만

GcPause, EffectSplit, RecolorSplit, RecolorDefer, TweenGuard, ZeroTween, InstantDirect, SkipSame, FastLoop, Precheck, DecoAnim, FloorAnim, MoveFinish, DormantSkip, SkipSameText, SkipInvisible, LazyHidden, SkipIdleParticles, FastBlend, HitTextFade, HitMeterFade, ImagePrefetch, SkipAssetUnload, LoadCache, LeakFix, ShaderWarm, FilterTypeCache, MeshWarm, SoundWarm, JitWarm, JsonStringPool, AsyncUploadBudget, AssetDiskCache, TagIndex, ThreadSchedulingMode=1, ThreadRenderScheduling, LegacyGfxJobs, NoGhosting, LowNoFft, FrameStats, CheckUpdates, GameScreenButton, HitchAlerts, OverlayMode=1, TightLate, EulerMemo, ColorFast, PairXY, DeferRotScale, LazySprite, FloorLateFix, CullGlow, FastOpa, FastLane Compact 생략.

조건부 기본 정책: ImageMaxSide=자동, FlipModel=현재 boot 상태 따름. TextGenerator 재사용·ParallelDecode·로딩 DecoBatch 등은 개별 Settings 스위치가 없으며 상위 기능을 따른다. FrameGenRefresh/Dense/BallMove가 true여도 FrameGenOutside=0이므로 **프레임 생성 전체는 기본 끔**이다. 모니터 세부 항목의 true는 표시 선택이며 최적화 기능 추가 활성화를 뜻하지 않는다.

### ② 측정과 배포를 다르게 만들 수 있는 곳: 18개 분류

D01 흑백 PNG 허용, D02 PairXY/GroupStep의 Prof 차단, D03 애니메이션 Shadow·재사용·Compact, D04 표본 원래 처리·재실행, D05 LoadFix 첫 지문 검증, D06 TransitionFix 재시작 교대, D07 Dormancy 안전망 주기, D08 ExitFix 태그 결과 교정, D09 이미지 대조 실패 폴백, D10 DevPresentFlags 전용 스위치, D11 상주 Batch의 시험 차단 조건, D12 PC 맞춤 자동 적용 억제, D13 Dev 프레임 통계 강제 끔, D14 관측 패치·시험 개입, D15 Settings 덮어쓰기·복구, D16 자동 플레이, D17 재생 시작점·FPS/출력 조작·캐시 조건, D18 MeasureBuild와 실제 컴파일 포함 범위.

18은 아래 D 표의 **차이 경로를 묶은 개수**다. 18개의 신규 버그나 항상 발생하는 차이를 뜻하지 않는다. 단순 로그·상태 출력·fixture 전용 선언은 따로 차이로 세지 않았다. 기본 끔인 실험 후보는 별도 표에서 다룬다.

### ③ 사용자가 결정할 항목

- 기본 켬 유지 근거가 충분한 핵심 기능과 TightLate·EulerMemo·ColorFast·메인+렌더 우선순위.
- **재검토**: JsonStringPool·AsyncUploadBudget·TagIndex·FastLane Compact·FrameStats. 이들은 기본 켬이나 개별 실사용 끊김 개선 또는 적용 범위의 동일성 근거가 약하다. 아래 권고는 끔(실험 탭)이다.
- 성능 손실/미미한 이득 후보 GroupStep·상주 DecoAnim Batch·DecoEngine·PosFast·TightLate.SkipSame·EvalMemo를 제품에서 없앨지. 아래에서는 없앰을 권고하며 연구 기록은 보존하는 전제다.
- LowNoFft·SkipIdleParticles·HitTextFade·ShaderWarm 등은 기존 기본 켬 유지 제안이지만, 항목별 증거 한계와 재검토 표시를 함께 읽어야 한다.
- 실험 페이지를 따로 모으고, 기본 켬 기능을 “기본으로 꺼져 있습니다”라고 안내하는 현재 문구를 정리할지.

## 기준과 근거 읽는 법

조사 도중 다른 작업의 커밋 d362352가 들어와 FxSlots/FxLastOn과 텍스트 입력 보호가 추가됐다. 변경을 되돌리지 않고 해당 부분을 추가로 읽어 235개 목록에 반영했다. 후속 0e977f1·642c28c의 입력칸 스타일·32자 UI 제한·여백 변경도 읽었으며 설정 필드·기본값의 추가 변화는 없었다. 이 감사가 소스나 커밋을 만든 것은 아니다.

- 정식 Player = Edition=Player, AutoTestBuild 미지정, 소스의 Main.MeasureBuild=false. 신규 Settings, 플래그 파일 없음, 안전 모드/오류 차단 없음, PC 맞춤 적용 전을 기준으로 한다. 실제 PC의 저장 설정·현재 설치 DLL·설치 플래그 상태는 이번 조사에서 검증하지 않았다.
- [Settings 선언](../StutterFix.cs#L1082)은 별도 Settings.cs가 아니라 StutterFix.cs 안에 있다. 로드는 ModSettings.Load → Resilience.Init → ApplyConfig/ApplyToggles → InstallAll → boot 상태 보정 → 빌드 전용 플래그 → TightLate/PosFast/ColorFast 설정 순서다([Load](../StutterFix.cs#L35), [Apply](../StutterFix.cs#L690)).
- 저장된 Settings.xml 값은 새 선언 기본값보다 우선한다. true로 바뀐 기본값이 기존 false 저장값까지 바꾸지는 않는다. 예외는 ImageAutoVer<1일 때 ImageMaxSide=0을 자동으로 옮기는 이행과 ShowOverlay→OverlayMode 이행이다.
- FlipModel=-1은 부팅 파일 상태를 읽어 0/1로 저장한다. LegacyGfxJobs·FrameStats·NoGhosting·이미지 한도처럼 다음 실행/불러오기에 반영되는 항목과 즉시 적용 항목을 구분해야 한다.
- PcTune은 첫 메뉴에서 PC 성능에 따라 LowAutoRes·LowAutoFps·LowFsr·LowCompressImages·LowMenuFps·LowSplit·LowPriority·LowNoThrottle·LowNoFft·LowPauseParticles를 자동으로 바꾸고 저장할 수 있다([PcTune](../PcTune.cs#L120)). 따라서 이 항목들의 “실제 최종 기본”은 모든 PC에서 하나로 고정되지 않는다.
- Resilience는 연속 비정상 종료 **2회**부터 안전 모드, 해당 기능 예외 **5회**부터 이번 실행만 차단한다([Resilience](../Resilience.cs#L18)). 과거 7회라는 기록을 현재 코드 사실로 사용하지 않았다. 안전 모드에서도 ImagePrefetch 자체는 남기고 이미지 축소가 필요한 경우로 제한하며 저사양 압축은 끈다.
- Compat의 다른 모드 설정, 지원 API·패치 소유자·맵 조건에 따라 활성 요청이 실제 사용으로 이어지지 않을 수 있다. 아래 “켬”은 후보가 허용된 상태이지 매 프레임 반드시 사용된다는 뜻이 아니다.
- E1=[README 기능 수치와 검증](../README.md#L78). E2=[optimization-36 진행·독립 검증](optimization-36.md#L56). E3=[10-18 채택과 후속 실측](optimization-36.md#L682). E4=[10-19 TightLate 이후](optimization-36.md#L836). E5=[ColorFast·Euler](optimization-36.md#L890). E6=[상수 버퍼 링](optimization-36.md#L624). 수치는 시험 범위에 한정한다. 픽셀/비트 동일, 곡 끝 상태 동일, 정책 검사 통과를 서로 바꾸어 쓰지 않는다.
- 표의 “측정 없음”은 이 감사에서 해당 스위치에 직접 귀속되는 성능 수치를 찾지 못했다는 뜻이다. 코드 존재나 빌드 성공을 이득으로 세지 않았다. “켬(기본), 재검토”는 현 상태 유지 제안이면서 증거 보강이 필요함을 뜻한다.

2. JSON/업로드/태그는 현 기본 켬과 별개로 실험으로 재검토. 디스크 캐시는 재방문 실측·복구 검증을 근거로 기본 켬 쪽으로 옮기되 첫 열기 쓰기 비용을 한 줄로 남긴다.

4. FrameGen·ConstantRing·ExpFullscreen·HalfRender·FilterIdentity·NativeMotion 계열·ParticleCatchup·MapProfiles·HitchHeatmap은 기본 끔으로 실험 페이지에 모은다. 파라미터 true를 전체 켬으로 보이게 하지 않는다.
5. LowRenderScale/FSR/DXT/NoFx/Fx는 사용자가 화면을 바꾸려고 선택하는 항목이다. 끔(실험 탭) 권고는 자동 기본 켬을 제안하지 않는다는 뜻이며, 기존 저사양/쉐이더/연출 페이지를 반드시 없애자는 뜻은 아니다.
6. GroupStep·상주 Batch·DecoEngine·PosFast·SkipSame 쓰기 후보·EvalMemo는 제품 토글 추가보다 제품에서 없앰을 권고한다. 진단 전용 검증/회귀 코드는 개발 빌드에 보존할 수 있다.
7. TightLate/EulerMemo/ColorFast는 기본 최적화로 설명하되 on/off 제어가 필요한 제품 지원 상황에서는 실제 런타임 상태·호환성 탈락 이유까지 보여 주는 방식을 검토한다. 연구 플래그를 사용자에게 그대로 노출할 필요는 없다.
8. 기본 탭의 “검증 중인 후보입니다. 기본으로 꺼져 있습니다” 문구는 현재 JSON·캐시·업로드 값과 맞지 않는다. Fx/FrameGen 하위 켬 값, 저장된 설정 유지, 재시작·다음맵 적용 시점을 구분해 안내한다.

## 이 감사의 한계와 후속 확인 우선순위

- 코드와 기존 근거만 검토했다. 게임 실행·빌드·설치·새 측정·패키지 생성·커밋을 하지 않았다. 실제 배포 ZIP과 현재 설치 DLL의 런타임 상태가 이 소스와 일치하는지는 미확인이다.
- 기존 기록의 모든 원시 로그를 다시 재계산하지 않았다. 역사적 측정·동일성 주장은 문서의 수치이고 이번 조사에서 재현한 결과가 아니다. 수치를 합산해 전체 개선율을 만들지 않았다.
- 우선순위1: 정식 Player/PlayerAuto의 동일 설정·파일·진입·화면 조건에서 상태 목록을 저장하는 후속 검증. 이 조사에서는 실행하지 않았다.
- 우선순위2: 기본 켬 재검토 항목(JSON·업로드·태그·FrameStats·FastLane)의 단독 OFF/ON과 실제 사용 횟수. 이미지/태그 결과 동일성과 끊긴 프레임 수를 함께 평가.
- 우선순위3: D08·D09의 Dev 교정 발생 유무 및 D02의 빠른 경로 사용 유무. Dev 대조 성공만으로 정식 경로 성공을 대체하지 않는다.
- 후속 정책/코드 변경은 사용자가 위 권고에서 선택한 뒤 별도 작업으로 진행한다.

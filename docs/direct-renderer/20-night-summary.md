## 밤에 확정한 사실
1. **Exit 는 CPU 병목**(화면 대기 0). 원본 2.68ms, 맵 그리기를 뺀 상한 2.09ms → 상한까지 가도 +28%. 메인 카메라 GPU 는 맵을 빼도 2.5ms 로 그대로.
2. **DD 의 24 FPS 붕괴 = VRAM 초과(14.1/7.53GB) + 우리 Grab 복사**: Grab 을 끄면 GPU 52~64ms → 6~8ms. M4l 의 "Grab 은 명령 목록 밖 즉시 복사" 로 해소(180 FPS). drawgpu: Grab draw 하나가 3.46ms.
3. **HELLO 배경색 = ColorWriteMask 비트 순서 버그**(Unity A=1..R=8 ↔ D3D11 R=1..A=8). 고친 뒤 PSNR 19.7 → 43.6. Codex 가 OneMinusSrcColor·Min/Max 블렌드 매핑 오류도 고침.
4. 명령 목록 캐시: 일시정지에서는 렌더 스레드 0.27~0.40ms 로 매우 좋다. **재생 중에는 그리기 순서가 프레임의 ~16% 에서 바뀌어 계획 전체를 다시 쓴다(1회 ~2.7ms)** — 국소 재계획(M4n WIP)이 다음 핵심.
5. 메인 스레드 collect 0.46~0.69ms 중 **캔버스 재확인 0.28~0.34ms**(UI CanvasRenderer.SetAlpha 수십만 회, 캔버스 노드 이동). 그래픽 단위·보임 여부만 재확인으로 바꿔 봤지만 다른 신호로 전체 재확인이 여전히 많다.
6. 측정 환경: JALib 이 시작 중 Harmony 를 자주 깨뜨려 측정 판에서만 끔(nojalib.txt), 강제 종료 뒤 안전 모드 오염 방지(session.lock 삭제·CrashStreak 0), 실패 시 스택 로그.

# ADOFAI 직통 렌더러 (Direct Renderer, DR) 설계 — 2026-11-14

사용자 지시(11-14): "아예 처음 근본부터 렌더러를 새로 만들라. 계산하는 쪽을 기존보다 훨씬 빠르게 할 수 있는 직통 경로를 세워야 한다."
화질 기준: 11-08 사용자 결정대로 "눈으로 같음" — 바이트 동일은 요구하지 않되, 같은 프레임 비교(framecmp)로 차이 수치를 항상 보고한다.

## 1. 왜 지금까지는 안 됐나 (반복 금지)

| 시도 | 구조 | 실패 원인(측정) |
|---|---|---|
| GpuDeco(현행) | 게임 장식 오브젝트·스크립트를 그대로 두고 일부만 GPU 로 그림 | 오브젝트·스크립트 유지비 그대로, 부분 소유라 정렬 동점·장벽, HELLO 3440 -10% |
| DecoEngine(10-19) | C# 엔진으로 장식 상태 계산 | 비트 동일·소유 81%인데 이득 0: 비용은 계산이 아니라 Unity 쓰기(Transform/Renderer) |
| 표 구동 adopt(10-21) | 굽기 표로 Unity 오브젝트를 움직임 | +0.45ms 손해: 역시 Unity 쪽 쓰기 |
| deco-v2 슬라이스(11-03) | 로드 때 굽기 + 원본 재질 스팬 | 스팬마다 dispatch·draw(777), 투명 장식까지 계산, 원본 재질 유지로 배칭 불가 → Exit 287→121 |
| 장식 떼기·배열화(11-12) | 기존 경로 미세 최적화 | 1% 단위 |

공통 원인: **계산 결과가 매번 Unity 객체(Transform·Renderer·Material)를 거쳐서 그려진다.** 그리고 소유가 부분적이라 나머지 Unity 렌더러와의 순서 맞추기 비용·제약이 남는다.

## 2. 직통 경로

```
[맵 열 때]  LevelEvent 목록 ──컴파일──▶ 장면 프로그램(네이티브 메모리, SoA)
                                      · 객체 표: 장식·타일·(행성 껍데기) 정적 속성, 정렬 키, 텍스처 번호
                                      · 트랙: 속성별 시간순 구간(시작·끝·시작값·끝값·이징) — 이벤트 시작 O(1) 색인
[매 프레임] 곡 시각 t + 카메라 1회 읽기
   네이티브 작업 스레드(SIMD): 활성 트랙만 평가 → 인스턴스 버퍼(2x3 행렬, 색, UV, 텍스처 층) 직접 씀
   보이는 것/정렬: 정적 정렬 키 + 깊이 이벤트 때만 다시 정렬, 화면 밖·알파 0 제외
[렌더 스레드] 플러그인 이벤트 1회: D3D11 로 camRT 에 순서대로 인스턴스 그리기(텍스처 배열로 긴 구간), 상태 저장·복원
```

- **Unity 객체 0**: 소유한 장식·타일은 GameObject/Renderer/Transform/DOTween 을 매 프레임 건드리지 않는다. 그 객체들의 스크립트(Update/LateUpdate/트윈)는 꺼 둔다.
- **게임 효과 이벤트 가로채기**: ffxMoveDecorationsPlus·타일 이동/색 등 소유 대상에 대한 효과는 이미 트랙으로 구워졌으므로 실행 시 게임 쪽 작업을 건너뛴다(로직·판정·히트박스가 필요한 경우만 예외 경로).
- **카메라 비용 0**: 시차(parallax)·카메라 고정·회전은 정점 셰이더에서 카메라 상수로 계산. 카메라가 움직여도 CPU 쓰기 없음.
- **완전 소유**: 메인 카메라 맵 내용(장식·타일·글로우)을 하나의 순서 스트림으로 그린다. 지원 못 하는 것(파티클·글자·행성·특수 셰이더)은 "남는 층"으로 Unity 가 따로 그리고, 그 층을 스트림 안의 제자리 항목으로 합성한다(구간 수를 작게 유지). 부분 소유로 생기던 동점·장벽 문제를 없앤다.
- **실패 시 원래대로**: 맵 단위로 켜고, 컴파일이 거절하면 그 맵은 원래 렌더러.

## 3. 단계와 합격선 (각 단계 ABBA·framecmp·복원 확인)

| 단계 | 내용 | 합격선 |
|---|---|---|
| M0 뼈대 | 네이티브 인스턴스 그리기 + 네이티브 트랙 평가 + 합성 스트레스 | 움직이는 사각형 3만 개: 메인 스레드 추가 < 0.1ms, 렌더 스레드 < 0.4ms, 그리기 호출 ≤ 텍스처 구간 수 |
| M1 이미지 장식 | 실제 맵 장식 컴파일(기존 DecoBake 표 재사용) → DR 로 그림, 원래 장식 렌더러·스크립트 끔 | Arche·Exit·HELLO: 메인 스레드 장식 몫 → 0.1ms 이하, framecmp 최대/평균 차이 보고 |
| M2 타일 | 타일 메시·색·이동(FloorAnim 표) 소유 | Exit 타일 숨김 상한(+14%)의 대부분 |
| M3 남는 층·완전 순서 | 행성·파티클·글자·마스크를 층 합성으로 | 거절 맵 0에 가깝게 |
| M4 GPU | 덧칠 줄이기(가려진 아래층 건너뛰기, 선택적 화면 LOD) | 3440 HELLO/DD/WF |

## 4. 측정 기준선 (3440 렌더, 11-14)

- 맵 내용 안 그림 + 타일 스크립트 끔(cpCeil) 대 현행: WF +59%, DD +56%, Exit +32%, HELLO +17%(GPU 병목).
- 장식만 숨김: DD +35%, WF +52%, HELLO +46%(GPU 덧칠 포함).
- 11-12(작은 창, CPU 병목): 맵 내용 그리기 전부 끔 +14~26%, 스크립트 44%(장식 경로 13~24%).

## 5. 원칙
- 특정 맵 상수 금지, 일반 규칙만. 매 프레임 할당 0. Main.Unload 원복.
- 측정은 ABBA, 판마다 새로 켬, `[곡 시작] 화면` 줄과 rtsize 확인.
- 코덱스는 구현·오프라인 검증, Claude 는 게임 측정·커밋.

## 문제
1. **drawn=0, draws=0**: 아무것도 그리지 않았다(가시 판정/화면 범위/카메라 행렬/camRT 크기 3440x1440 rtsize 와 창 2560 차이 등 확인). 그리기가 안 되면 GPU 비용을 못 잰다. 원인을 고치고 `dr state` 에 가시 판정에서 빠진 이유별 개수(화면 밖, 알파 0, 기타)를 추가.
2. **평가가 너무 느리다: 트랙 하나 약 233ns**(worker_sum/active). 목표는 **10ns 이하**(30k 인스턴스 70% 움직임에서 작업 합 < 0.3ms). 원인 후보: 트랙마다 포인터 따라가기·구조체 배열(AoS)·이징 함수 간접 호출·double 연산·스레드 동기화·가시 판정 겸 압축 비용·캐시 미스. 고칠 방향: 채널 SoA, 활성 구간을 연속 배열로(구간 시작 때 슬롯에 복사: t0, invDur, start, delta, ease), 이징별로 묶어 분기 없는 루프(같은 이징끼리 정렬), SIMD(SSE/AVX2, i5-9400F 는 AVX2 있음), 스레드에 큰 연속 덩어리, 인스턴스 버퍼 쓰기도 연속.
3. **작업 스레드가 게임과 CPU 를 다툼**: N=3000 에서도 -3~4% (i5-9400F 6코어, SMT 없음, Unity 작업 스레드 5개). 기본 스레드 수를 1~2로, 평가를 렌더 스레드 이벤트 직전까지 다 끝내도록 시작 시점을 앞당기기(Update 직후 시작이면 렌더까지 시간이 충분한지 확인). 단일 스레드로 30k 를 0.3ms 안에 끝내는 것이 이상적.

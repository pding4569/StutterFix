# DDONGSSADA 390~415초 45 FPS: VRAM 예산 초과로 쓰는 텍스처가 시스템 RAM 에 놓임 (2026-11-25)

## 증상
- dropscan8: DD 곡 390~415초에 18ms 넘는 프레임 약 620개(22ms 안팎 연속, 약 45 FPS). 메인 스레드 표본 84% 가 `GfxDeviceClient::WaitForPendingPresent`(GPU 대기).
- 재생 중 본 카메라 GPU: 380초 5.8ms, 395초 15.2ms, 403초 18~22ms(멈춰도 같음). 화면은 거의 검정.

## 나눠 본 것 (403초 정지, 본 카메라 GPU, 기준 21.6ms)
| 숨긴 것 | 개수 | GPU ms |
|---|---|---|
| 장식 전부 | 32,572 | 1.10 |
| 큰 장식(25 단위 넘음) | 91 | 1.14 |
| 텍스처 1024~2047 장식 | 1,686 | 2.07 |
| 반복 무늬(50x50 이상) | 17 | 6.75 |
| 타일 / 행성·파티클 | | 20.4 / 21.2 |

- 장식 필터(UpdateShader 경로) 장식은 0개, 묶어 그리기(MPB) 영향 없음, 장식 MPB 의 _MainTex 는 스프라이트 텍스처와 같음.
- 큰 장식 텍스처를 밉맵 사본으로 바꾸면 2.9ms 인데, **원래 텍스처로 되돌린 뒤에도 2.6ms 로 빠른 채** 남았다 → 샘플링 방식이 아니라 텍스처가 놓인 메모리 문제.

## VRAM
- 메모리의 Texture2D 3,401장, 약 32억 픽셀(RGBA 로 약 12.8GB). 지금 보이는 장식 텍스처는 25~28장, 약 160MB 뿐.
- 게임 전용 VRAM 은 약 5.8GB 에서 더 늘지 않음(카드 8GB, 전체 사용 6.3GB). 게임 공유(시스템 RAM) 사용량:
  맵 연 직후~157초 6.8GB → 160초 20MB → 곡 300~340초 15~20MB → **345~370초에 5초마다 약 1.4GB 씩 늘어 5.5GB**. 그 뒤 390~415초가 느린 구간.
- `ImagePrefetch` 끔(원래 게임 불러오기)도 같은 모양이고 403초 42.5ms 로 더 나쁨 → 모드 불러오기 탓 아님. GPU 장식은 이 맵에서 꺼짐(지원 34% < 50%).

## 시험한 고치기 (모두 403초 정지, 그림에 영향 없는 것)
| 시도 | 결과 |
|---|---|
| 보이는 텍스처를 작은 RT 로 Blit(건드리기) | 21.8 → 21.6 |
| 큰 RT 만들었다 바로 놓기(64/256/1024MB) | 변화 없음 |
| 더미 RT·Texture2D 256MB 를 들고 있다 놓기 | 변화 없음 |
| DXGI 축출 우선순위(보이는 것 MAX, 나머지 MIN) | 21.1 → 21.0 |
| 보이는 텍스처를 바이트 동일 GPU 복사본으로 바꿔 그림 → 원래로 되돌림 | 그대로 21.1 |
| 위에 이어 **복사본 지우기** | **3.8ms** (재생 이어간 407초도 3.8ms) |
- 재생 중 389초에 한 번 하면 그때 보이던 11장은 고쳐지지만 뒤에 새로 보이는 텍스처는 다시 시스템 RAM 에 있어 12~18ms 로 돌아감.
- 드라이버(VidMm)가 왜 이 순서에서만 올려 주는지는 설명 못 함. 재현은 세 판 모두 같음.

## 선택지
1. VramGuard(자동 큰 이미지 줄이기)의 판단에 "게임 공유 사용량" 또는 DXGI 예산(QueryVideoMemoryInfo)을 넣어 이런 맵을 더 줄임 → 확실하지만 그림이 흐려짐(DD 는 이미 긴 변 1536, 다음 단계 1024).
2. 바이트 동일 복사본 바꿔 끼우기를 새로 보이는 텍스처마다 자동으로 → 그림은 같지만 드라이버 동작에 기대는 방법, 복사본 생성 비용·검증 필요.
3. 곡 시간표로 곧 쓸 텍스처만 GPU 에 두는 스트리밍 → 정석이지만 큰 작업, 불러오기 끊김 위험.

## 진단 명령 (개발자용·자동 시험)
`vram`, `texcensus`, `texwarm blit|copy`, `vrampoke <MB>`, `vramhold <MB> [tex|rt]|free`, `texswap on|off|offkeep|free`, `texprio on|normal`, `mpbtex on|add|off`, `decofx`, `hidegroup decomesh|tex:<이름>` (hidegroup 결과에 카메라 직교 크기).

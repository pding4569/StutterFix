# 8비트 ROP와 같은 결과를 내는 합성기 설계

2026-11-13. 연구 설계이며 제품 구현·승인이 아니다. [실험 결과](../handoff/gpu-exact-20261113-result.md).

## 현재 결론과 입장 조건

RTX 4060 Ti의 독립 D3D11 실험에서 단순 float 반올림·9/10비트 양자화 등 10개 후보 중 실제 프리멀티플라이 블렌드를 모든 시험 입력에서 재현한 식은 없었다. 따라서 현재 식을 compute에 넣고 제품 렌더러를 바꾸면 안 된다.

대안으로 **실제 ROP에서 측정한 256상태 전이표**를 쓸 수 있다. 고정 소스 RGBA와 고정 블렌드 상태에 대해 대상 채널 d=0..255를 한 번씩 그려 f(d)를 얻는다. CPU 또는 compute에서 `T[k,d]=f(T[k-1,d])`, `T[0,d]=d`를 만든다. 반복 합성 시험에서 경험적 전이표는 k=2..255와 일치했다. 이것은 일반 산술식 발견이나 모든 사용자 GPU 검증을 뜻하지 않는다.

이 경로는 입력 색·알파의 **float 비트**, 셰이더가 실제 출력한 프리멀티플라이 값, 블렌드 인자·연산·쓰기 마스크, RT 형식·색 공간·MSAA를 모두 키로 가져야 한다. 알파만 8비트로 반올림해서 키를 줄일 수 없다. 이번 float 알파 시험에서 그런 후보도 실패했다. RGB 세 채널과 A는 별도 전이가 필요하다. 최악의 4채널 × 256상태 × 256반복 × 1바이트는 소스 하나당 256 KiB이며 GPU 표현/정렬 비용은 별도다. 이득보다 표 생성·캐시 비용이 크면 기존 경로를 쓴다.

## 실제 블렌드와 채널 식

Q는 GPU의 실제 UNORM 블렌드 경로 전체를 뜻한다. 아래 Q를 단순 `round(x*255)`로 구현할 수 있다고 가정하지 않는다. s,a는 텍스처 샘플·tint·재질을 반영한 출력 직전 값이다.

| 경로 | PS 출력 | RGB | A |
|---|---|---|---|
| Sprites/Tile, Sprites/Default, GpuDeco 기본 | (s·a,a) | Q(s·a+d·(1-a)) | Q(a+dA·(1-a)) |
| 일반 straight 비교군 | (s,a) | Q(s·a+d·(1-a)) | Q(a²+dA·(1-a)) |
| Legacy Particles/Additive | 원래 PS 출력(s,a) | Q(s·a+d) | RGB 쓰기 마스크이므로 dA 유지 |
| GpuDeco LinearDodge | (s·a,0) | Q(s·a+d) | dA 유지 |
| One/One 비교군 | (s,a) | Q(s+d) | Q(a+dA) |

실수 대수에서 같은 두 가산 경로도 소스 곱셈과 ROP의 내부 변환 위치 때문에 비트 동일을 별도 확인해야 한다. Grab 블렌드는 화면 복사와 추가 PS 계산이 있어 단일 Q 경로가 아니다. `GpuDecoBatch`의 `_SrcBlend/_DstBlend/_BlendOp` 재질 값도 키에 넣는다. 원본 에셋 상태는 [asset-states.json](../../tools/blendlab/asset-states.json), 타일 PS 곱셈은 `out/original-tile-shader/program-4.txt`의 `mul o0.xyz, r0.wwww, r0.xyzx`에서 확인했다.

## 1. 같은 층 반복 LUT

원본 아래→위 순서를 먼저 확정한다. **인접한** 같은 텍스처·같은 실제 출력색·같은 알파·같은 블렌드 층만 묶는다. 픽셀별로 모든 층이 실제 포함되는지 확인한 뒤 k를 센다. 공간적으로 겹치지 않는 층을 전체 k로 적용하면 안 된다. 텍스처 좌표·repeat·flip·회전·샘플러도 검증한다.

텍셀 알파 1 영역만 첫 대상으로 삼는다. bilinear는 필터 발자국 전체가 알파 1이어야 하며, mips·trilinear·anisotropic은 최초 범위에서 제외한다. 알파 1이어도 RGB 텍스처 값이 변하면 같은 소스색이 아니다. 초기 제품 후보는 **RGB도 같은 상수 내부**로 제한하거나 픽셀별 샘플 RGB 비트를 확인해야 한다. 센서스의 `runs_texel_alpha1_estimate`는 이 조건 전의 느슨한 면적 추정치다.

가장자리는 같은 픽셀 목록에서 원래 순서로 개별 처리한다. 지원하지 않는 PS/블렌드라면 구간 전체를 원본 드로우로 돌린다. 아직 일반 Q식이 없으므로 가장자리 일반 compute 흉내는 현재 사용할 수 없다. 255층을 넘으면 검증된 255층 표를 순차 적용한다. 층 전체를 한 식으로 합치는 `1-(1-a)^k`는 사용하지 않는다.

## 2. 고정점 조기 종료

아래→위로 누적한 현재 RGBA 바이트 d에 대해 **남은 모든 서로 다른 전이**가 `f_j(d)=d`인지 확인해야 한다. 한 층의 고정점이라는 사실이나 실수 알파 누적이 1에 가깝다는 이유로 종료하면 안 된다. 같은 소스 run이면 한 번의 고정점 조회로 남은 run만 생략할 수 있다. 뒤에 다른 색·가산·Grab이 있으면 다시 처리한다. 픽셀별 suffix 전이의 고정점 교집합을 미리 만들 수 있지만 목록 생성비와 저장비를 측정해야 한다.

실측 예: a=5.1/255를 float로 계산한 PMA 출력에서 RGB 고정점은 검정 0..25, 128/255 회색 128..178, 흰색 230..255였다. 이는 float 비트·GPU·실험 PS에 종속된다. `a=0.02`를 임의 GPU 공통 상수표로 쓰지 않는다.

## 3. 아래쪽 연속 층 캐시

주 카메라 clear와 배경부터 원본 렌더 순서의 **맨 아래 연속 prefix**만 재사용한다. clear 색·RT 내용·타깃·viewport·해상도·색 공간·MSAA·정렬·컬링·VP×localToWorld 비트·sprite geometry/UV·texture 버전·sampler·재질·MPB·active 상태가 같아야 한다. 월드 고정 물체라도 카메라 이동으로 화면 행렬이 달라지면 무효다. 움직이는 도중 새 물체가 prefix 아래 끼거나 기존 물체가 사라져도 무효다. 변화 없는 층 전체를 모아서 캐시하면 중간에 끼인 움직이는 층과 순서가 바뀐다.

캐시는 필터 적용 전 선형 원본 RT의 정확한 바이트여야 한다. RGBA8 복사로 시작하고 추가 블렌드·색 변환을 피한다. skybox·DepthOnly·DontClear·외부 카메라·화면 읽기·시간/전역값 의존 셰이더·미추적 MPB·파티클·스킨 메시·동적 텍스처·SortingGroup은 처음에는 prefix 장벽이다. 텍스처 updateCount가 모든 외부 GPU 쓰기를 포착한다고 가정하지 않는다. 센서스의 일치 서명은 연구 추정이며 캐시 사용 허가가 아니다.

## 4. 타일 분류와 픽셀별 순서 목록

1. main-camera 직전 원본 목록을 수집한다. 목록과 정렬을 검증하지 못한 프레임은 원본으로 보낸다.
2. 16×16 또는 32×32 타일에 보수적 geometry bounds로 층 인덱스를 넣되 아래→위 순서를 유지한다. 목록 overflow는 해당 타일/구간 원본 fallback이며 조용히 버리지 않는다.
3. prefix 캐시를 정확히 복사하거나 원본 clear에서 시작한다. 캐시의 층/타일 경계를 고정한다.
4. 각 픽셀에서 실제 geometry/coverage·UV·필터 발자국을 확인한다. 지원되는 상수 내부 run에는 LUT, 고정점 suffix에는 종료를 적용한다. 일반 PS 계산은 처음에는 원본 draw로 남긴다.
5. 각 채널을 byte 상태로 유지하고 마지막에 한 번 쓴다. 반올림은 각 층의 f 내부에 있어야 한다. 화면에 복귀할 때 추가 블렌드를 하지 않는다.

지원 run과 원본 가장자리의 순서를 분리하려면 스텐실/coverage 분할 또는 구간별 중간 RT가 필요하다. 이 추가 패스 비용까지 포함한다. 필터는 원래 실행 위치에서 그대로 처리하고 캐시/LUT 경계를 넘어 이동하지 않는다. GrabPass·SpriteMask·다중 패스·파티클은 처음에는 원본 장벽이다. 서로 섞인 영역을 무시하고 compute 결과를 마지막에 올리는 것은 금지한다.

## 정렬 동점 규칙 [[unity-tie-sort-rule]]

기존 `SceneRenderOrder.Key`는 sorting layer 값→sorting order→render queue→거리 역순→셰이더 ID→재질 ID 순이다. 같은 종류 셰이더의 ID 다음 재질 ID는 기존 게임 관찰 규칙이다. 다중 패스/Grab에는 기존 `ShaderRank` 보정이 있으나 Unity 일반 계약으로 확대하지 않는다. **같은 재질까지 동점인 renderer의 최종 순서는 미확정**이며 renderer ID는 진단 정렬의 결정성만 준다. 그런 버킷은 합성·캐시에서 제외한다. SortingGroup 내부 순서도 별도 검증 전 제외한다.

## 사용자 GPU 자체 검사와 원본 복귀

제품 활성화 전 실제 API·어댑터·드라이버·RT linear/sRGB·색 공간·샘플 수·쓰기 마스크별 ROP 기준과 compute/LUT 결과를 비교한다. 8비트 입력 전수와 실제 PS 출력 float, 경계/반올림/포화값, RGBA 독립 패턴, k 반복을 포함한다. 작은 최초 검사 통과를 전체 경로 통과로 취급하지 않는다. 새 소스 LUT는 실제 출력값으로 생성한 뒤 별도 반복 드로우로 검증한다.

불일치 **한 바이트**, 장치 재생성, 드라이버/RT 변경, 미지원 shader/pass/blend/mask, 순서 불확정, stale texture, 목록 overflow, 할당 실패, readback 실패가 있으면 해당 연구 경로를 비활성화하고 같은 프레임 원본 렌더러를 선택한다. 원본을 먼저 숨긴 뒤 실패를 알아내는 구조는 금지한다. 사용자 GPU 자체 검사·복원·전체 곡 픽셀 비교·실제 무거운 구간 프레임 시간 검증을 통과하기 전 제품 기본값을 바꾸지 않는다.

## 센서스와 예상 상한 계산

AUTOTEST 전용 `gpuexact census N`은 N개의 실제 카메라 프레임과 N-1개 전이를 관찰한다. 마지막에 prefix, unchanged_all, runs, runs_texel_alpha1_estimate의 mean/min/p10/p50/p90/max를 한 번 출력한다. 분모는 프레임별 **투영 AABB 면적 합계**이며 true fragment 수나 성능 비율이 아니다. unknown·MPB·마스크·그룹·미확정 동점은 장벽이다. 텍셀 히스토그램은 UV/화면 덮임 가중이 아니므로 내부 비율은 추정치다.

실제 fragment census를 추가해 F=전체 조각 수, P=캐시 prefix 조각 수, R=prefix 밖 정확한 상수 내부 반복 조각 수, G=그 run의 픽셀별 대표 1회 조각 수, X=나머지 고정점 종료로 제거되는 조각 수를 얻으면:

`saved = P + (R-G) + X`, `s = clamp(saved/F,0,1)`.

서로 겹치는 절감 영역은 한 번만 센다. 현재 센서스만으로 G와 X는 얻을 수 없다. 센서스 p,r,i를 사용할 때 느슨한 면적 proxy 상한은 `min(1,p+i)`이고 실제 fragment 절감 상한으로 보장되지 않는다. 두 비율을 단순 합해 확정 절감으로 보고하지 않는다.

GPU 시간에서 해당 fragment/ROP 비용 비중을 b라 하면 비용 0의 이상적 배수는 `1/(1-b*s)`. 실제 예상 시간은 `Tnew = Told*(1-b*s) + Tclassify + Tlist + TLUTbuild/amortization + Tcachecopy + Tboundaries + Tvalidation`. 각 추가항은 실측해야 한다. CPU/GPU 겹침 때문에 이 식의 GPU 배수가 게임 FPS 배수와 같다고 가정하지 않는다. 현재 센서스 숫자·b·추가 비용·실제 게임 향상은 모두 미측정이다.

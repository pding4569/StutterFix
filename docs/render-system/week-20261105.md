## 1. 진짜 FPS와 로직 FPS

`DisplayPace`(화면에 나갈 프레임만 그리기)의 2~3배는 로직 프레임 수다. 그림은 주사율로 제한되므로 화면에 나가는 FPS를 올리는 기능이 아니다. 끊김과 입력 처리 간격에 어떤 영향이 있는지는 실제 플레이로 확인해야 한다.

### 진짜 FPS 이득: JIT 인라인 + 홀드 건너뛰기 + 마스크 패치

12초 구간, 끔은 앞뒤 2판 평균, 켬은 1판.

| 맵 | 끔 앞/뒤 | 켬 | 변화 |
|---|---|---|---:|
| HELLO 2026 | 207.7 / 209.4 | 222.3 | +6.6% |
| Exit | 280.4 / 286.4 | 352.0 | +24.2% |
| DDONGSSADA | 212.6 / 231.9 | 243.0 | +9.3% (끔 차이 큼) |
| Windflower | 197.6 / 197.8 | 206.1 | +4.2% |

Exit 이득의 상당 부분은 마스크 패치다(단독 단판 +11.8%). 이 패치는 게임 업데이트마다 맞춰야 해서 기본 끔이다.

### 로직 FPS: 위 묶음 + DisplayPace, 곡 전체 곡당 1판

| 맵 | 평균 FPS | 곡 시작 연출 뒤 최악 | 끊김 |
|---|---|---|---|
| HELLO 2026 | 251 → 528 | 213 → 20ms | 1 → 0 |
| Exit | 365 → 1051 | 12 → 39ms | 0 → 1 |
| DDONGSSADA | 300 → 762 | 79 → 25ms | 6 → 0 |
| Windflower | 299 → 860 | 22 → 20ms | 0 → 0 |

Exit의 39ms 끊김은 원인 미확인이다. DDONGSSADA 끔 판의 끊김은 압축 캐시 상태 영향일 수 있다. 시간 누적은 HELLO 12초 구간에서 엔진 시계 대비 최대 오차 6.6ns로 맞았다. 장식 최종 값과 픽셀 동일성은 증명하지 않았다. Arche 무거운 구간은 96 → 104로 그릴 프레임을 건너뛸 여유가 없다.

## 2. 게임 2개 동시 실행

- 단독 559·561 FPS, 동시 각 432~440 FPS(단독의 78%). 합계 약 870 FPS(1.56배).
- 재생 중 표본(단독 44개, 동시 100개): 메인 스레드 96 / 92%, 렌더 스레드 43 / 35%, 전체 CPU 60 / 90%, GPU 37 / 46%, GPU 클럭 2037 / 2710MHz.
- 해석: 단독 판에서 메인 스레드 하나가 꽉 차 있고 CPU·GPU 전체에는 여유가 있다. 스레드 CPU 시간에는 회전 대기가 섞일 수 있어 남은 여유의 정확한 양은 아니다. 맵 1개(2022), 2560 창 모드 결과다.
- 계산을 나누거나 번갈아 그리는 기능은 구현·시험하지 않았다. 1.56배는 두 게임이 각자 전부 계산할 때의 합이다. 장식 계산만 넘기는 것은 `DecoEngine` 때 계산이 비용이 아니라 쓰기가 비용이라는 기록(Arche 3.04→3.02ms)이 있어 기대가 작다. Arche 동시 실행 시험은 사용자 요청으로 중단되어 값이 없다.

## 6. 이번 주에 알게 된 것

- 압축 캐시 상태로 같은 DD 구간이 76~236 FPS로 갈렸다. 11-04 이전 일부 ABBA는 이 변수가 섞였을 수 있다.
- 분석 스크립트를 게임과 함께 돌리면 끊김이 생긴다. 1초마다 `nvidia-smi`를 부른 판도 FPS가 낮게 나왔다(HELLO 192).
- 모드 빌드 훅이 C: 옛 복사본을 설치한 사고가 있었다. 시험 뒤 설치 DLL 대조가 필요하다.
- Unity 동점 정렬은 셰이더 ID, 재질 ID 순이다.
- 게임 구조 전체를 `docs/render-system/00~07`에 정리했다. 게임 핵심 로직은 1~2%이고 비용은 맵 시스템과 엔진 호출에 있다.

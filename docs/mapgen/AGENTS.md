# 얼불춤 맵 생성기 (시작 문서)

노래 파일(mp3/ogg/wav)을 넣으면 얼불춤(A Dance of Fire and Ice) 맵(`.adofai`) **초안**을 만든다.
박자에 맞는 타일 + 변속 + 음악에 맞춘 모션 그래픽 연출. 사람이 에디터에서 다듬는 것을 전제로 한다.

이 문서는 StutterFix 프로젝트(`pding4569/StutterFix`)에서 넘겨받은 것이다. 성능 측정 근거는 그 저장소의 `CLAUDE.md` 에 더 있다.

> **표시 규칙**: 이 문서에서 `[확인]` 이 붙은 것은 기억이나 추론으로 적은 것이다. 게임에서 만든 실제 맵과 대조해 확정하기 전에는 믿지 않는다.
> 확정하면 `[확인]` 을 지우고 어떤 맵·어떤 방법으로 확인했는지 한 줄 적는다.

---

## 0. 규칙

- 한국어로 대화한다.
- **허락받은 곡만** 쓴다. 노래 파일, 만든 맵, 남의 맵은 저장소에 올리지 않는다(`.gitignore`: `songs/`, `out/`, `ref/`).
- 다른 사람의 맵·모드 코드를 복사하지 않는다. 남의 맵은 **형식 확인과 통계(숫자)** 용으로만 읽는다.
- 게임 DLL·디컴파일한 게임 코드는 저장소에 넣지 않는다.
- 개인 정보(이메일 등)는 어디에도 쓰지 않는다.
- 측정·대조로 확인하지 않은 것을 "된다"고 하지 않는다.

## 1. 단계 (한 단계씩, 게임에서 열어 확인한 뒤 다음으로)

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| 0 | **형식 확정**: 템플릿 맵, 타일 시각 계산기, 정답지 대조 (2장, 8장) | 남의 맵 10개 이상에서 계산한 타일 시각이 게임 값과 모두 1ms 안 |
| 1 | **박자 타일**: BPM 하나, 오프셋, 직선과 꺾기, 쉼 | 4분 곡 하나를 자동 플레이로 끝까지, 사람이 쳐서 싱크 이상 없음 |
| 2 | **변속**: 곡 템포가 바뀌는 곡, 가독성용 배속 | 템포가 바뀌는 곡에서 누적 오차 1ms 안 |
| 3 | **기본 연출**: 강한 박에 카메라·번쩍·흔들림, 구간마다 색 | 성능 예산(7장) 통과, 끊김 검사 통과 |
| 4 | **구간 연출**: 도입·벌스·상승·드롭 알아보기, 필터, 카메라 전환 | 드롭이 "드롭처럼" 보인다 (사람 판단) |
| 5 | **장식 모션 템플릿**: 링, 선, 파티클, 이퀄라이저 | 장식 수·움직임 수 예산 안, 끊김 없음 |

첫 버전은 **BPM 하나, 행성 2개, 회전 방향 바꾸기(Twirl)만, 미드스핀·홀드·자유 이동 없음**.

## 2. .adofai 형식

### 2.1 확정하는 방법 (0단계에서 먼저)

1. 지금 게임 버전 에디터에서 **빈 맵을 새로 만들어 저장**한다. 이것을 `template/blank.adofai` 로 둔다(저장소에 넣어도 됨, 노래 없음).
   생성기는 이 템플릿을 읽어 `settings` 의 모든 기본값을 그대로 쓰고, 필요한 칸만 바꾼다. 필드 이름·값 형식(`"Enabled"` 문자열인지 `true` 인지 등)을 추측하지 않기 위해서다.
2. 에디터에서 이벤트를 하나씩 넣어 저장하고(속도 바꾸기, 회전 방향 바꾸기, 카메라, 번쩍, 필터, 장식 등) 그 줄을 `template/events/<이벤트>.json` 으로 떼어 둔다. 생성기는 이 조각을 복사해 값만 바꾼다.
3. 파일 인코딩(앞에 BOM 이 있는지), 줄바꿈, 끝에 남는 쉼표 등은 템플릿과 똑같이 쓴다.
4. 읽기는 관대하게: 사람이 만든 맵에는 끝 쉼표, 주석 비슷한 것, 옛 형식(`pathData`)이 섞여 있다.

### 2.2 큰 구조 `[확인]`

```
{
  "angleData": [0, 0, 90, 0, ...],     // 타일마다 나가는 방향(도). 999 = 미드스핀
  "settings": { "version": ..., "songFilename": "song.ogg", "bpm": 120, "offset": 0, "pitch": 100, ... },
  "actions": [ { "floor": 10, "eventType": "SetSpeed", ... }, ... ],
  "decorations": [ { "eventType": "AddDecoration", ... }, ... ]
}
```
- 옛 맵은 `angleData` 대신 글자 목록 `pathData`(R, U, L, D 등)를 쓴다. 읽기만 지원하고 쓰기는 `angleData` 로.
- `floor` 는 타일 번호(0 = 시작 타일). `angleOffset` 은 그 타일 안에서 이벤트가 걸리는 위치(도, 박자로 바꾸면 각도/180박) `[확인]`.
- `eventTag` 로 이벤트에 이름을 붙여 다른 이벤트가 부를 수 있다 `[확인]`.

### 2.3 타일 사이 시간 (핵심) `[확인]`

각도는 0 = 오른쪽, 90 = 위, 반시계 방향이 + 이다.
타일 i 의 방향을 a[i] 라 할 때, 행성은 들어온 쪽(a[i-1] + 180)에서 나갈 쪽(a[i])까지 돈다.

```
시계 방향(기본):     돈 각도 = (a[i-1] + 180 - a[i]) mod 360,  0 이면 360
반시계(Twirl 홀수 번 뒤): 돈 각도 = 360 - (위 값),            0 이면 360
박 수 = 돈 각도 / 180
초     = 박 수 × 60 / 그 타일의 BPM
```

| 원하는 간격 | 돈 각도 | 모양 (오른쪽으로 오다가, 시계 방향) |
|---|---|---|
| 1박 | 180° | 직선 |
| 1/2박 | 90° | 위로 꺾기 |
| 1/3박 | 60° | 위로 더 날카롭게 |
| 1/4박 | 45° | 아주 날카롭게 |
| 3/2박 | 270° | 아래로 꺾기 |
| 2박 | 360° | 온 길로 되돌아감 = **타일이 겹침** → 쓰지 않음 (쉼으로) |

생성할 때(원하는 박 수 b, 이전 방향 p):
```
시계:   a = (p + 180 - 180·b) mod 360
반시계: a = (p + 180 + 180·b) mod 360
```

확정이 필요한 것:
- 첫 타일(0번) 앞의 방향을 무엇으로 보는지, 마지막 타일 처리.
- 미드스핀(999): 시간 0 이고 다음 타일의 기준 방향을 뒤집는다고 알려져 있다. 1단계에서는 안 쓴다.
- 행성 3개(MultiPlanet)일 때 각도 계산이 달라진다. 1단계에서는 안 쓴다.
- 쉼(Pause)·홀드(Hold)·자유 이동(FreeRoam)이 시간에 더하는 양.

### 2.4 시간을 바꾸는 이벤트 `[확인]`

| 이벤트 | 하는 일 | 주요 칸 |
|---|---|---|
| `SetSpeed` | 그 타일부터 BPM 바꿈 | `speedType`: `"Bpm"` 이면 `beatsPerMinute`, `"Multiplier"` 면 `bpmMultiplier`. `angleOffset` |
| `Twirl` | 그 타일부터 회전 방향 뒤집기 | 없음 |
| `Pause` | 그 타일에서 N박 멈춤 | `duration`(박), `countdownTicks` |
| `Hold` | 누르고 있는 타일 | `duration` |
| `MultiPlanet` | 행성 수 | `planets` |
| `Checkpoint` | 연습용 시작점 | `tileOffset` |

## 3. 노래 분석

라이브러리: `librosa`(분석), `numpy`, `soundfile`/`audioread`(읽기). mp3 는 ffmpeg 가 필요할 수 있다.

### 3.1 BPM 과 오프셋

- `librosa.beat.beat_track` + 템포그램으로 BPM 후보를 낸다. **절반/두 배 혼동**이 흔하므로 후보 2~3개를 보여 주고, `--bpm` 으로 사람이 정할 수 있게 한다.
- BPM 은 소수점까지 유지한다(예: 174.0, 128.003). 반올림하면 4분 곡에서 수십 ms 밀린다.
- 오프셋: 첫 강박(마디 첫 박)의 시각(ms). 박 위치를 전체 박 격자에 최소제곱으로 맞춰 구한다(박 하나의 오차가 아니라 곡 전체 평균).
  `settings.offset` 이 정확히 무엇의 시각인지(첫 타일을 치는 시각인지, 그보다 몇 박 앞인지)는 `[확인]`.
- 박자표: 기본 4/4. 마디 첫 박은 저음 세기 주기로 추정, `--beats-per-bar` 로 바꿀 수 있게.

### 3.2 템포 맵 (변속의 바탕)

곡 전체를 "구간별 BPM" 목록으로 만든다: `[(시작 초, BPM, 시작 박 번호), ...]`.

- 자동: 박 사이 간격을 이동 중앙값으로 보고, **2% 넘게 바뀐 상태가 4박 이상 이어지면** 새 구간. 짧게 튀는 것은 무시.
- 점점 빨라지거나 느려지는 곡(라이브 녹음 등): 박마다 BPM 을 바꾸는 방식(`--tempo per-beat`)을 고를 수 있게. 이벤트가 많아지지만 `SetSpeed` 자체는 가볍다.
- **수동 템포 맵이 가장 정확하다**: `--tempo-map tempo.csv` (`초,BPM` 줄). 작곡가가 준 BPM 정보나 DAW 에서 뽑은 값을 넣을 수 있게 한다.
- 결과는 `out/<곡>/analysis.json` 에 저장해 다음 실행에서 다시 분석하지 않는다.

### 3.3 치는 순간 (온셋)

- HPSS 로 타악(percussive)·화성(harmonic)을 나누고, 타악 쪽에서 대역별 온셋:
  저음(킥, 약 150Hz 아래), 중음(스네어, 약 150~2500Hz), 고음(하이햇, 약 5kHz 위).
- 화성 쪽 온셋은 멜로디·코드 변화.
- 각 온셋에 세기(onset strength)와 대역을 붙인다.

### 3.4 구간과 세기

- 세기 곡선: RMS(짧은 창) + 온셋 밀도, 마디 단위로 평균.
- 구간 경계: 크로마/MFCC 자기 유사 행렬로 나누고(`librosa.segment`), 마디 경계에 맞춘다. `--sections sections.csv` 로 사람이 고칠 수 있게.
- 이름 붙이기(규칙 기반): 세기 상위 구간 = 드롭/후렴, 드롭 직전 4~16마디에서 세기·밀도가 오르는 곳 = 상승(빌드업), 처음 = 도입, 마지막 = 끝.
- 멜로디 높낮이: `librosa.pyin` 으로 주 음높이(연출용, 대략이면 됨).

## 4. 박자 격자에 맞추기

- 구간마다 쓸 격자를 고른다: 1, 1/2, 1/3, 1/4, 1/6, 1/8 박. 온셋들을 각 격자에 맞췄을 때 오차 합이 가장 작은 것.
- 허용 오차: 약 25ms. 넘으면 버리거나(흔들리는 소리) 사람이 볼 수 있게 표시.
- 같은 칸에 두 개면 하나만.
- **난이도** `--difficulty 1~10` 이 정하는 것:

| 난이도 | 가장 잘게 | 두 타일 사이 최소 (ms) | 따라가는 소리 |
|---|---|---|---|
| 1~3 | 1/2 박 | 250 | 강박 + 킥 |
| 4~6 | 1/4 박 | 120 | 킥 + 스네어 |
| 7~8 | 1/4, 1/3 | 80 | 타악 전부 |
| 9~10 | 1/8, 1/6 | 50 | 타악 + 멜로디 |

  숫자는 시작값이다. 갖고 있는 맵들의 통계(9.5)로 조정한다.

## 5. 타일 만들기 (차트)

### 5.1 어떤 소리를 칠지

- 조용한 구간: 강박·멜로디 위주, 간격 넓게.
- 센 구간: 킥·스네어 위주, 난이도 한도까지 촘촘히.
- 같은 간격이 너무 오래 이어지면(예: 같은 1/4박 32개 넘게) 강세 있는 칸만 남겨 숨 쉴 자리를 둔다.
- 기본은 "치는 소리마다 타일 하나". 얼불춤 관례대로 소리가 없어도 박마다 타일을 두는 방식(`--fill-beats`)도 고를 수 있게.

### 5.2 쉼

| 쉼 길이 | 처리 |
|---|---|
| 1.5박 이하 | 각도로 (270° 까지) |
| 1.5박 넘음 | `Pause` 이벤트(남는 박), 또는 박마다 타일 채우기 |
| 아주 김(도입 등) | `Pause` + 카운트다운 |

### 5.3 가독성 (변속으로 해결)

- 돈 각도가 **45° 아래**(1/4박보다 잘게)면 타일이 접혀서 읽기 어렵다.
  그 구간은 `SetSpeed` `Multiplier` 로 BPM 을 2배·4배 올리고 각도를 그만큼 크게 둔다. **시간은 같고 모양만 펴진다.**
  예: 120 BPM 1/4박(45°) 연타 → 그 구간 ×2(240 BPM) 로 바꾸면 1/2박(90°).
- 구간이 끝나면 원래 BPM 으로 되돌린다(`Bpm` 으로 절대값 지정하는 편이 누적 오차가 없다).

### 5.4 길 모양

- 각 타일 위치 = 이전 위치 + (cos a, sin a). 타일이 **겹치거나 너무 가까우면(거리 0.8 아래)** 안 된다.
- 같은 박 수는 시계/반시계 두 모양이 있다. 겹침을 피하는 쪽을 고르고, 방향을 바꿀 때는 `Twirl` 을 넣는다.
- 몇 타일 앞을 미리 보고(앞보기) 겹칠 것 같으면 그 전에 Twirl 하거나 다른 모양을 고른다. 그래도 안 되면 긴 직선으로 빠져나온다.
- 구간이 바뀔 때 길의 큰 방향을 바꾸면 구간이 눈에 보인다(연출과 같이).

## 6. 변속 정리

변속에는 세 가지가 있다. 섞지 않게 표시해서 넣는다.

| 종류 | 왜 | 넣는 법 |
|---|---|---|
| **곡 템포 변화** | 노래 자체가 빨라지거나 느려짐 | 템포 맵(3.2)의 구간 시작 타일에 `SetSpeed` `Bpm` (절대값) |
| **가독성 배속** | 잘게 쪼갠 박을 펴서 보이게 | 5.3. `Multiplier` 또는 `Bpm`, 구간 끝에 되돌림 |
| **연출 변속** | 드롭에서 속도감, 브레이크에서 느린 느낌 | 같은 시간을 다른 BPM 으로 표현: BPM 을 올리면 행성이 빨리 돌고 각도가 커진다. 소리와의 싱크는 그대로 |

공통 규칙:
- 각도 계산은 **그 타일의 BPM** 으로 한다: 박 수 = 초 × BPM / 60.
- 변속이 타일 중간에 걸려야 하면 `angleOffset` 을 쓴다 `[확인]`. 처음에는 타일 경계에서만 바꾼다.
- 매번 끝에 **모든 타일의 시각을 템포 맵으로 다시 계산해 온셋 시각과 비교**한다. 오차가 1ms 를 넘는 타일이 있으면 실패로 보고 어디서 밀렸는지 출력한다.
- 연출 변속은 1/8 박보다 잘게 쪼개지지 않게(행성이 너무 빨라 보임), 드롭 한 구간에 한두 번.

## 7. 연출

### 7.1 쓰는 이벤트 `[확인]` (칸 이름은 템플릿 조각에서 복사)

| 이벤트 | 용도 | 주요 칸 |
|---|---|---|
| `MoveCamera` | 당기기, 각도, 위치 | `duration`(박), `relativeTo`, `position`, `rotation`, `zoom`(100 = 기본), `ease` |
| `Flash` | 번쩍 | `duration`, `plane`(앞/뒤), `startColor`, `startOpacity`, `endColor`, `endOpacity` |
| `ShakeScreen` | 흔들림 | `duration`, `strength`, `intensity`, `fadeOut` |
| `SetFilter` | 필터 켜고 끄기 | `filter`, `enabled`, `intensity`, `disableOthers` |
| `Bloom` | 빛 번짐 | `enabled`, `threshold`, `intensity`, `color` |
| `RecolorTrack` / `ColorTrack` | 타일 색 | `trackColor`, `secondaryTrackColor`, `trackColorType`, 범위 |
| `MoveTrack` | 타일 움직이기 | 범위, `duration`, `positionOffset`, `rotationOffset`, `scale`, `opacity` |
| `AddDecoration` | 장식 만들기 (`decorations` 쪽) | `decorationImage`, `position`, `relativeTo`, `scale`, `rotation`, `color`, `opacity`, `depth`, `tag` |
| `MoveDecorations` | 장식 움직이기 | `tag`, `duration`, `positionOffset`, `rotationOffset`, `scale`, `color`, `opacity`, `ease` |
| `CustomBackground` | 배경색 | `color` |

`SetFilterAdvanced`, `HallOfMirrors`, `ScreenTile`, `ScreenScroll`, 글자 장식은 처음에는 쓰지 않는다(무겁거나 게임 버그가 있음, 8장).

### 7.2 소리 → 연출 대응

| 소리 | 연출 (기본값, 세기에 따라 크기 조절) |
|---|---|
| 킥 (센 구간) | 카메라 `zoom` 104 → 100, 0.5박, OutCubic |
| 스네어 | 앞쪽 `Flash` 흰색 20% → 0%, 0.25박 |
| 마디 첫 박 (드롭) | 카메라 `rotation` ±3°, 1박 / 링 장식 퍼지기 |
| 아주 센 순간 (드롭 첫 박) | `ShakeScreen` 강 + `Flash` 60% + `Bloom` 켬 |
| 구간 시작 | `RecolorTrack` 새 색, `CustomBackground` 바꾸기, 필터 바꾸기 |
| 상승(빌드업) | 마디마다 `zoom` 조금씩 올리기(100 → 115), 마지막 마디 흔들림 쌓기, 드롭 첫 박에 한 번에 되돌림 |
| 브레이크(조용) | 필터(흑백 등) 켜기, 카메라 천천히 회전, 연출 밀도 최소 |
| 멜로디 높낮이 | 장식 세로 위치, 크기 |

- 같은 연출이 계속 반복되면 지루하다. 구간마다 "연출 세트"를 2~3개 두고 돌려 쓴다.
- 색: 구간마다 2~3색 팔레트. 처음엔 미리 정한 팔레트 몇 개에서 고르고, 나중에 앨범 그림에서 뽑기.

### 7.3 장식 모션 템플릿

이미지는 생성기가 직접 만든다(PIL): 흰 원, 링, 선, 점, 사각형. **흰색으로 만들고 `color` 로 물들인다**(이미지 수를 줄이려고). 크기 256px 안.

| 템플릿 | 움직임 |
|---|---|
| 링 퍼지기 | 박에 맞춰 크기 0 → 300%, 투명도 100 → 0, 1박 |
| 도는 선 | 화면 가장자리 선 여러 개, 마디마다 90° 회전 |
| 파티클 튀기 | 점 8개가 행성 둘레로 퍼지며 사라짐, 0.5박 |
| 이퀄라이저 | 막대 8~16개, 박마다 대역 세기만큼 높이 |
| 궤도 점 | 행성 둘레를 도는 점, 박 길이로 한 바퀴 |

**장식은 미리 만들어 두고(풀) 다시 쓴다.** 박마다 새 장식을 만들지 않는다. 같은 `tag` 묶음을 `MoveDecorations` 로 처음 상태로 되돌린 뒤 다시 움직인다.

## 8. 끊김 없는 연출 규칙 (StutterFix 측정 근거)

StutterFix 에서 고사양 맵의 끊김 원인을 잰 것이다. 생성기는 처음부터 피하고, 마지막에 `budget.py` 가 검사해 넘으면 실패로 본다.

| 규칙 (시작값) | 근거 |
|---|---|
| 한 순간(같은 타일, `angleOffset` 차이 3° 안)의 효과 **8개 이하**. 넘으면 `angleOffset` 으로 나눠 둔다 | 같은 박에 효과 수십 개가 시작되면 한 프레임이 40ms 넘게 멈췄다 |
| `MoveTrack` 한 번의 범위 **200타일 이하** | 타일 수천~만 개에 한 번에 걸면 효과 하나가 45~55ms |
| 타일 **스타일(trackStyle) 바꾸기는 구간 시작에만** | 곡 중 스타일이 바뀌면 처음 보는 타일 모양을 곡 중에 만들어 32ms |
| `SetFilterAdvanced` 쓰지 않기, `SetFilter` 바꾸기는 마디에 한 번 이하 | 고급 필터 정리 한 번이 효과 하나에 2~18ms, 길이 있는 고급 필터는 게임 쪽 예외를 매 프레임 던짐 |
| 동시에 움직이는 장식·타일 애니메이션 **수백 개 이하** | 애니메이션이 수천 개 쌓이면 정리 비용이 제곱으로 커져 한 프레임 382ms |
| 글자 장식은 제목 정도만 | 글자 장식은 갱신할 때 할당과 비용이 크다 |
| 장식 블렌드 모드 쓰지 않기 | 블렌드 장식 1,500개에서 약 11 FPS |
| 장식 이미지 **256px 안, 종류 20개 안**, 장식 총 **300개 안** | 큰 이미지가 많으면 그래픽 메모리가 넘쳐 드라이버 쪽에서 끊김 |
| 효과음(`PlaySound`, `SetHitsound`)은 종류를 적게 | 처음 쓰는 소리를 곡 중에 불러오느라 30ms |

숫자는 시작값이다. 9.3 의 끊김 검사 결과로 조정한다.

## 9. 검증

### 9.1 정답지: 게임이 계산한 타일 시각

- StutterFix 개발자용 자동 시험에 **`timedump <파일>`** 명령을 하나 더한다(StutterFix 쪽 작업): 열린 맵의 타일마다
  `번호, 게임이 계산한 시각(entryTime), 방향, 회전 방향, 미드스핀 여부, 그 타일 BPM` 을 CSV 로 쓴다.
- 생성기의 시각 계산기(`timing.py`)로 같은 맵을 계산해 비교한다. **모든 타일 1ms 안**이어야 통과.
- 남의 맵 여러 개(변속·Twirl·Pause·미드스핀·행성 3개가 들어간 것 포함)로 돌려 2.3·2.4 의 `[확인]` 을 지운다.
- 생성한 맵도 같은 방법으로: 게임이 계산한 시각 vs 노래 온셋 시각.

### 9.2 싱크

- 자동 플레이로 돌리며 타격음과 노래가 맞는지 사람이 듣는다.
- 오프셋이 의심되면 첫 4마디만 잘라 만든 맵으로 확인.

### 9.3 끊김

- StutterFix 저장소의 `tools/sfmeasure`(MCP, 파이썬): 자동 시험이 든 StutterFix 를 설치하고
  `sf_run` 에 `["open <맵 경로>", "auto on", "play", "waitend 600"]` → 곡 중 끊김 요약. 자세한 것은 `tools/sfmeasure/README.md`.
- 끊김이 나오면 그 시각의 연출을 줄이고 8장의 숫자를 고친다.

### 9.4 겹침

- 모든 타일 위치를 계산해 두 타일 거리 0.8 아래가 있으면 실패.

### 9.5 통계 (선택, 4장·8장 숫자 맞추기)

- 갖고 있는 맵들에서 숫자만 뽑는다: BPM 대비 가장 잘게 쪼갠 박, 1초당 타일 수, 박당 카메라 이벤트 수, 구간당 색 바꾸기 수.
- 맵 내용(패턴 자체)은 복사하지 않는다.

## 10. 구조와 사용법

```
mapgen/
  analyze.py    노래 → analysis.json (BPM 후보, 템포 맵, 온셋, 구간, 세기, 음높이)
  grid.py       온셋 → 박자 칸
  chart.py      칠 소리 고르기, 쉼, 가독성 배속
  path.py       박 수 → 각도, Twirl, 겹침 피하기
  timing.py     angleData + 이벤트 → 타일 시각 (9.1 대조용)
  effects.py    구간·소리 → 연출 이벤트
  decor.py      장식 이미지 만들기, 모션 템플릿
  budget.py     8장 규칙 검사
  writer.py     템플릿 + 결과 → .adofai
template/       빈 맵, 이벤트 조각 (2.1)
```

```
python -m mapgen song.ogg --out out/song \
  [--bpm 174] [--tempo-map tempo.csv] [--sections sections.csv] \
  [--difficulty 6] [--fill-beats] [--style motion|minimal] [--seed 1]
```
- 출력 폴더에 `.adofai`, 노래 복사본, 장식 이미지, `analysis.json`, 검사 보고서(`report.txt`: 오차, 겹침, 예산).
- `--seed` 로 같은 입력이면 같은 맵이 나오게(비교·검증용).

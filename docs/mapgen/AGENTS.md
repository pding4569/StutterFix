# 얼불춤 맵 생성기 (시작 문서)

노래 파일(mp3/ogg)을 넣으면 얼불춤(A Dance of Fire and Ice) 맵(.adofai) 초안을 만든다.
박자에 맞는 타일 + 음악에 맞춘 모션 그래픽 연출. 사람이 에디터에서 다듬는 것을 전제로 한 **초안**이다.
이 문서는 StutterFix 프로젝트에서 넘겨받은 것이다. StutterFix 저장소(`pding4569/StutterFix`)의 `CLAUDE.md` 에 성능 측정 근거가 더 있다.

## 규칙

- 한국어로 대화한다.
- **허락받은 곡만** 쓴다. 노래 파일과 만든 맵은 저장소에 올리지 않는다(`.gitignore`).
- 다른 사람의 맵·모드 코드를 복사하지 않는다. 게임 DLL·디컴파일한 게임 코드는 저장소에 넣지 않는다.
- 개인 정보(이메일 등)는 어디에도 쓰지 않는다.

## 단계 (한 단계씩, 게임에서 열어 확인한 뒤 다음으로)

1. **박자 타일 + 기본 연출**: BPM·오프셋·소리 치는 순간 → 박자 칸에 맞춤 → 타일 각도 → `.adofai`. 강한 박에 카메라 살짝 당기기·번쩍.
2. **구간 연출**: 도입·벌스·드롭 구간을 알아보고 색 테마, 필터, 카메라 각도 전환. 소리 세기에 따라 효과 밀도.
3. **장식 모션 템플릿**: 퍼지는 링, 회전하는 선, 튀는 파티클 같은 도형 움직임 몇 가지를 만들어 구간마다 골라 쓴다. 드롭 직전 상승 연출.
4. **끊김 검사**: StutterFix 의 측정 도구로 자동 플레이를 돌려 끊기는 곳을 찾고 연출을 고친다.

첫 버전은 BPM 하나, 직선과 꺾기만. 실제로 쳐 보며 늘린다.

## 노래 분석 → 연출

| 노래 분석 | 연출 |
|---|---|
| 강한 박 (킥, 스네어) | 카메라 살짝 당기기, 화면 번쩍, 타일 튕기기 |
| 구간 바뀜 | 색 테마 전환, 필터 켜고 끄기, 카메라 각도 |
| 소리 세기 곡선 | 효과 밀도 |
| 드롭 직전 상승 | 점점 빨라지는 확대, 흔들림 쌓기 |
| 멜로디 높낮이 | 장식 위치·크기 |

파이썬 음악 분석 라이브러리(예: librosa)로 BPM, 박, 소리 치는 순간, 세기, 구간 경계를 뽑는다.

## .adofai 형식 (실제 맵 파일로 반드시 확인할 것)

- JSON 비슷한 텍스트. 끝에 쉼표가 남는 등 표준 JSON 과 다를 수 있어 읽기는 관대하게.
- `settings`: 노래 파일 이름, BPM, 오프셋 등. `angleData`: 타일 방향 각도 목록. `actions`: 타일 번호(`floor`)에 붙는 이벤트(`eventType`). `decorations`: 장식.
- 타일 사이 각도가 박자 길이다(직선이면 1박, 꺾일수록 짧아짐). 회전 방향 바꾸기(Twirl), 속도 바꾸기(SetSpeed)가 이를 바꾼다. **정확한 규칙은 게임에서 만든 맵을 몇 개 열어 대조해 확정한다.**
- 이벤트에는 타일 안 위치(`angleOffset`)가 있어서 같은 타일의 효과를 조금씩 어긋나게 둘 수 있다.

## 끊김 없는 연출 규칙 (StutterFix 측정 근거)

고사양 맵이 끊기는 원인을 StutterFix 에서 재 둔 것. 생성기는 처음부터 이것을 피한다.

- **한 순간에 효과를 몰지 않는다.** 같은 박에 효과 수십 개가 시작되면 한 프레임이 수십 ms 멈춘다. 박당 효과 수에 상한을 두고, 같은 타일 안에서 `angleOffset` 으로 나눠 둔다.
- **타일 이동 효과(MoveTrack)의 범위를 작게.** 타일 수천 개에 한 번에 걸면 효과 하나가 40~50ms 걸렸다.
- **타일 스타일을 자주 바꾸지 않는다.** 색 바꾸기가 스타일을 바꾸면 곡 중에 새 타일 모양을 만들어 끊긴다.
- **고급 필터 켜고 끄기를 몰지 않는다.** 필터 정리 한 번이 효과 하나에 수 ms~20ms 였다.
- **동시에 도는 애니메이션 수를 제한한다.** 수천 개가 동시에 돌면 정리 비용이 제곱으로 커진다(한 프레임 382ms 기록).
- **글자 장식을 적게.** 글자 장식은 갱신 비용이 크다.
- **블렌드 모드 장식을 쓰지 않는다.** 많으면 화면 복사로 FPS 가 크게 떨어졌다.
- **장식 이미지는 작게.** 큰 이미지가 많으면 그래픽 메모리가 넘쳐 끊긴다.

## 확인 방법

- 만든 맵을 게임 에디터에서 연다. 싱크는 사람이 쳐 보고 확인한다.
- 끊김 검사: StutterFix 저장소의 `tools/sfmeasure`(MCP, 파이썬). 자동 시험이 든 StutterFix 를 설치하고
  `sf_run` 에 `["open <맵 경로>", "auto on", "play", "waitend 600"]` → 곡 중 끊김 요약. 자세한 것은 `tools/sfmeasure/README.md`.

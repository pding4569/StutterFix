# 장식 픽셀 비용은 왜 비싼가 (2026-11-25)

사용자 질문: 장식 픽셀 처리가 비싸다면 그 처리 방식이 왜 비싼지 분석.

## 앞서 잰 것
- 정지 화면 픽셀 셰이더 호출: 7777 2.26억/프레임(화면 55장 분량, 장식 1.88억), Windflower 1.61억(장식 1.22억). 장식 픽셀 하나 6.7~8.7ps.
- 화면보다 큰 반투명 그림이 수십 장 겹친다. 텍스처 면적의 알파 0 비율: 7777 P3_FOG1 72%, P3_ST2 95.6%, WF ozgrass_blur 49%.
- 장식 셰이더(Sprites/Tile, Sprites/Default) 픽셀 계산은 `tex(uv) * 꼭짓점 색` 후 미리 곱한 알파, 섞기 One/OneMinusSrcAlpha.

## 분해 시험 (7777 100초 정지, 본 카메라 GPU timestamp, 화면 Sprites 재질 416개를 시험 셰이더로 강제)
| 픽셀 셰이더 | 본 카메라 µs |
|---|---|
| 원래 (끔, 6번) | 1754~1766 |
| 알파 0 이면 discard | 1758·1764 |
| 항상 discard (텍스처 안 읽음) | 1337 |
| 상수 (0,0,0,0) 출력, discard 없음 | 1340 |
| 상수 알파 0.5 출력 (모든 픽셀이 실제로 섞임) | 2144·2157 |

- 상수 0 섞기 = 항상 discard → **GPU 가 기여 0 인 섞기를 이미 하드웨어에서 건너뛴다.** 그래서 알파 0 discard 는 이득이 없다.
- 모든 픽셀을 실제로 섞게 하면 +820µs. 지금 장식은 알파가 0 이 아닌 픽셀만 실제로 섞고 있다.
- 장식의 텍스처 읽기 + 실제 섞기 몫 = 1758 − 1337 ≈ 420µs(카메라의 24%). 이 둘은 그림을 만드는 데 꼭 필요한 일이라 같은 그림으로는 줄일 수 없다.
- 바닥 1337µs 에는 장식이 아닌 것(타일·필터 413µs·배경·행성)과 장식 조각의 래스터화·셰이더 실행 자체가 들어 있다.

## 장식 종류별로 숨겨 보기 (같은 장면, `hidegroup`)
| 숨긴 것 | 개수 | 본 카메라 µs |
|---|---|---|
| 없음 | | 1749~1791 |
| 장식 전부 | 2430 | 467 |
| Sprites/Tile 장식 | 1357 | 556 |
| Sprites/Default 장식 | 40 | 1763 |
| 반복 무늬(repeat >= 50x50) | 41 | 877 |
| 큰 장식(25 단위 넘음) | 55 | 574 |

- 이 장면 GPU 의 절반은 **화면 전체를 덮는 반복 무늬 층**: P3_FOG2(500x500, 77x77 반복, 색 알파 0.21) 16장, P3_FOG1(같은 크기, 0.77) 16장, P3_ST2(100x100 반복, 0.07) 4장. 36장 × 화면 410만 px ≈ 1.5억 px = 앞서 잰 장식 픽셀 1.88억의 대부분.
- 앞의 "항상 discard 1337" 과 "장식 숨김 467" 의 차이(870)는 덮기 비용만이 아니다(스프라이트가 아닌 장식도 섞임).
- 꼭 맞는 메시 시험(알파 != 0 칸만 덮기, 반복 무늬는 보이는 칸만, 로컬 patches/tightmesh-repeat-notExact): 반복 무늬 덮는 면적 39% 로 → 1758→1592µs(-9.4%). 덮는 면적을 61% 줄여도 166µs 뿐 → 이 층들의 비용은 대부분 알파가 있는 부분의 텍스처 읽기·섞기다. 그림도 바이트까지 같지 않아(최대 12/255) 기각.
- 진단: `hidegroup tile2d on` 이 반복 무늬 층의 텍스처·반복 수·색 알파를 `tileitem` 줄로 남긴다.

## 남은 수단과 한계
- 알파 0 영역을 아예 그리지 않기: 위 시험으로 상한 -9.4%(7777 무거운 장면), 그림 다름 → 기각.
- 같은 무늬 16장 겹침을 한 번으로 합치기: 8비트 화면에 장마다 반올림되므로 같은 그림이 아니다.
- 밉맵·압축·점 샘플링은 그림이 달라져 쓰지 않는다.
- 이 정지 화면의 GPU 프레임은 2.3ms(약 430 FPS 분량)라 이 구간은 GPU 가 병목이 아니다. GPU 절감은 GPU 병목 구간에서만 FPS 로 이어진다.

# 고사양 페이지와 화면 효과 (ReShade 같은 기능) 설계

설정 창에 "화면 효과" 페이지를 따로 두고, 게임 화면에만 후처리 효과를 건다. **원래 게임 화면을 바꾸는 기능이라 전부 기본 꺼짐.**
클라우드에서 쓴 설계다. 빌드·측정은 PC 에서.

## 설정 창을 두 쪽으로: 최적화 / 고사양

오른쪽 아이콘 줄 맨 위·맨 아래에 **위·아래 화살표**를 두고 두 묶음을 오간다.

| 쪽 | 내용 | 원칙 |
|---|---|---|
| **최적화** (지금 것) | 플레이·맵 불러오기·그래픽·저사양·모니터 | 원래 게임과 같은 결과, 끊김 제거 |
| **고사양** (새로) | 화면 효과, 화질 올리기, 저지연 | **원래 화면을 바꾸는 선택 기능**, 전부 기본 꺼짐, 비용 표시 |

두 원칙이 섞이지 않게 나누는 것이 목적이다. 고사양 쪽에 들어간 기능은 "원래와 같음" 검증 대상이 아니라, 대신 끄면 완전히 원래대로 돌아가는지만 검증한다.

### 고사양 쪽에 넣을 기능

| 기능 | 하는 일 | 바탕 |
|---|---|---|
| **화면 효과** | 아래 효과 목록 (색감, 선명, 가장자리, 글로우, 빛 줄기, 비네트, LUT, 주변 비추기) | 이 문서 |
| **슈퍼샘플링** (렌더 배율 100% 넘게) | 게임 화면을 1.5배·2배로 그린 뒤 줄여 냄 → 타일·장식 가장자리가 아주 깨끗 | 이미 있는 렌더 배율(`LowEnd.RenderScalePct`, 지금 10~100%)을 위로 늘림 |
| **MSAA** | 게임 화면 버퍼(camRT)에 다중 샘플 → 회전한 타일 계단 현상 | camRT 를 만들 때 `antiAliasing` 값 |
| **장식 원본 화질** | 큰 이미지를 줄이지 않음 (VRAM 이 넉넉할 때만, 모자라면 경고) | 이미 있는 `ImageMaxSide` 를 이 쪽으로 옮겨 보여 줌 |
| **이방성 필터링** | 기울거나 작게 줄어든 장식 이미지가 덜 뭉개짐 | `QualitySettings.anisotropicFiltering` |
| **저지연 모드** | 독점 전체 화면: 화면에 나오기까지 지연 절반, 대신 FPS 약 -10%, 찢어짐 | 이미 있는 실험 설정 `ExpFullscreen` 을 정식으로 |
| **주사율 맞춤 프레임 제한** | 모니터 주사율 바로 아래로 FPS 를 묶어 G-Sync/FreeSync 에서 부드럽게 | 메뉴 FPS 제한 코드 재사용. 곡 중 입력 판정과 관계없는지 확인 |

넣지 않는 것: 게임 판정·타이밍을 건드리는 것, HDR 출력(유니티 쪽 작업이 크고 모니터 의존). 프레임 늘리기(보간)는 따로 연구 중이다(`docs/framegen-research.md`, `codex/framegen`).

## 셰이더 출처 (원리 참고 또는 라이선스가 허락하면 이식)

| 출처 | 쓸 만한 것 | 라이선스 (넣기 전 다시 확인) |
|---|---|---|
| AMD FidelityFX | FSR(이미 넣음), **CAS** 선명하게, LPM 톤 매핑 | MIT |
| NVIDIA Image Scaling (NIS) | 선명하게·키우기 | MIT 로 알려짐 |
| Keijiro Takahashi 의 Kino 시리즈 (GitHub) | **Streak**(가로 빛 줄기, 네온과 잘 맞음), Bloom | 대부분 MIT/Unlicense, 저장소마다 확인 |
| FXAA 3.11, SMAA | 가장자리 부드럽게 | 공개·관대한 라이선스로 알려짐, 확인 |
| Dual Kawase 블러 | 가벼운 글로우 바탕 | 기법(코드는 직접) |
| 2D 래디언스 캐스케이드 | 주변 비추기 | 기법, 공개 구현은 라이선스 확인 |
| Shadertoy | 참고만 | 기본 CC BY-NC-SA → 코드 복사 금지 |
| ReShade 셰이더 팩 | 참고만 | 제각각 → 복사 금지 |

"빛 줄기"(Streak): 밝은 행성·타일에서 가로로 길게 빛이 번지는 애너모픽 렌즈 느낌. 글로우와 함께 "네온" 미리 설정에 넣을 후보.

## 이미 있는 것 (새로 만들 필요가 적다)

1. **게임에 들어 있는 CameraFilterPack 셰이더**: `Shader.Find("CameraFilterPack/...")` 로 바로 쓸 수 있다(`LowEnd` 의 선명하게가 `CameraFilterPack/Sharpen_Sharpen` 을 쓴다).
   게임에 실제로 들어 있는 이름 목록부터 뽑는다(`Resources.FindObjectsOfTypeAll<Shader>()` 를 개발자용 명령으로). 색, 비네트, 색수차, 필름 그레인, 블러 등이 있으면 셰이더를 새로 만들 필요가 없다.
2. **셰이더 묶음을 모드에 넣는 길**: `fsr/` (FSR 1, `BuildFsr.cs.txt` 로 유니티 6000.3 에디터에서 AssetBundle 을 만들고 DLL 에 넣어 `AssetBundle.LoadFromMemory`). 새 셰이더도 같은 길로 묶는다.
3. **게임 화면만 따로 다루는 자리**: 플레이 중 게임은 카메라 3개를 `scrCamera.camRT` 한 장에 그린 뒤 사각형으로 낸다(`LowEnd` 해상도 낮추기·`Fsr` 이 쓰는 곳). 여기에 걸면 UI(HUD, 설정 창)는 그대로 선명하다.
   에디터·메뉴처럼 camRT 를 안 쓰는 화면에서는 걸지 않거나, 본 카메라에 따로 건다(나중).

## 효과: 얼불춤에 맞는 것만

고르는 기준: **박자를 읽는 데 방해가 없고**(타일·행성이 흐려지거나 번지지 않음), **입력 지연과 FPS 를 거의 안 먹고**, 2D 화면에서 차이가 보이는 것.

### 넣는 것 (6개)

| 효과 | 왜 얼불춤에 맞나 | 셰이더 |
|---|---|---|
| **색감** (생동감·대비·밝기·색온도) | 타일·행성 색이 또렷해짐. 생동감은 이미 진한 색은 덜 올려 색이 뭉개지지 않음 | 한 패스로 새로 |
| **선명하게** | 고해상도·큰 모니터에서 타일 가장자리와 글자가 또렷 | 이미 있음 (Sharpen / FSR RCAS), 페이지만 옮김 |
| **가장자리 부드럽게** (FXAA) | 회전한 타일·대각선 길의 계단 현상 | 한 패스로 새로 |
| **글로우** (밝은 부분만 약하게 번짐) | 행성·네온 타일이 빛나 보임. 맵의 블룸 연출이 켜진 동안은 자동으로 쉼 | 새로, 작은 크기에서 계산해 가볍게 |
| **비네트** (가장자리 약하게 어둡게) | 시선이 화면 가운데(행성)로 | 색감 패스에 합침 |
| **LUT** (색 보정 표) | 사용자가 원하는 색 분위기를 그림 파일 하나로 | 색감 패스에 합침 |

### 실험: 주변 비추기 (2D 전역 조명)

ReShade 의 RTGI 처럼 **빛나는 타일·행성이 주변 바닥과 배경을 그 색으로 물들이는** 효과. RTGI 는 깊이 정보로 3D 빛을 흉내 내지만, 이 게임은 2D 라
**화면의 밝은 픽셀을 빛나는 물체로 보고 그 빛이 둘레로 퍼지는 것**을 2D 로 계산한다(2D 래디언스 캐스케이드 같은 방식, 원리만 참고해 새로 짬).

- 글로우는 "빛나는 물체 자체가 번짐", 이건 "**그 빛에 주변이 비춰짐**"이라 다르다. 어두운 배경에 네온 타일이 있는 맵에서 차이가 크다.
- 무겁다. 화면의 1/4~1/8 크기에서 계산하고 늘려 붙인다. 사용자가 고르는 선택 기능이라 무거워도 넣는다. 대신 GPU 시간을 재서 설정 창에 "무거움, 약 N ms" 로 보여 주고, 화질 단계(1/8, 1/4, 1/2)를 고를 수 있게 한다.
- 1단계(색감·선명·가장자리) 뒤에, 글로우가 된 다음에 시도한다.

미리 설정 4개: **꺼짐**(기본) / **선명** (선명하게 + 가장자리) / **또렷** (선명 + 색감) / **네온** (또렷 + 글로우 + 비네트).

### 넣지 않는 것

| 효과 | 이유 |
|---|---|
| 모션 블러, TAA(시간 누적 안티에일리어싱) | 움직이는 행성·타일이 번져 **박자를 읽기 어려움** |
| 피사계 심도, AO, 3D 전역 조명(RTGI 그대로) | 깊이 정보를 쓰는 효과라 2D 에서 거의 안 보임. 대신 2D 로 다시 만든 "주변 비추기"(실험) |
| 색수차 | 가장자리에 색이 갈라져 타일 경계가 흐려짐 |
| 필름 그레인, 노이즈 | 화면이 지저분해져 빠른 패턴에서 방해 |
| 렌즈 플레어, 가짜 HDR | 화면이 뿌옇게 바래고 맵 연출과 겹침 |
| 강한 블러, 왜곡 계열 | 맵 연출(필터 이벤트)에 이미 있고, 상시로 켜면 읽기 방해 |
| CRT·스캔라인 같은 스타일 효과 | 취향 효과라 나중에 "재미" 항목으로만 검토 |

CameraFilterPack 에 수백 개가 들어 있어도 **위 6개 말고는 설정 창에 내놓지 않는다.**

## 규칙

- **효과 여러 개는 한 패스로 합친다**(색감 + 비네트 + 그레인 + 색수차). 패스 하나마다 화면 전체를 한 번 더 읽고 쓰므로 3440x1440 에서 비싸다.
- 효과마다 GPU 시간을 PresentMon(`MsGPUBusy`)으로 재서 설정 창에 대략 비용을 적는다.
- 맵 연출(필터 이벤트, 블룸 이벤트)과 겹칠 때 어느 쪽이 먼저인지 정한다: 맵 연출 → 화면 효과 순.
- **프레임 늘리기와 함께**: 화면 효과는 진짜 프레임에만 걸고, 보간은 효과가 들어간 진짜 두 프레임 사이를 채운다(맵 연출 → 화면 효과 → 보간). 그래서 효과 비용은 출력 FPS 가 아니라 진짜 FPS 만큼만 든다. 다만 보간이 움직임을 찾는 그림에 효과가 들어가므로, 글로우·주변 비추기처럼 번지는 효과를 켠 채 보간의 새 그림 비율·왕복 횟수를 다시 잰다.
- 미리 설정(프리셋) 몇 개 + 직접 조절. 설정은 모드 설정에 저장.
- 끄면 원래 경로 그대로(카메라 대상·셰이더 원래대로). `Main.Unload` 에 되돌리기.
- ReShade 셰이더 코드는 라이선스가 제각각이라 **복사하지 않는다.** 원리(공식)만 참고해서 새로 쓴다. 넣는 셰이더의 라이선스는 `fsr/license.txt` 처럼 같이 둔다.
- ReShade 자체를 깐 사용자는 모드가 알아채서(게임 폴더의 ReShade dll) 로그·모니터에 표시만 한다.

## 첫 단계

1. 개발자용 명령으로 게임에 든 셰이더 이름 목록 뽑기.
2. 색감 한 패스 셰이더 만들어 fsr 과 같은 방법으로 묶기, camRT 에 걸기.
3. 끔/켬 GPU 시간 재기, UI 가 그대로인지 확인(`shot` 캡처).
4. 설정 창에 "화면 효과" 페이지(Linear/Raycast 방향, 기존 페이지와 같은 모양).

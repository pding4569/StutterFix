# Codex 작업 Z: "히트음 예약 묶기"(HitSoundBatch) — StutterFix 독립 구현 + Quartz 병용 시 우리 것 우선 — 게임 실행·Mods 설치·커밋 금지

결과: 코드 + `docs/handoff/codex-hitsound-20261019-result.md`(**apply_patch UTF-8 BOM**, 한글 확인). 빌드 셋(Dev/Player/PlayerAuto) 오류 0, `tools/check-ui-encoding.py`·LoadCheck·`tools/CompatCheck`(게임 멤버 참조 전수 검사: `dotnet tools/CompatCheck/bin/Release/net8.0/CompatCheck.dll <StutterFix.dll> <Managed>`) 통과. **기본 꺼짐**(설정 창 플레이 > 실험 탭의 새 스위치), 기존 `SoundWarm`(소리 미리 불러오기)과 **별개의 기능·별개의 스위치**.

## 근거 (Claude 실측 + Codex Quartz 분석 `docs/quartz-analysis-20261019.md`)
- 일반 게임(Unity 6000.3.10f1) HELLO 2026 전곡 3440×1440, 판마다 새 프로세스: StutterFix 단독 평균 194 FPS / 1% low 99 / 12ms 초과 89개. Quartz 병용 224 / 118 / 64개. **Quartz 의 `Optimizer.RenderAllHitSounds` 만 끄면 190 / 96 / 105개(단독 수준)로 돌아간다** → 이 옵션 하나가 +15% 평균·+19% 1% low 의 원천. (판정 글자 숨기기·Wallpaper Engine 정지·행성 파티클은 원인 아님/미확인.)
- Quartz 분석(정적): 게임 `scrConductor.PlayHitTimes` 는 히트음 자료 목록(시간·음량·클립)을 만들고 `nextHitSoundToSchedule=0` 으로 둔다. 게임 매 프레임 Update 는 오디오 시계 기준 5초 앞 항목까지 **개별 `AudioManager.Play`** 를 반복 예약한다. Quartz 는 PlayHitTimes 의 postfix 에서 목록·클립 PCM 을 확보하고 성공 시 `nextHitSoundToSchedule` 을 끝으로 옮겨 게임의 개별 예약을 비운다. 0.5초 구간·12초 선행으로 작업 스레드(BelowNormal)가 샘플을 합산하고, 최대 32개 음원 풀의 `AudioClip.SetData` + `PlayScheduled` 로 재생한다. (HELLO 타일 14.7k, Arche 4.1k — 타일이 많을수록 개별 예약이 많다.) **이 방식을 코드째 옮기지 말고 우리 구조에 맞게 독립 구현·가능하면 더 가볍게.** 다른 모드 코드는 저장소에 두지 않는다(`docs/release.md`).

## 해야 할 일
1. **게임 동작 정확히 파악**(IL: `tools/ilscan`, ilspycmd): `scrConductor.PlayHitTimes`, 히트음 자료형(`HitSoundsData` 류), `nextHitSoundToSchedule`, `scrConductor.Update` 의 예약 루프, `AudioManager.Play/PlayScheduled` 인자(클립·dspTime·volume·pitch·mixer 그룹·루프 여부), 히트음 종류(타일 이벤트 `SetHitsound`, 기본 히트음, 커스텀 히트음 파일, 볼륨·`hitsoundVolume`·`GCS.*` 옵션, 오디오 오프셋 보정 `AudioSettings.dspTime`/`conductor.dspTime`), 일시정지·재개·재시작(`Restart`/`FailAction`)·에디터 중간 시작(`seek`)·곡 속도(`speed`/`pitch`) 때 예약이 어떻게 지워지고 다시 만들어지는지, `scrController` 와의 호출 순서, 다른 모드가 걸려 있는 지점(StutterFix 의 `SoundWarm`/`FfxReuse` T 와의 상호작용).
2. **우리 방식 설계·구현**(`HitSoundBatch.cs`, 기본 꺼짐; 설정 `HitSoundBatch`): (a) 준비 단계(원본 PlayHitTimes 끝난 뒤)에 목록·클립 PCM 확보 — 실패·미지원 조건(압축 포맷 읽기 불가, 클립 길이 비정상, 피치 변조, 3D/루프 등)이면 **원래 경로로 즉시 복귀**(우회하지 않고 반환), (b) 작업 스레드에서 구간(예: 0.25~0.5초) 단위로 샘플 합산 → 메인 스레드는 음원 풀에 `SetData`+`PlayScheduled` 만(프레임당 상한, 한 프레임에 몰리지 않게), (c) 음량·히트음 볼륨 설정이 곡 중에 바뀌면 처리(재렌더 또는 안전하게 해제), (d) 일시정지·재개·재시작·실패·곡 끝·모드 끄기·`Main.Unload`·씬 전환에서 **소유한 음원·클립·예약만** 정리하고 원래 `nextHitSoundToSchedule` 의미(원본이 이어서 예약해도 되는 상태)로 되돌림, (e) 합산은 클리핑·정규화 없이 게임의 믹서가 했을 합과 같게(float 합산, 필요하면 소프트 한계 없음 — 같은 값), 리샘플링이 필요하면 원본과 같은 방식, (f) 메모리 상한(PCM 캐시·음원 풀 크기) 명시, 곡마다 해제.
3. **Quartz 병용 시 우리 것 우선**: `Compat` 에 Quartz 의 `RenderAllHitSounds` 활성 여부 감지 추가(`Harmony.GetPatchInfo(PlayHitTimes)` 로 owner `quartz.module.optimizer` 의 postfix 확인 + 필요하면 Quartz `UserData/Optimizer.json` 의 `RenderAllHitSounds` 값을 **읽기만**; 인증 관련 파일은 절대 읽지 말 것). 우리 기능이 켜져 있고 Quartz 의 같은 기능이 활성이면 **정확히 그 PlayHitTimes postfix 하나만** 우리 Harmony 로 일시 제외(또는 우리 postfix 가 `nextHitSoundToSchedule` 선점)해서 이중 예약·이중 재생이 없게 하고, 우리 기능을 끄거나 `Unload` 하면 되돌림. Quartz 옵션 값/설정 파일은 바꾸지 않는다. 우리 기능이 꺼져 있으면 Quartz 쪽을 건드리지 않는다. 이중 재생이 일어날 수 있는 순서(우리가 먼저/나중)를 코드로 확인해 정리.
4. **검증 도구**(DEV/AUTOTEST): `hitsound state`(목록 개수·구간 수·캡처 성공/실패 이유·풀 사용량·프레임당 `SetData` 횟수·원래 경로 복귀 횟수), `hitsound verify`(곡 준비 직후 원본 예약 자료로 기대되는 구간별 합산 PCM 을 순수 계산하고 우리가 렌더한 PCM 과 비교: 최대 오차·시각 오차(샘플 단위)·누락 0), `hitsound compare`(개발용: 같은 구간을 원본 개별 예약으로 한 번, 우리 합산으로 한 번 녹음할 수 있는지(`AudioListener.GetOutputData`/`OnAudioFilterRead` 캡처) 검토; 불가능하면 PCM 대조만). 고빈도 함수에 Stopwatch 패치 추가 금지(측정 오염).
5. **설정 창**: 플레이 > 실험 탭에 한 줄 스위치 `히트음 예약 묶기 (실험)`(설명: 타일마다 히트음을 하나씩 예약하는 대신 미리 합쳐 예약합니다. 소리 타이밍·음량이 달라질 수 있어 기본으로 꺼져 있습니다). 한글 `T("한글","English")` 패턴, 깨짐 검사.
6. 결과 문서에: 게임 동작 요약(IL 근거), 설계, 미지원 조건 표, Quartz 병용 처리, 알려진 위험(소리 지연·음량·피치·일시정지), Claude 가 게임에서 돌릴 순서(`hitsound state/verify`, HELLO 전곡 A/B: 끔/켬 새 프로세스 + Quartz 없음, 그 다음 Quartz 있음(RenderAllHitSounds 켠 상태)에서 우리 켬 → 이중 재생 없음 확인, 효과 비교 기준: 평균 194→224 근처, 1% low 99→118 근처).

# Codex 과제 S2f: decorender — 정렬 키 전체를 한 번에 가져가고, 그룹 안 순서를 "재질 인스턴스 ID" 규칙으로

같은 규칙(E:\StutterFixWork\wt-decorender, 커밋·게임 실행·설치 금지, `#if DEV || AUTOTEST`, 사용량 절약). 결과 문서 `docs/handoff/codex-decorender-5-20261020-result.md`.

## 실측 근거
1. `sortprobe`(2,550 시험) 유효 결과: 같은 (sortingLayerID, sortingOrder)에서 순서를 정하는 규칙은 대략 **(렌더 큐, 카메라까지 거리(z), 재질 인스턴스 ID 오름차순(뒤→앞 순서))**. 재질이 다르면 `material-id` 규칙이 n=2·6 에서 100%, n=3 에서 98%, 큐가 다르면 큐 우선 100%, z 가 다르면 거리 우선 100%. 재질도 같을 때(생성 순서/형제 순서/부모 시험)는 시험이 무효(valid=0)로 나와 규칙을 못 정했다(동일 재질 동률은 불안정할 수 있음). **MeshRenderer 와 SpriteRenderer 의 동률은 생성 순서(렌더러 instanceID)를 따랐다**(mesh-last n=2: 뒤→앞 순서가 id 오름차순 100%).
2. 이 게임의 이미지 장식은 **장식마다 재질 인스턴스가 따로** 있다(census: 재질 인스턴스 1,100개 / 재질 종류 1개). 즉 같은 키 안 장식 순서는 사실상 "각 장식 재질의 instanceID" 순서일 가능성이 크다.
3. 지금 `decorender` 는 키 안 순서를 Renderer instanceID 오름차순으로 가정하고, 키를 비관리 렌더러와 공유하는 장식은 모두 제외했더니(`shared-order=1787/1795`) 선택이 6개로 줄었다. 공유 상대는 거의 전부 **같은 키의 다른 장식**(키 0/1: 관리 34 + 비관리 847 등, 대부분 지금은 안 그려지는 `forceRenderingOff` 상태).

## 바꿀 것
1. **키 단위 가져가기**: 정렬 키 `(layer, order)` 의 장식 전체(보이든 안 보이든 `scrVisualDecoration` 전부)가 모두 아틀라스 가능(`Sprites/Tile` 기본값 조건, Clamp, 한 변 ≤ 2048, 마스크/히트박스 아님, 점샘플링 아님)이고, 그 키에 비관리 렌더러(타일·행성·다른 종류 렌더러·장식이 아닌 것)가 없을 때만 그 키를 통째로 관리한다. 하나라도 불가능한 장식이 있으면 그 키 전체를 제외(`key-not-fully-eligible`). 키별 (전체 장식 수, 가능 수, 제외 이유)를 로그. 키가 관리되면 그 키의 장식 전부를 같은 그룹 메시(아틀라스 페이지마다 하나)에 두고, **안 그려야 하는 장식(알파 0, `forceRenderingOff`, 비활성)은 그 프레임 정점을 내보내지 않는다**(현재 보임 판정은 SpriteRenderer 의 enabled/forceOff/alpha 를 그대로 따라 읽는다). 보임이 바뀌어도 순서는 안 바뀐다.
2. **그룹 메시 안 순서**: 키 안 장식을 **원래 `sharedMaterial.GetInstanceID()` 규칙**으로 정렬한다: sortprobe 의 뒤→앞 순서와 같은 방향(결과 문서의 `trials.csv`/report 로 방향 확인: 재질 ID 오름차순이 뒤→앞인지). 같은 재질이 우연히 같은 장식이 있으면 Renderer instanceID. 이 순서는 `on` 시점에 한 번 정해 고정(재질 인스턴스는 안 바뀌는지 changed 감지에 포함: 재질이 바뀌면 그 키 전체 복귀).
3. **그룹 메시 렌더러 대 키 안 다른 렌더러**: 키를 통째로 가져가면 비관리 렌더러와의 동률이 없다. 키 단위 조건을 만족하는 키만 관리하므로 그룹 대 비관리 동률은 처음부터 없다. 그래도 그룹 메시 자신들(같은 키의 아틀라스 페이지 둘 이상)은 동률이므로 키당 아틀라스 페이지가 둘 이상이면 그 키를 제외(`split-order`, 이미 있음).
4. 나머지(관찰 20프레임은 이제 "움직이는 장식이 하나라도 있는 키"를 고르는 데 사용: 정적 키는 가져가지 않는다, 변화 감지 시 키 단위 복귀, compare, floatcolor 옵션, `state` 항목)는 그대로 두되 키 단위 통계를 `state` 에 추가: 관리 키 수, 관리 장식 수(보이는/안 보이는), 제외 키 수와 이유별 개수, 정점 수.

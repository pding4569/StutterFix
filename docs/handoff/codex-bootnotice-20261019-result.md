# boot.config 재시작 안내 작업 결과 — 2026-10-19

게임 실행·Mods 설치·커밋을 수행하지 않았다. boot.config 실파일도 시험에 사용하지 않았다. 최적화 기본값과 기존 파일 변경·백업·복원 로직은 유지했다.

## 변경 위치

- `BootConfig.cs`: `NeedsRestart`, `ResetByOutside` 추가. 첫 Apply 때 실행 중 그래픽 작업 모드(SystemInfo, Describe와 같은 정보)와 변경 전 설정을 보관한다. 실제 쓰기에 성공했고 실행 중 상태와 목표가 다를 때만 재시작 필요로 표시한다. 줄 끝 복구만 하는 경우는 제외한다. 사용자 토글을 실행 중 값으로 되돌리면 표시도 해제한다.
- `StutterFix.cs`: 시작 시 Apply 호출에 `userChange: false`에 해당하는 세 번째 인자 `false`만 추가했다. 기존 설정 토글 호출은 기본값 `true`를 사용한다.
- `RestartAdvisor.cs`: 홈의 기존 재시작 이유를 `NeedsRestart`로 판단한다. 재시작 실행·확인·저장 보호·맵 재열기 구현은 바꾸지 않았다.
- `SettingsWindow.cs`: 상태 필드와 별도 안내 메서드, Update/OnGUI 연결, Destroy 정리만 추가했다. 실험 탭과 HitSoundBatch 관련 코드는 수정하지 않았다.
- `AutoTest.cs`: `bootnotice show|state|reset` 명령을 추가했다. DEV/AUTOTEST 전용이며 일반 Player에는 시험 진입점이 없다.

## 감지 조건과 표시

외부 초기화는 시작 시 Apply에서 설정을 실제로 바꾸면서, 켜려는 `force-gfx-jobs` 키가 없거나 Flip을 켜려는데 `force-d3d11-bitblt-model` 줄이 있었을 때로 구분한다. 파일 모양에 따른 추정이므로 Steam 동작 자체를 입증하지는 않으며 첫 설치도 같은 조건에 해당할 수 있다. 사용자가 설정을 바꾼 호출은 이 조건으로 분류하지 않는다.

작업 모드는 파일의 legacy 줄만 보고 적용됐다고 가정하지 않고 실행 중 `SystemInfo.renderingThreadingMode`를 사용한다. 출력 방식은 시작 시 파일 상태와 `-force-d3d11-bitblt-model` / `-force-d3d11-flip-model` 실행 인자를 보관한다. 실제 출력 방식의 PresentMon 검증은 하지 않았다.

안내는 화면 위쪽 가운데, 어두운 바탕·반지름 6·기존 글꼴과 버튼으로 표시한다. 한글 본문은 기존 `Wrapped`의 띄어쓰기 기준 줄바꿈을 사용한다. 메뉴에서 표시된 시간 합계가 최대 20초이며 재생·게임 장면·편집기·시작 로딩 장면에서는 숨긴다. 설정 창이 열리면 안내를 숨겨 홈 카드와 겹치지 않는다. 안내가 보이는 동안 기존 업데이트 알림도 그리지 않는다.

외부 초기화 문구:

> Steam 업데이트로 그래픽 설정(boot.config)이 초기화됐습니다. StutterFix 가 다시 써 뒀지만 게임을 한 번 다시 시작해야 적용됩니다. 그 전에는 프레임이 낮게 나올 수 있습니다.

사용자 변경 문구:

> 그래픽 설정을 바꿨습니다. 다시 시작하면 적용됩니다.

두 문구와 제목·버튼은 `T(한글, English)`로 제공한다. `나중에`를 누르면 이번 실행에서 다시 표시하지 않는다. 시간 만료나 닫기는 홈의 재시작 이유를 지우지 않는다.

`지금 다시 시작` → `한 번 더 누르면 재시작`(3초 내 두 번째 클릭) → 기존 `RestartAdvisor.Restart` 경로를 사용한다. 기억한 에디터 맵이 있으면 기존 재열기를 사용하며, 저장 보호에서 막히면 해당 안내와 6초 확인 시간을 유지한다. 자동 재시작은 없다. 카드 영역 클릭 차단은 별도 소유자를 사용하고 기존 Main.Unload → SettingsWindow.Destroy 경로에서 해제한다. 새 정적 이벤트·콜백 등록은 없다.

실제 변경이 현재 실행과 다를 때 로그:

```text
[그래픽 설정] 이번 실행은 boot.config 가 적용되지 않았습니다 (외부 초기화)
[그래픽 설정] 이번 실행은 boot.config 가 적용되지 않았습니다 (사용자 변경)
```

## Claude가 수행할 게임 확인 순서 — 이 작업에서는 미실행

1. DEV 또는 PlayerAuto 설치 후 메뉴에서 `bootnotice state`로 실제 상태를 기록한다. `bootnotice show`는 시험 플래그만 세우며 boot.config를 읽거나 쓰지 않는다.
2. `bootnotice show` → `shot bootnotice-ko`로 카드 위치·줄바꿈·버튼을 확인한다. English로 바꿔 같은 순서를 반복한다. 작은 화면에서도 잘리지 않는지 확인한다.
3. 설정 창 홈을 열어 상단 카드가 숨고 기존 재시작 권장 카드가 유지되는지 확인한다. 시험 플래그 자체는 홈 재시작 이유를 추가하지 않는다.
4. 메뉴로 돌아와 `나중에`를 누르고 `bootnotice state`의 dismissed=True를 확인한다. `bootnotice show`는 명시적으로 닫힘 상태와 표시 시간을 초기화한다. 20초 표시 후 사라지는지도 확인한다.
5. `bootnotice reset`은 시험 플래그를 끄고 닫힘·표시 시간·확인을 초기화한다. 실제 NeedsRestart/ResetByOutside는 바꾸지 않는다. 실제 재시작 필요가 없으면 카드는 나타나지 않는다.
6. 시험 카드를 켠 뒤 재생·편집기로 이동해 숨김과 클릭 차단 해제를 확인한다. 메뉴로 돌아오면 남은 표시 시간만 이어지는지 확인한다.
7. 재시작을 허용한 별도 시험에서 첫 클릭만으로 종료되지 않는지, 두 번째 클릭의 기존 재시작과 마지막 에디터 맵 복귀가 동작하는지 확인한다. 저장 안 된 편집의 보호는 기존 에디터 재시작 경로에서도 확인한다. 카드 자체는 편집 중 숨기므로 해당 상태에서 카드를 강제로 노출하지 않는다.
8. 정식 Player에서 외부 초기화 직후 첫 실행의 위 로그와 실제 카드를 확인하고, 재시작 후 NeedsRestart 안내가 사라지는지 확인한다. 실제 초기화 시험은 게임 실행을 허용한 별도 작업에서 수행하며 `bootnotice show`로 파일을 초기화할 수 없다.

화면 캡처, 실제 Player 안내 로그, 엔진 적용 여부, 재시작·저장 보호의 게임 내 동작은 미검증이다. 게임 실행 금지에 따라 위 절차를 인계한다.

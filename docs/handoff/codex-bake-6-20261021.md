## 해야 할 것
1. **매끄러운 단조 곡 시계** 설계·구현(`DecoBake`, 그림자 모드 유지): 입력 = 매 프레임 `songposition_minusi`(지터 있음)와 게임이 쓰는 델타(`Time.deltaTime` 또는 smoothDeltaTime × `DOTween.timeScale`, `DecoAnim.UpdatePrefix` 와 같은 값). 평가 시각 `tb` 는 (a) 이전 `tb` 에 이번 프레임 델타(×pitch 반영)를 더해 전진하고 (b) `songposition_minusi` 와의 차이를 작은 이득(예: 프레임당 1~5%)으로 천천히 끌어당겨 누적 드리프트를 없애며 (c) 큰 차이(>50ms, 일시정지·seek·되감기·재시작)에서는 즉시 재동기. 단조(되감기 전까지) 보장. 이 방식이 "프레임 델타 누적(원본 Rec)"과 "곡 시각 기준(굽기)"의 절충임을 문서에 명시하고, **무상태 평가기 자체는 그대로**(입력 시각만 매끄럽게). 에디터 미리보기에서 임의 점프는 (c)로 즉시 재동기.
2. **오프라인 fixture 로 효과 증명**: 증거 파일의 12개 행(frame, songposition_minusi, actual, dt, RecPos)과 효과 파라미터(T0=9.9, dur=0.9, linear, 5812.06055→−5647.93945)로, (i) 현재 방식(raw songposition) 오차와 (ii) 새 `tb` 방식 오차를 계산해 비교하는 검사를 `tools/decobake-contract-check` 에 추가(같은 입력으로 재현). 합성 지터(±6ms 균등/버퍼 계단형)에서 새 방식의 최대 시간 오차가 1~2프레임 이내가 되는지, 드리프트 없는지, 일시정지/되감기에서 재동기되는지.
3. **verify 지표를 시간 단위로 병행**: 표본마다 `|actual−baked| / |그 프레임 속도(단위/초)|` 로 "시간 환산 오차(ms)"를 계산해 속도 큰 표본만 거대해 보이는 문제를 걷어낸다(속도 0 근처는 NA). 속성별 시간 환산 오차 n/최대/p99/RMS 와 프레임 수 환산(프레임 길이 대비)을 로그. 기준: 시작 위상 ≤ 1프레임, 시간 환산 오차 p99 ≤ 2프레임(제안). 기존 원단위·픽셀 환산 지표도 유지.
4. **버그**: 재생 중 `stop` → `seek 262 8` → `wait 1` → `decobake ready` 에서 `ArgumentOutOfRangeException`(Index was out of range...)로 중단(`night-results/bake5.log` 줄 342). 원인을 코드로 찾아 고치고(seek 가 PrepVfx/Setup 을 다시 돌려 스냅샷 세대가 바뀌는 경로일 가능성: 이전 세대 배열 인덱스 사용), fixture 에 재현 케이스 추가. 실패해도 예외로 죽지 말고 "재준비" 로 복구.
5. **evalActive**: 비단조 테이프(카운트다운 되감기)에서 관측 불가로 나오지 않도록 되감기 구간에서 커서를 재설정하고 단조 구간만 측정. 목표 ≤0.5ms/프레임이 합성(fixture)에서뿐 아니라 실측에서 나오게 하는 데 필요한 변경.
6. 빌드 3종(`-c Release`; `-p:Edition=Player`; `-p:Edition=Player -p:AutoTestBuild=1`) 오류 0 + LoadCheck + 기존 fixture 통과. Player 제외, 그림자 모드, `Module.ResolveSignature` 금지, 새 Harmony 패치 없이.

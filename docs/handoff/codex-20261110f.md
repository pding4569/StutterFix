## 1. 파티클 장식을 RunLod 후보로 (`runlod particles on|off`, 기본 off)

- 후보: `ParticleSystemRenderer` 이고 부모에 `scrParticleDecoration` 이 있으며, 재질 셰이더가 Sprites/Default 또는 Sprites/Tile, 섞기가 미리 곱한 알파(지금 SpriteRenderer 조건과 같은 검사: `_SrcBlend`/`_DstBlend` 가 없거나 1/10), 마스크 상호작용 없음, SortingGroup 없음, renderMode 가 Billboard(메시·스트레치 제외), 트레일 없음(trailMaterial 사용 안 함).
- 확대율: 파티클 하나의 화면 크기 / 텍스처 크기. 보수적으로 `main.startSize` 의 최솟값(곡선·랜덤 모드별 min) × `transform.lossyScale` × ppw / max(texW,texH). `sizeOverLifetime`·`sizeBySpeed` 가 켜져 있으면 그 곡선의 최솟값 배율을 곱하고, 못 구하면 후보에서 뺀다. 텍스처 시트 애니메이션이면 칸 크기로 나눈 텍스처 크기를 쓴다. `MinMag` 이상일 때만 묶음에 넣는다(지금 규칙 그대로).
- 지금 `Cand.R` 이 `SpriteRenderer` 형이라 `r.sprite` 등을 쓴다. Renderer 공통으로 일반화하되 SpriteRenderer 경로의 동작·성능은 그대로 둔다. 보임 알림(VisTag)·정렬 키(큐, 정렬층, 순서, 거리, 셰이더 ID, 재질 ID)·화면 사각형(ViewRect: renderer.bounds)·`cb.DrawRenderer` 는 파티클에도 같은 방식으로 쓴다. 파티클 재질이 여러 개(sharedMaterials 길이 > 1)면 후보에서 뺀다.
- 게임 코드 확인: `E:\StutterFixWork\decompiled\Assembly-CSharp\scrParticleDecoration.cs`, `ADOFAI.FloorFX\ffxSetParticlePlus.cs`, `ffxEmitParticlePlus.cs` — 재질·텍스처·크기·정렬을 언제 바꾸는지 보고, 바뀌면 후보 캐시(재질 32프레임 재확인 방식)를 따라가게 한다.
- `runlod state` 에 파티클 후보 수/프레임당 파티클 구성원 수를 추가한다(실제로 탔는지 증거).

- 후보 루프: `r.bounds`·`sortingLayerID`·`sortingOrder` 등 엔진 호출을 후보당 한 번씩만(중복 호출 제거), 값이 안 바뀐 후보의 재계산 생략은 **바뀐 것을 확실히 아는 경우에만**(추측 캐시 금지: 깊이는 이벤트로 즉시 바뀐다).

개발자용 대조: `runlod verify on` 이면 같은 프레임에 옛 방식과 새 방식의 묶음 목록(구성원 렌더러 ID 열, 사각형, 해상도)을 비교해 다르면 로그(`[묶음 LOD] 검증 다름 ...`)와 횟수. 기본 off, 켰을 때만 비용.

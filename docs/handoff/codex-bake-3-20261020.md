# Codex 임무 bake-3: 크기(scale) 지원 + 지원률 오프라인 추정

2026-10-20. 작업 폴더 `E:\StutterFixWork\wt-bake` (브랜치 `codex/night-bake`, bake-2 커밋 c055112 위). 게임 실행·설치·커밋 금지. 결과 `docs/handoff/codex-bake-3-20261020-result.md` + `-o` 파일(10줄).

## 문제
bake-2 는 **크기(scale) 변경이 하나라도 있는 장식을 통째로 굽기에서 제외**한다(첫 Step 의 지연 Startup 과 X/Y getter 순서를 정의하지 않아서). 그런데 Arche 의 MoveDecorations 이벤트 95,211개 중 **74,259개(78%)가 scale 을 포함**한다(`"scale": [` 정규식 계수). 이대로면 지원률이 0 에 가까울 것이다. 크기 지원이 굽기의 필수 조건이다.

## 해야 할 것
1. **크기 의미 확정**: `DecoAnim.cs`(`Startup`, `Step`, scale X/Y 처리), `ffxMoveDecorationsPlus.StartEffect/Decode`(크기 목표, 상대/절대, `scale` 가 null/NaN 인 축), `scrDecoration` 의 localScale/`realScale`/`tilingScale`/피벗·시차와의 관계를 읽어 (a) 시작값을 언제·무엇에서 읽는지(첫 Step 지연 vs StartEffect 시점), (b) X/Y 축별 읽기 순서, (c) 교체 시 이전 효과 완료/Kill 과의 관계, (d) 같은 프레임 여러 효과의 영향을 정리. 위치/회전에서 이미 구현한 교체 규칙(이전 완료 후 새 시작값)이 크기에도 같은지 코드 근거로 확인. **모르는 갈래는 구현하지 말고 그 장식 전체를 제외 사유로 센다**(이유 문자열 구분).
2. 구현: `DecoBake.Core.cs`/`DecoBake.cs` 에 scale 채널(X,Y) 추가. 곡 시각 기반 무상태 평가, 이징 재사용. `decobake verify` 에 scale 오차 통계(상대 오차, 픽셀 환산 가능하면 스프라이트 크기 곱) 추가. 오프라인 fixture(`tools/decobake-contract-check`)에 크기 교체·상대 크기·NaN 축·길이 0 예제 추가.
3. **오프라인 지원률 추정 도구** `tools/optimization/bake-support-estimate.py`(읽기 전용): Arche `.adofai`(`D:\얼불춤 맵 파일\Arche\` 의 `*FULL.adofai` 하나, 정확한 파일 지정)를 읽어 장식 인스턴스별로 bake-2/3 의 제외 사유(초기 배치, 마스크, 히트박스, 이미지 변경, 사용자 이징, 이벤트 종류 등)를 이벤트 파일만으로 가능한 범위에서 추정해 사유별 **고유 장식 수와 비율**, 전체 지원 장식 비율(이벤트 파일로 판정 불가한 항목은 "미정" 칸으로 분리)을 표로 출력. 지원률이 낮으면 **어떤 사유를 풀면 가장 많이 늘지** 상위 5개를 제안(코드 근거와 함께).
4. 빌드 3종(`-c Release`; `-p:Edition=Player`; `-p:Edition=Player -p:AutoTestBuild=1`) 오류 0 + LoadCheck. Player 제외 확인.

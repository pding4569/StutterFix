# Codex 임무 bake-2: 굽기 컴파일러 프로토타입 구현 (시간 의미를 "곡 시각 기반"으로 정의, 그림자 모드만)

2026-10-20. 작업 폴더 `E:\StutterFixWork\wt-bake` (브랜치 `codex/night-bake`). 게임 실행·설치·커밋 금지. 결과 문서 `docs/handoff/codex-bake-2-20261020-result.md` + `-o` 파일(10줄 이내 한국어).

## 배경과 결정
앞 임무 결과(`docs/handoff/codex-bake-20261020-result.md`)대로 기존 `DecoAnim` 은 프레임 델타 누적이라 무상태 굽기가 비트 동일일 수 없다. 사용자는 오늘 밤 테스트를 안 돌리고, 미리 **틀(프로토타입)**을 개발해 두라고 했다. 그래서 이번에는 **곡 시각 기반 새 의미를 프로토타입의 기준으로 채택**한다(제품 채택·릴리스는 사용자 승인 전 금지, 기본 꺼짐, 그림자 모드만: 기존 경로를 건드리지 않고 값을 따로 계산해 비교만 한다).

## 만들 것 (`DecoBake.cs` 등, `#if DEV || AUTOTEST`, Player 제외, 기본 꺼짐, `Main.Unload` 되돌리기)
1. **수집**: 효과 목록이 확정되는 지점(앞 임무 결과 "A: 게임에서 그대로 읽을 곳" 표)에서 `ffxMoveDecorationsPlus`(우선; 위치/회전/크기/색/불투명도/시차 등 지원 속성) 인스턴스를 읽는다: `startTime`, `startEffectOffset`, `duration`, 이징, 대상 태그→장식 집합(`scrDecorationManager.GetTaggedDecorations` 의미 재사용), 각 속성의 목표값·상대/절대 기준·`angleOffset`·반복 전개된 인스턴스 각각. 실행 순서는 `PrepVfx` 의 정렬 순서(`scrVfxPlus.instance.effects`)를 그대로. 훅은 이름+인자 수+호출 규약으로 **정확히 하나**만 고르고 실패하면 설치하지 않는다(**`Module.ResolveSignature`/`ResolveMethod(MetadataToken)` 금지** — Mono 에서 안 된다). 새 Harmony 패치를 최소화(가능하면 이미 있는 후크 재사용).
2. **굽기**: 장식(인스턴스)×속성별 시간순 구간 표. 구간 = 예약 시작 T0(=startTime−startEffectOffset), 길이, 시작값, 끝값, 이징 id/파라미터. **교체 규칙은 기존과 같게**: 같은 장식·같은 속성에 새 이벤트가 시작되면 (a) 상대 목표의 기준값은 이전 효과를 끝내기 전의 현재값에서 잡고 (b) 이전 효과는 끝값까지 완료(`Kill(true)`)된 뒤 (c) 새 시작값은 그 완료값이다(예: 현재 4, 이전 끝 10, 상대 +2 → 새 시작 10, 새 끝 6). 길이 0 은 T0 에 즉시 값. 이 규칙을 `ffxMoveDecorationsPlus.StartEffect` 와 `DecoAnim` 코드를 읽어 정확히 구현하고, 모르는 갈래는 구현하지 말고 **지원 안 함 사유로 센다**(그 장식 전체를 굽지 않음).
3. **시간 대응**: 기존 Rec 는 `Time.deltaTime*DOTween.timeScale` 로 진행한다. 곡 시각(`conductor.songposition_minusi` 등)과 게임 진행 시간의 관계(피치, 보정 `calibration_i`, 일시정지)를 코드에서 확정해 문서에 적고, 평가 `Eval(장식, 속성, 곡시각)` 이 **무상태**(같은 입력→같은 값, seek/되감기 무관)가 되게 한다. 이징은 기존 `DecoAnim` 이징 함수를 그대로 재사용.
4. **평가기**: 구간 표 이진 탐색(또는 커서) → 값. 기존 `DecoBatchEval`(DecoSim.cs)의 SoA 형태를 참고하되 누적기가 아닌 무상태로.
5. **검증 명령 `decobake verify`**: `DecoSim` 테이프(프레임별 실제 `Rec` 출력)와 같은 프레임의 곡 시각에서 굽기 평가를 대조. 테이프에 프레임별 곡 시각이 없으면 `DecoSim` 에 기록을 추가(개발 전용). 불일치는 **비트 동일이 아니라 오차 통계**로: 속성별 최대 절대 오차·p99·상위 장식 8개, 효과 시작 프레임 위상 차이(프레임 수), 교체 발생 장식의 오차, 지원 안 함 사유별 장식 수·비율. 위치는 월드 단위와 화면 픽셀 환산 둘 다(3440×1440 기준). 눈에 안 띄는 기준 제안: 위치 0.01 픽셀 이내.
6. **비용 명령 `decobake bench`**: 굽기 시간(Arche 28,828 장식·95,211 이벤트), 메모리, 평가 시간. 굽기는 메인 프레임 16ms 이하 분할 또는 작업 스레드 + 메인 스냅샷 단계 분리.
7. 빌드 3종(`-c Release`; `-p:Edition=Player`; `-p:Edition=Player -p:AutoTestBuild=1`) 오류 0 + LoadCheck. 오프라인 fixture(`tools/decobake-contract-check` 확장 가능)로 교체 규칙 예제·이징·길이 0·반복을 검사.

# 설정창에 "GPU 장식" 페이지 분리 (Codex 작업 명세)

작업 폴더: `E:\StutterFixWork\wt-ui` (브랜치 `claude/player-ui`). 게임을 켜거나 커밋하지 않는다. 빌드만 확인한다.

## 목표
`SettingsWindow.cs` 의 플레이 → 실험 탭("장식 이동 실험" 묶음) 안에 섞여 있는 새 GPU 장식 시스템 설정 두 개를
**독립된 새 페이지 "GPU 장식"(영문 "GPU decorations")** 로 옮긴다. 쉐이더 페이지(번호 8)를 추가했던 방식(`DockOrder`, `PageNames`, 페이지 그리는 분기, 도크 높이 `10*IconS` 의 아이콘 개수 계산, 클램프 `Mathf.Clamp(page, 0, 8)`)을 그대로 따른다. 새 페이지 번호는 9, 도크 순서는 그래픽(3) 다음에 쉐이더(8), 그 다음 GPU 장식(9).

## 옮길 것
- `c.GpuDeco == 1` 토글 "GPU 장식 처리 (실험)" (키 `gpudeco`)
- `c.GpuDecoImages == 1` 토글 "이미지 장식도 GPU로 처리" (키 `gpudecoimages`, `gpuDeco` 가 꺼져 있으면 흐리게 — 기존 `Option(..., 1, gpuDeco ? null : T(...))` 그대로)
- 플레이 → 실험 탭에는 이 두 줄을 지운다. 다른 "장식 이동 실험" 줄(moveepsilon 등)은 그대로 둔다.

## 새 페이지 내용 (T() 한/영 쌍 필수, 기존 말투: 짧고 사실만)
1. 맨 위 제목 줄/설명: 한 줄. 예) "장식이 아주 많은 맵에서 장식 이동을 GPU가 계산합니다."
2. 위 두 토글(설명 문구는 기존 것을 그대로 쓰되 "장식 2만 8천 개 기준 약 5초" 는 "처음 한 번 약 5초, 같은 맵을 다시 하면 1초 안팎" 으로 고친다 — 근거: 이식 측정에서 첫 준비 5.3초, 다시 하기·편집기 재생 0.9초).
3. "알아 둘 점" 묶음(읽기 전용 글줄, 스위치 없음): 
   - 켜면 재생을 시작할 때 준비 시간이 늘어난다(맵 장식 수에 비례).
   - 다음 재생부터 적용된다. 켜고 끄기를 재생 중에 바꾸지 않는다.
   - 지원하지 않는 맵·환경에서는 알아서 원래 처리로 돌아간다.
   - 정렬이 같은 순서로 그려져야 하는 극히 일부 장식은 원래 렌더러로 남는다(그래서 아주 드물게 화면이 한두 픽셀 다를 수 있음). 
4. 상태 줄(읽기 전용, 한 줄): 이번 맵에서 GPU 처리 중인지. 이미 있는 정적 상태가 있으면 쓰고(예: `GpuDecoPlayer` 의 켜짐 여부 공개 속성), 없으면 이 줄은 만들지 말고 최종 보고에 "상태 줄 없음" 이라고 쓴다. 새 공개 속성은 `GpuDecoPlayer.cs` 를 수정하지 말고 이미 있는 것만 읽는다 (그 파일은 다른 작업 중).

## 건드리지 말 것
- `GpuDeco*.cs`, `DrawCollapsePolicy.cs`, compute/bundle 파일. 설정 필드 이름·저장 형식(`Settings.xml`)은 그대로.
- 다른 페이지의 레이아웃과 색. 지침: `CLAUDE.md` 의 "설정 창 디자인"(Linear/Raycast, 상자 없이 목록 줄, 빨강은 끊긴 프레임에만).
- 아이콘: 기존 페이지 아이콘을 그리는 방식을 따라 GPU 장식용 아이콘을 하나 추가한다(칩/격자 모양, 같은 선 굵기). 손으로 만든 큰 장식은 넣지 않는다.

# 임무: 체감이 큰 최적화를 스스로 찾고 고친다 (Codex 자율)

사용자 목표(AGENTS.md): **플레이 중 순간 끊김을 없애고, 기다리는 시간을 줄인다.** 평균 FPS 보다 끊김 제거가 우선. 프레임 늘리기(보간)는 이번 임무 범위 밖이다(건드리지 않는다).
토큰 사정상 Claude 는 최소로 개입한다. 아래 순서를 스스로 끝까지 한다. 모르는 것은 AGENTS.md 의 "확정된 원인과 해결"·"측정에서 배운 것"과 docs/ 를 먼저 읽는다.

## 해야 할 일

1. **후보 찾기(측정 기반)**: 아래 4개 맵을 곡 전체로 돌려 끊김·기다림을 모은다. 게임은 `tools/sfmeasure`(파이썬)로 켠다(`sf_run` 에 해당하는 server.py 함수를 `python -c "import server as S; ..."` 로 직접 부른다. 사용법은 AGENTS.md "켜 둔 게임 다시 쓰기" 참고).
   - `D:/얼불춤 맵 파일/HELLO (BPM) 2026/level.adofai` (타일 많음)
   - `D:/얼불춤 맵 파일/Arche/[𝐃𝐎 𝐍𝐎𝐓 𝐎𝐏𝐄𝐍 𝐓𝐇𝐈𝐒 𝐀𝐓 𝐇𝐎𝐌𝐄] FULL.adofai` (장식 많음, 파일 큼)
   - `D:/얼불춤 맵 파일/Windflower/Windflower.adofai` (이미지 많음)
   - `D:/얼불춤 맵 파일/Plum - Timeline/Timeline.adofai` 또는 `7777`·`scam` 중 하나(타일 이동 효과)
   각 맵: 맵 열기 시간, 첫 재생까지 시간, 곡 중 30ms 넘은 프레임 수와 위치·원인, 끝날 때·다시 하기·편집으로 나갈 때 걸리는 시간.
2. **순위**: 사용자가 "겁나 크다"고 느낄 만한 순서(초 단위 대기 > 50ms 넘는 끊김 > 30ms)로 표를 `docs/handoff/big-perf-findings.md` 에 만든다.
   이미 고친 것(AGENTS.md 표)은 빼고, 원인 미확인인 것은 PerfView(`tools/etwstall` 문서) 없이 알 수 있는 데까지만 적는다.
3. **고치기**: 순위 위에서 **원인이 코드로 잡히고 원래 게임과 같은 화면을 지킬 수 있는 것** 1~3개를 고친다.
   - 효과·판정·소리·화면은 원래와 같아야 한다. 같은지 대조하는 방법(개발자용 대조 명령 또는 바이트 비교)을 함께 만든다.
   - 새로 게임에 거는 것(Harmony, 정적 이벤트)은 `Main.Unload` 에서 되돌린다. 설정은 기본 켬(확정 이득일 때) 또는 기본 끔(불확실).
   - 측정: 같은 맵·같은 조건 4판 이상 A/B(`sf_ab` 방식, 판마다 게임 새로 켬). 전/후 숫자와 판 수를 findings 문서에 적는다. 이득이 작으면(맵 열기 0.3초 미만, 끊김 변화 없음) 넣지 않고 이유만 적는다.
4. **빌드**: `dotnet build -p:Edition=Player -p:AutoTestBuild=1` 과 `-p:Edition=Player` 둘 다 오류 0. 정식 DLL 에는 개발용 대조·진단이 안 들어가게(Edition 조건).
5. **끝낼 때**: 작업 폴더에서 게임이 꺼져 있는지 확인하고, Mods 폴더에는 **정식 `bin/Player/StutterFix.dll`** 을 복원해 둔다(자동 시험 DLL 을 남기지 않는다). 마지막 메시지에 상위 3줄 요약: 무엇을 얼마나 줄였는지(전→후), 못 한 것, 사용자가 확인할 것.

## 하지 말 것

- 커밋·푸시·태그·릴리스·main 변경(샌드박스에서도 막혀 있다. 변경은 작업 폴더에 둔다. Claude 가 검토 후 커밋).
- 프레임 늘리기(FrameGen*, framegen*.h), 화면 효과(쉐이더) 코드.
- 다른 모드 코드 수정, 사용자 설정 파일(Settings.xml)을 시험 뒤 원래 값으로 복원하지 않는 것.
- 시험 맵 이름이 아닌 개인 맵(헤르츠 맵 모음, 100만 타일 맵)을 여는 것.
- 한 번에 큰 리팩터링. 작은 수정 → 측정 → 다음.

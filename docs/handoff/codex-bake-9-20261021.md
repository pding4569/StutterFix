## 실측 (Arche 258→278초, 판마다 새로 켠 끔·켬·켬·끔; `docs/optimization-36.md` 끝 표)
채택 켬은 프레임당 장식 CPU 합계 **3.62~3.66ms vs 끔 3.16~3.21ms(+0.45ms), FPS −8~10%, 켤 때 580~590ms 프레임**. 구성: 켬 = 모드 애니메이션 갱신 0.31 + 효과 시작 0.07 + 관리자 LateUpdate 1.08 + **채택 구동 평균 2.20 / p99 4.9 / 최악 5.6ms**, 끔 = 갱신 1.92 + 시작 0.13 + LateUpdate 1.12. 기록 219,807 → 14,649, `skippedRec` 205,158. 게임에서 활성 채널은 평균 **11,452개/프레임**(`evalActive` 중앙 0.91ms), `forceRenderingOff` 불일치(채택 켬에서 알파 0 장식이 숨겨지지 않음 — `DecoAnim.Bake.cs` 의 `BakeWrite` 는 `MoveApply.DeferTransform` 만 쓰고 `InvisibleSkip.After`/색 경로를 안 탄다). 서명 비교는 캡처가 무거워(10초 30프레임) 시간 정렬 실패.

## 제미나이 제안(검증 대상 — 코드/계측으로 참·거짓을 가리고, 참이면 채택)
1. **`forceRenderingOff` 누락 수정**: 채택에서 최종 알파(`color.a × opacity × floor`) ≤ 0 이면 `InvisibleSkip` 과 같은 규칙으로 강제 숨김/해제, 알파≤0 동안 위치·회전·크기는 C# 필드만 갱신하고 Unity Transform 호출은 알파>0 첫 프레임까지 미룸(이미 `MoveApply.DeferTransform` 으로 일부 함 — 빠진 갈래 찾기). 이것이 채택 구동 2.2ms 의 큰 몫인지 **단계별 시간 분해**로 확인(평가 / 위치 쓰기 / 회전 / 크기 / 색 / 숨김 판정 / 목록 순회).
2. **정지 구간(plateau) 장식 순회 제거**: 활성 구간 장식만 평가하고 끝나는 프레임에 끝값을 한 번만 쓰기. (우리 측정은 활성 채널 평균 11,452개로 제미나이가 말한 600~800개보다 훨씬 많다 — 왜 많은지: 겹치는 효과, 같은 장식 여러 채널, 긴 구간 등 분해해 보고, 줄일 수 있으면 줄인다.)
3. **트리거 앵커 시계(Trigger-Anchored dt clock)**: 재생 중 전역 `accumDt += Time.deltaTime * DOTween.timeScale`(원본 `DecoAnim.UpdatePrefix` 와 같은 값)을 두고, 효과 인스턴스(Source ID)가 **실제로 시작되는 프레임**(`FastMove.Prefix` 가 이미 관찰)에 `startTau[source] = accumDt` 를 한 칸 기록. 채택 평가는 `pos = accumDt − startTau[source]`(교체 규칙은 표가 이미 가짐). 이렇게 하면 원본 Rec 와 **같은 시작 프레임·같은 dt 누적**이라 곡 시계 지터가 0 이 된다(재생 중). seek/되감기/에디터 미리보기는 기존 `tb`(무상태)로 폴백. 적용 가능성·부작용(교체 시 Kill(true) 완료값, 같은 프레임에 여러 효과, 일시정지)을 코드로 검토하고 구현.
4. **카나리아 표본 비교(같은 판 안)**: 채택 켬 판 안에서 고정 해시로 뽑은 대표 장식 64~128개는 **소유하지 않고 원본 Rec 를 그대로 돌리며**, 같은 프레임에 채택 평가값을 계산만 해 비교(쓰지 않음). 같은 프레임이라 시간 정렬 문제가 없고 프레임당 비용이 작아야 한다(<0.05ms). 오차(위치/크기/알파/숨김 판정 불일치)를 `decobake adopt state` 에 누적 통계로 낸다. 기존 `verify`/서명 비교는 유지하되 주 검증은 이것.
5. **켤 때 580ms 프레임**: 채택 시작(전체 재평가+소유 전환)의 비용을 분해하고 **여러 프레임에 분할**(예: 프레임당 ≤2ms 예산, 순서 설계, 분할 동안 원본/채택 값 불일치가 보이지 않게)하거나 `adopt on` 을 곡 시작 전 정지 상태에서 완료하게. 곡 중 `adopt on` 은 거부해도 됨(개발용 도구).

## 목표
채택 켬의 프레임당 장식 CPU 합계가 끔보다 낮아지는지가 판정 기준이다(끔 3.16~3.21ms). 목표 ≤ 2.5ms. 낮아지지 않으면 어느 단계가 막는지 분해표로 결론낸다(거짓 낙관 금지).

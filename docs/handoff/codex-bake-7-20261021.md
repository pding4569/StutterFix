## 해야 할 것
1. **재준비에서 지원 장식 유지**: `scrDecoration.Setup` postfix 에서 읽는 "초기 스냅샷"(startPos/pivot/크기/색 등)을 맵 열기 때 한 번 저장하고, `PrepVfx`/seek 로 재준비될 때는 **같은 맵(같은 장식 인스턴스 목록)이면 저장된 초기 스냅샷을 재사용**해 표를 다시 굽는다(tilebake 의 "기준 스냅샷 재사용" 방식 참고: `wt-tilebake` 의 `FloorBake.cs`, 브랜치 `codex/night-tilebake`). 인스턴스 ID 목록/개수가 바뀌었거나 장식 객체가 재생성되면 거부하고 이유를 로그. 재준비 뒤 `지원=` 수가 첫 준비와 같아야 한다(`SnapshotChangedException`/세대 처리와 충돌 없게). 초기 스냅샷은 PrepVfx 의 ScrubToTime(0) **이전** 상태여야 한다(이미 적용된 효과를 다시 굽지 않게).
2. **크기 채널 시간 오차 원인**: 초반 경로의 크기 X/Y 가 위치보다 크다(p99 2.67 vs 1.95 프레임). 원인을 코드/로그로 가린다: (a) 크기 시작값을 첫 Step 에서 지연해 읽는 의미(`DecoAnim.Startup`, 축별 Kill(true) 완료값)를 굽기가 다르게 가정하는지, (b) 이징 종류, (c) 같은 장식의 위치 효과와 크기 효과 T0 차이. `decobake verify` 에 크기 상위 3개 장식 진단(효과 목록, 시작/끝값, 실제 첫 움직임 프레임, 최대 오차 부근 12행, 시간환산)을 위치와 같은 수준으로 추가. 확정 못 하면 필요한 다음 관측을 구체적으로.
3. **무거운 구간 시간 오차**: 재준비 지원 수가 정상(23,631)일 때 262~276초 구간에서 오차가 어떤지 보려면 1번이 먼저다. 이 구간은 프레임이 길다(약 90~100 FPS, 11ms 안팎)는 점이 초반(430~480 FPS, 2ms)과 다르다: `tb` 의 1% 보정 이득이 프레임이 길 때 느리게 따라붙는지, `smoothDeltaTime` 사용 여부, 긴 프레임(>20ms) 후 재동기 임계(50ms)와의 상호작용을 오프라인 fixture 로 시뮬레이션(프레임 길이 11ms·지터·가끔 30~60ms 프레임)하고 필요하면 이득/임계를 프레임 길이에 맞게 조정(근거와 함께, 임의 보정 금지).
4. 빌드 3종(`-c Release`; `-p:Edition=Player`; `-p:Edition=Player -p:AutoTestBuild=1`) 오류 0 + LoadCheck + fixture. Player 제외, 그림자 모드, `Module.ResolveSignature` 금지, 새 Harmony 패치 없이.

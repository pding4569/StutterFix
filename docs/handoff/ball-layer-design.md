# 공 따로 그리기 층 설계 (프레임 늘리기 공 일그러짐의 근본 해결)

## 문제

프레임 늘리기가 공(행성: 몸통·빛(Glow)·고리(Ring)·꼬리(Tail 파티클)·스파크)을 보간 화면에 그릴 때, **이미 합쳐진 진짜 화면 두 장**에서
공 픽셀을 거꾸로 분리한다(`native/sfnative/framegen_block.h` 의 `colorAt` 안 행성 층). 공 위에는 빛, 꼬리 연기, 궤도 고리,
타일 빛, 필터가 겹쳐 있어 분리 규칙이 어떤 장면에서는 꼭 어긋난다(회색 반투명 공, 어두운 고리, 빛이 두 겹). 규칙을 더해도 끝나지 않았다.

## 해결

진짜 프레임마다 **공만** 따로 한 번 더 그려 둔다. 그러면 공의 정확한 색·투명도를 알아서, 배경과 분리하는 추측이 필요 없다.
보간 화면은 `배경(공 없는 화면) + 공 층(사이 위치로 옮김)` 이다.

### 공 층을 만드는 법: 두 배경 매트(matte)

공 렌더러(몸통 SpriteRenderer, 빛 SpriteRenderer, 고리 LineRenderer, 꼬리·스파크 ParticleSystemRenderer, TrailRenderer)만 보이는 카메라로
같은 카메라 위치·크기로 두 번 그린다: 검은 배경 `Cb`, 흰 배경 `Cw`. 블렌드 방식(불투명 알파 / 가산 / 곱)에 상관없이

- 투명도(가려짐) `a = 1 - mean(Cw - Cb)` (채널별 `1-(Cw-Cb)` 의 평균 또는 채널별 그대로)
- 공이 더하는 색 `S = Cb` (검은 배경 위의 결과 = 공이 얹는 색, 이미 a 를 곱한 premultiplied)

보간에서의 합성: `결과 = 배경 * (1 - a) + S` (premultiplied over). 가산 빛은 a≈0, S>0 → 배경에 더해진다. 불투명 몸통은 a=1.

공 렌더러가 몇 개뿐이라 그리기 비용은 작다(전체 장면을 다시 그리지 않는다).

### 배경(공 없는 화면)

지금 진짜 `world` 에는 공이 들어 있다. 두 가지 길:

- (A) 공 렌더러를 끄고 `world` 를 그린다 → 공 층을 따로 얹는 모든 출력에서 공은 오로지 공 층에서만 나온다. 가장 깔끔하다.
  비용: 이미 `worldCamera.Render()` 로 그리므로 렌더러를 끄고 켜는 것뿐. 진짜 프레임(실제 Present)에는 원래 게임 그림이 그대로 나가야 하므로
  **게임 화면(camRT)은 건드리지 않고 `world` 복사본만 공 없이** 그린다(지금도 `world` 는 모드가 따로 그리는 별도 렌더다).
- (B) 지금처럼 공이 든 `world` 를 두고 공 층의 `a` 로 나눈다(`배경 = (world - S) / (1-a)`) → a→1 에서 불안정. 쓰지 않는다.

## 구현 단계 (Codex)

1. **조사(코드만 읽기)**: 행성 오브젝트의 레이어, 렌더러 목록과 셰이더/블렌드(`planetRed/planetBlue` 아래: `PlanetRed`, `Glow`, `Ring`, `Tail`, `Sparks`, `Core`,
   `TrailRenderer`), 게임이 그 위에 거는 후처리(블룸 등)가 `world` 에 포함되는지. `tools/ilscan` 과 기존 `FrameGen.cs`(`redRenderers`, `PlanetEnvelope`)를 참고.
2. **관리 코드 `FrameGen.cs`**:
   - 공 층용 RT 3장 링 ×2(검은·흰 배경) 또는 한 장에 가로 두 칸. 색 `ARGB32`(공은 LDR) 부족하면 `ARGBHalf`.
   - 매 진짜 프레임: 공 렌더러만 켠 별도 카메라로 두 번 `Render()`. 그 뒤 `world` 렌더는 공 렌더러를 끄고(그리기 직전 enabled=false → 직후 복원, 예외 시에도 복원).
   - 패킷에 두 장의 포인터를 싣는다. `Packet` 은 152바이트 고정(`static_assert`, `Marshal.SizeOf`) → 새 필드를 넣으면 크기와 네이티브 `block version` 을 같이 올린다(5 → 6, 게임 재시작 필요).
   - 설정 `FrameGenBallLayer`(기본 **끔**). 끄면 지금 경로 그대로(이전 합성).
3. **네이티브**:
   - `Slot` 에 공 층 이미지 두 장 추가(복사 또는 보유), `framegen.cpp`/`framegen.h` 의 packet 읽기.
   - `framegen_block.h` 의 `colorAt`: 공 층이 있으면 `bg = 배경 보간(공 없음)`, 공 위치는 두 진짜 위치의 호(`orbit`) 보간(지금 코드 재사용),
     각 진짜 프레임의 공 층을 그 사이 위치로 옮겨 `lerp`, 합성은 위 premultiplied over. 끄면 지금 코드.
4. **시험(Claude 가 게임을 돌려 확인)**: `tools/framegenlab/dupcap` 전체 해상도(3440x1440) 연속 8장(h90000, HELLO 2026, 60 FPS 제한·4배)에서
   생성 프레임의 공이 진짜 프레임과 같은 크기·밝기, 빛이 한 겹, 어두운 고리 없음. 정지 장면에서 공 층 off/on 이 같은지(공이 안 움직일 때 두 방식 결과 차이 0).

## 위험·주의

- 게임 필터(블룸 등)가 공 위에 걸리면 공 층에 안 들어가 밝기가 어긋날 수 있다. 1단계 조사 결과에 따라 필터가 걸린 뒤의 공만 쓰는 대안(필터 전 `world` 에서 공만 렌더)을 검토.
- 공이 두 개(빨강·파랑)이고 서로 겹칠 때 층은 합쳐 하나로 둔다(둘 다 한 카메라에 그린다).
- 커스텀 공 모양(이모지, 스킨), 코옵 꼬리(`TailCoop`), 꺼진 공은 `renderer.enabled && activeInHierarchy` 인 것만.
- 진짜 Present 의 게임 화면은 원래 그대로여야 한다(입력·판정·화면 일치). 공 렌더러를 끄는 것은 모드의 `world` 렌더에만.
- 비용: 공 층 2회 렌더 + 합성 샘플 몇 개. 곡 중 프레임당 GPU 증가를 `PresentMon`/`GPU timestamp` 로 재서 결과에 적는다(0.2ms 안팎 목표).
- 정식 빌드로 넣기 전에 기본 꺼짐으로 두고 Claude 가 시험한다. 되돌릴 수 있게 설정 하나로 이전 경로가 살아 있어야 한다.

# 코덱스 작업: "겹친 층 더미" 조사와 한 번에 계산 시제품 (2026-11-13)

작업 폴더 `E:\StutterFixWork\wt-v14prod` (claude/adofai-renderer). 커밋·푸시·게임 실행·설치 DLL 교체 금지. 한국어 보고, 결과 문서 `docs/handoff/stack-20261113-result.md`.

## 배경
`zcull census`(ZCull.cs, 커밋 71d10ed)로 HELLO 50초를 보니 덧칠(화면 약 200장 분량)의 주인이 같은 이미지 `pt2_circle1.png` 흰 원 약 150장이다.
색 (1,1,1,0.02), 크기 20 에서 0.1 씩 줄고, 위치·회전이 조금씩 다르며 order 가 연속(50, 49, ...). 일반 블렌드(SrcAlpha, OneMinusSrcAlpha).
이런 "같은 텍스처·같은 재질·연속 순서·일반 블렌드" 층 더미는 한 패스에서 계산할 수 있다:
결과 = dst·Π(1-aᵢ) + Σ cᵢ·aᵢ·Π_{j>i}(1-aⱼ). 색이 모두 같으면(흰색) = dst·T + c·(1-T), T = Π(1-0.02·texAlphaᵢ(p)).
원의 안쪽(텍스처 알파 1, RGB 같음)에서는 T = 0.98^k(k = 그 픽셀을 덮는 원 수) 라 텍스처를 안 읽고 끝나고, 가장자리 띠만 샘플하면 된다.

## 할 일
1. **조사(진단, DEV||AUTOTEST 전용)**: `zcull census` 에 더미 분류를 더한다(또는 `stack census` 새 명령). 그리기 순서에서 연속이고 같은 sharedMaterial·같은 sprite.texture·일반 블렌드·같은 색 RGB 인 층을 한 더미로 묶어, 더미별 층 수·조각 수(기존 GPU 세기 재사용)·전체 조각 중 비율·색 알파 분포·크기 범위를 로그. 맵 전체 조각 중 "층 4개 이상 더미" 비율을 한 줄로: `[stack] fragments_total=F in_stacks=S (x%) stacks=N top: tex=... layers=... frags=...`. `E:\StutterFixWork\zcull_run.py` 에 맵 키를 늘려 hl50·hl86·dd55·s7 120·wf260·sh88·ar262 를 돌릴 수 있게(이미 있으면 그대로). 실행은 Claude 가 한다.
2. **오차 시험(게임 없이, tools/stackfold/)**: Unity 없이 C# 또는 Python 으로 원본 경로(층마다 8비트 RGBA 대상에 순서대로 블렌드, 쌍선형 샘플, Unity 반올림 규칙: 각 블렌드 후 8비트 UNORM 저장)와 한 번에 계산(float 로 누적 후 한 번 반올림)을 같은 입력으로 비교한다. 입력: HELLO 50초 더미를 흉내 낸 흰 원 150장(알파 0.02, 크기 20→5, 회전·이동 조금씩, 실제 pt2_circle1.png 은 `D:\얼불춤 맵 파일\HELLO (BPM) 2026\` 아래에서 찾아 읽기, 없으면 부드러운 원) 위에 여러 배경(검정, 흰, 무늬). 출력: 픽셀 최대 차이, 차이 >0 / >1 / >2 비율, PSNR. 카메라 RT 형식이 8비트(ARGB32)인지 ARGBHalf 인지에 따라 결과가 달라지니 두 경우 모두. 게임의 실제 camRT 형식은 코드(LowEnd.cs RT 만드는 곳 등)에서 찾아 적는다.
3. **GPU 시제품(가능하면)**: 같은 입력을 Unity 밖에서는 못 재므로, 셰이더 하나(HLSL)로 "더미 한 번에" 픽셀 셰이더 초안을 tools/stackfold/StackFold.shader 에 쓴다: 층 변환 배열(최대 256)·색·텍스처를 받아, 안쪽 판정은 해석적으로(원 텍스처의 알파=1 반경을 미리 구해 둠), 가장자리 띠만 샘플. 게임 연결은 하지 않는다.

## 왜 하는가 (Claude 측정)

Arche 무거운 구간(2560x1417)은 한 프레임에 픽셀 셰이더 3억 4,400만 번(화면 95장분)을 칠한다. GPU 경과 3.07ms → 초당 약 1,100억 픽셀로, RTX 4060 Ti 의 반투명 덧칠(ROP: 렌더 타깃 읽고-섞고-쓰기) 한계 근처다. 400 FPS(2.5ms)는 지금 방식으로는 픽셀 수를 30% 넘게 줄이지 않는 한 불가능하다. 투명 부분 잘라내기·저해상도·가리기는 다 해 봤고 각각 몇 %다.
근본 해결 가설: **겹친 층을 사각형마다 따로 섞지 말고, 화면 픽셀마다 셰이더 안에서 여러 층을 한꺼번에 합성하고 렌더 타깃에는 한 번만 쓴다.**
- 미리 곱한 알파 "over" 는 결합 법칙이 성립한다: 위에서 아래로(front-to-back) `C += T * c_i; T *= (1 - a_i)` 를 누적하고 마지막에 `dst = C + dst * T` (섞기 One, SrcAlpha 계열) 한 번. 더하기(LinearDodge)는 `C += T * c_i` 만.
- 층마다 드는 것이 "렌더 타깃 읽기·쓰기"에서 "텍스처 샘플 1번 + 덧셈"으로 바뀐다(텍스처 샘플 속도가 ROP 속도보다 몇 배 높다).
- 위에서부터 누적하므로 `T < 0.5/255` 가 되면 그 아래 층은 전부 건너뛸 수 있다(반투명 층이 10여 장 겹치면 아래는 8비트에서 안 보임) → 반투명 가리기.
이 가설이 이 GPU 에서 실제로 빠른지, 몇 배인지 **만들기 전에** 실험실에서 잰다.

## 벤치 내용 (`GpuDecoLab.CompositeBench`, 새 파일)

공통: 대상 RT 2560x1440 ARGB32(게임 camRT 는 HDR 아님, MSAA 없음), 배경은 임의 색 그림으로 채워 둠. 층 텍스처는 1024x1024 16장짜리 Texture2DArray(절반은 안개처럼 부드러운 알파 0.2~0.6, 1/4 은 별처럼 80% 가 알파 0 인 점무늬, 1/4 은 가장자리만 불투명한 레터박스/비네트). 층마다 다른 아핀 변환(위치·회전·크기)과 색·투명도(StructuredBuffer).
층 수 N = 8, 16, 32, 64. 장면 3가지: (S1) 모든 층이 화면 전체를 덮음, (S2) 층마다 화면의 30~100% 를 덮는 회전 사각형, (S3) S1 인데 층의 1/4 이 더하기 혼합.

방법:
- **A1**: 층마다 그리기 1번(사각형, One OneMinusSrcAlpha). 지금 원래 방식.
- **A2**: 사각형 N 개를 메시 하나로 한 번에(GpuDeco 구간과 같은 꼴).
- **B1**: 화면 사각형 1개, 픽셀 셰이더가 N 층을 위에서 아래로 반복(사각형 안인지 검사 → 안이면 `SampleLevel` → 누적), 조기 종료 없음. 반복 횟수는 상수가 아니라 uniform(동적 반복).
- **B2**: B1 + `T < 0.5/255` 면 반복 종료.
- **B3**: B2 + 화면을 32x32px 칸으로 나눠 칸마다 "이 칸에 걸치는 층 목록"을 컴퓨트 셰이더로 만들고(매 프레임), 픽셀 셰이더는 자기 칸 목록만 돈다(S2 용).
측정: 방법·장면·N 마다 GPU 시간(ms). D3D11 타임스탬프 쿼리를 못 쓰면 한 프레임에 그 패스를 K 번 반복해 그리고 `AsyncGPUReadback(1x1).WaitForCompletion()` 으로 GPU 를 비운 뒤 Stopwatch 로 재서 K 로 나눈다(K 를 바꿔도 기울기가 같은지 확인). 워밍업 뒤 20회 중앙값. 측정 시각의 다른 프로세스 GPU 사용률도 한 줄 적는다(배경 화면 프로그램이 15% 쓰는 PC 다).
정확성: 같은 장면에서 A1 결과와 B1/B2/B3 결과의 RGBA 최대 차이·평균 차이(8비트). 순차 섞기는 층마다 반올림하고 한 번에 합성은 한 번만 반올림하므로 몇 LSB 차이는 예상된다. B2 가 건너뛴 층 수의 평균도 기록.

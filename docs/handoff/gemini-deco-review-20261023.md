# Gemini 검토 요청 — 장식 트레이스 GPU 전곡 경로

너는 Unity D3D11 렌더링·GPU 컴퓨트·CPU/GPU 동기화 최적화 엔지니어다. 아래 구현과 실제 측정값을 검토하고, 병목을 구분할 최소 실험과 개선 설계를 제안해라. 코드가 없는 부분을 사실로 가정하지 말고 필요한 코드 부분을 요청해라.

## 환경과 목표

- StutterFix: 얼불춤 장식 애니메이션 최적화 모드. Unity 6 Mono, C# netstandard2.1, C++ D3D11 플러그인.
- 실제 시험 3440×1440·144Hz·D3D11·VSync 0.
- 목표는 원본 정렬·시각·충돌체 보존과 순간 끊김 제거다.
- GPU 경로 CPU 비용: 관리 코드 + 네이티브 렌더 스레드 합계 평균 0.5ms 이하.
- 같은 구간 OFF/ON/ON/OFF FPS +25% 이상, 새 30ms 초과 끊김 0.

## 구현

1. 맵 열기에서 장식별 위치·회전·크기·색·불투명도·시차 16채널 이벤트 표를 준비한다.
2. 곡 시각 하나로 평가하면 원본과 위상이 어긋나 폐기했다. 효과별 실제 시작과 원본의 float `progress += dt` 시계를 따라간다.
3. CPU가 활성 효과 소스별 이징을 계산하고, 바뀐 채널 및 sourceE/progress를 GPU에 업로드한다.
4. ComputeShader가 월드 정점을 계산한다. 적격 장식은 독립 MeshRenderer로 그리고 원래 SpriteRenderer는 forceRenderingOff 한다. 원래 재질·텍스처·정렬 키·충돌체를 보존한다.
5. Unity Mesh 정점 버퍼가 각각 별개라서 계산한 정점을 각 메시 버퍼로 복사한다. native deferred command list에서 raw UAV 8개마다 한 번 Dispatch하고, Unity 렌더 스레드의 플러그인 이벤트에서 ExecuteCommandList(TRUE)한다.
6. 두 알파 인자가 모두 상수이고 하나가 정확히 0인 경우에만 대체 렌더러를 끈다. 움직이는 알파·불확실한 값에는 생략을 적용하지 않는다.

## 측정

### 기존 좁은 구간

- Arche 257~300초를 9개 준비 구간으로 나눈 후보.
- 262/270/276초 원본 대비 픽셀 차이 각각 0.
- 당시 ABBA 평균 127.19→170.86 FPS(+34.33%).
- 단, 원시 로그에 fuse 진단이 켜져 있었다. **진단 없는 이득으로 일반화할 수 없다.**

### 전곡 합집합

- 전곡 적격 장식 23,547개를 한 벌로 준비한다. 시각별 가시성 예측으로 후보를 누락시키지 않는다.
- 20/88/262초 실제 켜진 대체 렌더러는 약 9/18/1,730개다.
- 렌더러를 꺼도 정점 복사는 23,547개 전체에 남는다. 8개씩이면 매 프레임 약 2,944개 복사 Dispatch다.
- 처음부터 308.4초 포탈까지 GPU 경로 유지: native 제출/실행 25,603/25,603·오류 0.
- 모니터 평균 83 FPS, 최악 29ms·30ms 초과 0. 전체 OFF 대조는 없으므로 인과적 손실률은 주장하지 않는다.

### 정확한 알파에 따른 복사 생략

- 목적지 512개씩 46개 command-list 묶음. 실제로 꺼진 렌더러만 있는 묶음은 실행하지 않는다.
- 프레임별 마스크는 128칸 SPSC 큐에 넣는다. 늦게 실행된 이벤트가 다음 프레임의 마스크를 쓰지 않게 했다.
- 독립 D3D11 fixture: 1/513/1,715개 버퍼 ×281패턴 바이트·상태 복원 오류 0. 큐 wrap·overflow 거부·다른 producer 거부·삭제 token 검사 완료.
- 정렬 순서대로 512개씩 묶은 후보의 진단 없는 ABBA:
  - OFF 124.421→ON 67.547 FPS(-45.71%).
  - 관리+native CPU 평균 0.681857ms.
  - progress 0.245572ms, dispatch 0.311413ms, native 실행 CPU 상한 약 0.116948ms.
  - progress에는 소스 진행·dirty 채널 업로드·sourceE/progress 업로드가 함께 포함된다.
  - dispatch에는 Unity 명령 제출 비용이 포함된다. 순수 이징 시간/GPU 실행 시간으로 해석하면 안 된다.
  - 오류 0, 안정성 4항목 통과, 새 30ms 초과 끊김 0. **성능 관문 실패.**

### 최신 준비 중 후보

- 렌더러 생성 순서·그리는 순서·GPU 원본 정점 순서는 유지한다.
- 복사 목적지/원본 offset 쌍만 비슷한 등장 시각끼리 준비 때 정렬한다. 시각 힌트는 배치 근접성 용도뿐이고 실제 생략은 정확한 알파 상태가 결정한다.
- 비연속 원본 offset을 읽는 scatter 복사 fixture는 바이트 오류 0.
- 게임 88초 활성 묶음 1/46. 생략/모든 묶음 실행의 화면 차이 전체 4,953,600픽셀에서 0.
- 262초 활성 묶음 5/46. 처음에는 캡처 도구의 8장 제한에 걸렸고, 해당 지점만 분리해 재시험했다. 생략/모든 묶음 실행 및 다시 생략의 화면 차이는 전체 4,953,600픽셀에서 각각 0이었다. 제한값은 늘리지 않았다.
- 최신 후보 성능은 아직 확인 안 됨.
- 원본 게임 대비 일부 새 정지 표본에 최대 1~2/255 차이가 남았다. 완전히 0이라고 주장하지 않으며 원인은 미확정이다.

## 제한과 별도 미완료 항목

- 큰 메시로 억지로 합쳐 정렬을 바꾸는 방식은 실제 픽셀 검증에 실패했다.
- MinHook·모든 draw 가로채기·Steam 우회·두 번째 swapchain 금지. 원래 swapchain/보통 Present 유지.
- 게임 셰이더/ReShade 코드를 라이선스 확인 없이 복사할 수 없다.
- 연구용 기본 꺼짐, 일반 Player 제외. 배포 승인과 분리한다.
- readback/캡처는 성능 판과 분리한다. per-decoration Stopwatch와 매 프레임 전체 renderer/material/Transform 조회를 추가하지 않는다.
- 현재 GPU→CPU 끄기는 논리값을 복원하지만 진행 중 CPU 애니메이션 Rec를 재생성하지 않는다. 연속성 보완이 필요하며 값 복원 검사만으로 해결됐다고 보지 않는다.

## 답변 요청

1. 확정 가능한 사실과 가설을 구분해라.
2. 복사 Dispatch 수·ExecuteCommandList 비용·dirty 업로드·Unity 렌더 큐 대기를 구분할 **최소 실험 3개**와 각 실험의 측정값/반증 조건을 제시해라.
3. 독립 렌더러 정렬을 유지하면서 장식별 메시 버퍼 복사를 줄이거나 없앨 수 있는 Unity/D3D11 경로를 검토해라. 불확실한 API/가정과 필요한 셰이더 변경을 명시해라.
4. 최신 복사 근접성 후보의 검증 가치와 실패 조건을 설명해라.
5. GPU→CPU 전환에서 시작값·진행률·이징·교체/완료 의미를 보존하는 안전한 복구 설계를 제시해라.
6. 가장 먼저 할 작업 하나, 필요한 코드 부분, 검증 기준을 적어라.

평균 FPS 상승을 보장하거나 GPU 시간을 CPU 제출 시간으로 대체하지 마라. Microsoft·Unity 공식 문서로 API 제약을 확인해라.

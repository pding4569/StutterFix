# Codex 작업 T: 기능·토글 전수 감사 (2.8.0 정리용) + "측정 빌드와 실제 배포 빌드가 다르게 동작하는 곳" 찾기 — 소스 코드 변경 금지, 게임 실행·Mods 설치·커밋 금지

결과: `docs/feature-audit-2.8.0.md` (**apply_patch 로 UTF-8 BOM**, 한글 확인) + 검토 메모 `docs/handoff/codex-featureaudit-20261019-result.md`. 소스(.cs)는 건드리지 않는다(조사만). 사용자가 이 표를 보고 "켤 것 / 실험 탭으로 옮길 것 / 지울 것"을 정한다.

## 배경
사용자 질문: "기능을 넣으면서 켜 놓고 시험했는데, **꺼서 시험한 것**은 없느냐?" → 측정(PlayerAuto/Dev 빌드, 모드 폴더의 `*-on`/`*-off` 파일, Settings.xml 값)과 사용자가 실제로 받는 정식 Player 빌드의 기본 동작이 **다른 곳**이 있으면 그 결과가 실제 프레임에 안 나온다. 또 실험용 기능이 너무 많이 쌓여서 정리해야 한다: **켤 건 켜고, 필요 없는 건 "실험" 탭으로 옮기거나 없앤다.**

## 할 일
1. **목록**: 모든 기능 스위치를 찾아 표로. 소스: `Settings.cs`(설정 필드와 기본값, Settings.xml), `StutterFix.cs` 의 `File.Exists(...)` 플래그 파일(`*-on`/`*-off`/`*-verify` 등 전부), `SettingsWindow*.cs` 의 토글·페이지·탭, `Edition.Dev`/`MeasureBuild`/`AutoTestBuild` 분기(`#if DEV`, `#if AUTOTEST`, `Edition.*`). 열: 이름 / 어디서 켜고 끄는지(설정 창 페이지·탭, Settings 필드, 플래그 파일) / **정식 Player 빌드에서의 실제 기본값**(코드로 확인; 선언 기본값과 로드 때 덮어쓰기가 다를 수 있음 — 예: `TightLate.SkipSame` 선언 true, 로드 때 `tightskip-on` 파일 유무로 덮어써 실제 꺼짐) / 사용자에게 보이나(설정 창) / 한 줄 설명 / 이득의 근거(`docs/optimization-36.md` 등에서 찾은 측정값, 없으면 "측정 없음") / 위험·부작용(알려진 것) / **권고**: `켬(기본)`, `끔(실험 탭)`, `없앰` 중 하나와 이유.
2. **측정 빌드 ≠ 배포 빌드 점검**: (a) `#if DEV || AUTOTEST`, `Edition.Dev`, `MeasureBuild`, `AutoTestBuild` 분기 중 **기능의 동작(결과·성능)을 바꾸는 것**을 모두 찾는다(진단·로그·명령은 무시). 예: 측정 빌드에서만 일부 패치가 켜지거나 건너뛰거나, `Settings` 기본값이 다르거나, 측정용 프로브가 Harmony 래퍼로 비용을 부풀리거나(Dev 에서 호출당 2.5배), 자동 시험이 `Settings` 를 바꾸는 곳(`sf_run` 의 `settings`, `auto on`, `RDC.auto` 등). (b) 측정 하네스(`tools/sfmeasure`, `AutoTest.cs`)가 정식 사용자와 다르게 하는 것(자동 플레이, 설정 덮어쓰기, 모드 폴더 플래그 파일, `Settings.xml` 사본). (c) 위 중 "이득을 측정했지만 정식 Player 에서는 그 기능이 꺼져 있거나 다르게 동작할 수 있는" 항목을 **별도 표**로: 기능 / 측정 때 상태 / 배포 기본 상태 / 영향 / 해결 제안.
3. **실험 기능 정리 제안**: `Settings` 중 설정 창에 있는 것들을 현재 탭/페이지 구조와 함께 정리하고, 지금 "실험" 탭(또는 비슷한 곳)이 있는지, 없으면 어떻게 만들면 되는지(`SettingsWindow` 구조 읽고 제안; 코드 변경 금지). 각 항목에 대해 위 권고를 근거와 함께.
4. 기본 켬 후보는 반드시 근거(측정값 + 비트 동일/검증 근거)와 함께, 근거가 약한데 켜져 있는 것은 "재검토" 로 표시.
5. 맨 위 요약: ① 정식 Player 기본 상태에서 켜져 있는 기능 목록(이름만) ② 측정 때와 배포 때가 다른 곳 N개(제목만) ③ 사용자가 결정해야 할 항목.

## 규칙
- 코드로 확인한 것만 사실로 적는다. 모르면 "미확인". 헤르츠 맵 이름·게임 DLL·개인 정보 금지.
- 표는 마크다운, 길어도 괜찮지만 읽기 쉽게(범주별 소제목).

브랜치 `claude/player-port`. 설정 `GpuDeco`(기본 0, 꺼짐)·`GpuDecoImages`(기본 1). 설정창 위치: 플레이 → 실험 탭 "GPU 장식 처리 (실험)". 환경은 이 문서의 숫자 전부 **2560x1440@120(모니터 끈 상태)** 이며 앞선 3440x1440@165 숫자(끔 73.6 → 켬 270.7 FPS, Arche 262초)와 섞지 않는다.

## 검증한 것
- 두 빌드(플레이어, AUTOTEST) 오류 0. `GpuDecoPlayerCheck` 438개 검사: 플레이어 DLL에 시험용 타입 없음, 번들 임베드·해시 일치.
- 화면 일치(같은 일시정지 장면에서 켠 채 캡처 vs `live off` 캡처, 끔-끔 대조군 차이 0): 곡 40/110/300초 차이 0, 262초 최대 3~4(0.0003%). 180초는 아래 한계.
- 다시 하기 7라운드 연속 켜짐, 관리 힙 1295→1066→1037(평탄), 유니티 할당 1019→1090MB(첫 두 번 후 평탄).
- 곡 중 설정 끄기: 장면 정상, 오류 없음. 에디터 처음부터·중간 시작 모두 켜짐.

## 이번 밤에 고친 문제
1. 카메라 조건이 렌더 텍스처(camRT)를 거절 → 게임 화면에서 꺼짐.
2. 텍스처 52개 한도(제 오해: 곡 전체 99개가 배열 3종+직접 44개로 들어간다) → 통합 포기 조건 제거.
3. 에디터 재생에서 `scrController.Update` 앞 후크가 불리지 않아 켜지지 않음 → `Tick`에서도 켜기 시도.
4. 다시 하기 3번째부터 `초기 Setup 누락`으로 꺼짐 → 처음 Setup 기록·관리자 참조 유지.
5. 재생 준비 14.2초 → 약 5.3초(표 지문 SHA256 5.1초가 검증용이라 제품에서 생략).
6. 매 프레임 고정 비용: 검증·프록시 확인·플레이어 검사 주기화, 명령 버퍼 2회 실행 → 최소 디스패치(관리 코드 0.35→0.04ms).
7. 마스크 복사(`GpuDecoCopy.MaskedEnabled`)를 켜지 않아 독립 렌더러가 항상 전체 복사(GPU 18ms) → on8masked 와 같게 켬. 독립 렌더러 장식을 복사 순서 앞으로 모으는 재배치도 추가(텍스처 초과 맵용).
8. 통합을 못 켜면(소유만) 오히려 훨씬 느려짐(101→17 FPS) → 통합 불가면 켜지 않고 원본 유지. 에디터 중간 시작처럼 CPU 처리 장식이 있으면 그 장식만 통합에서 빼고 원본 렌더러를 장벽으로 둔 채 통합을 켠다.
9. 곡 시작 직후 60프레임 따라잡기 구간에 켜면 곧바로 원본으로 복귀 → 중간 시작(곡 위치>0.5초)에서만 그 구간을 기다린다.
10. Codex(sol): 직접 텍스처를 안 쓰는 구간용 셰이더 변형 `NO_DIRECT_TEXTURES`(구간 519개 중 약 150개). 새 번들에 포함. 효과는 거의 없었다(그리기 횟수가 비용).
11. 트림(`TightVariant`)에 사각형 조건 추가(방어적. 180초 문제의 원인은 아니었음).

## 알려진 한계 (사용자에게 알릴 것)
- **재생을 시작할 때마다 준비가 약 5초 더 걸린다**(장식 2.8만 개). 다시 하기도 매번 다시 준비한다. 설정창 설명에 적었다. 라운드 간 준비 결과 재사용은 미구현.
- **정렬 동점 한계(`TieAllBarriers=false`, 기본)**: 지금 숨겨진 비소유 장식(`sprite`/`renderer`)이 곡 중에 깨어나 소유 장식과 같은 정렬 묶음(같은 z)에 놓이면 그리는 순서가 달라질 수 있다. Arche 180초에서 옅은 띠 하나가 빠졌다(켬 vs 원본 최대 17/255, 픽셀 9%; 전체 순서 검사 위반 9건). 켜면(`true`) 정확하지만 262초 FPS 295→128(독립 렌더러 2,854개의 CPU 비용 +4.4ms). 정확히 막으려면 깨어나는 순간의 재계획(100ms+ 끊김)이나 항목별 동적 전환이 필요하다. **사용자 결정 필요.**
- 가벼운 구간은 끔보다 약 0.3ms/프레임 느리다.
- 카운트다운 중 켜는 순간 프레임 약 240ms 한 번.
- 이미지 장식이 바뀌는 구간은 `NO_DIRECT_TEXTURES` 변형을 쓰지 않는다(보수적).

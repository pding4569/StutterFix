# GPU 쪽 근본 재설계 — "8비트 덧칠의 정확한 대수" 조사 (2026-11-13)

## 배경 (이미 확인된 것, 다시 하지 말 것)
- 무거운 장면 GPU 비용 = 반투명 덧칠(HELLO 50초 약 200장 분량). camRT 는 ARGB32(R8G8B8A8_UNorm).
- 픽셀 단위 깊이 가림: 0% (무거운 층에 불투명 픽셀 없음, docs/handoff/zcull-20261113.md, ZCull.cs).
- 같은 텍스처 층 더미를 수식(1-(1-a)^k)으로 한 번에: 최대 10/255 오차 → 손실이라 보류. **이번 조사의 핵심은 수식 대신 GPU 의 8비트 반올림을 그대로 흉내 내서 비트 동일하게 만드는 것.**
- 한 번에 합성(compute) 벤치(codex-20261112a-result.md): 조기 종료 없으면 ROP 와 같거나 느림(64층 0.87배). 이득은 전부 "건너뛰기"에서 나옴.
- 타일 인스턴싱 불가(tilerender census). GpuDeco(자체 장식 렌더러)는 이미 비트 동일로 존재 — 그 셰이더/블렌드 상태를 기준으로 삼을 것.

## 생각 (검증 대상)
알파 블렌드는 채널마다 dst(8비트) → dst'(8비트) 함수다: dst' = Q(src·a + dst·(1−a)) (Q = GPU 의 UNORM 변환/블렌드 반올림).
이 함수가 셰이더에서 **비트까지** 재현되면 다음이 모두 원본과 똑같은 결과로 가능하다:
1. **같은 층 반복 LUT**: 같은 색·같은 알파로 완전히 덮는 층 k개 = f^k(dst). 256×k 표 한 번 조회로 k층을 처리(텍스처 읽기·ROP k번 → 1번). 가장자리(텍셀 알파가 1이 아닌 곳)만 원래대로.
2. **고정점 조기 종료**: 반올림 때문에 f(d)=d 인 d 가 생긴다. 남은 층이 모두 그 d 를 바꾸지 않으면 그 픽셀은 끝.
3. **앞쪽 층 캐시(프레임 간)**: 정렬 순서 맨 아래부터 화면상 변화 없는 층들(카메라 기준 고정 장식, 정지 구간)의 합성 결과는 비트까지 같다 → 지난 프레임 결과 텍스처에서 시작하고 바뀐 층부터만 그린다.
4. 이 셋을 묶은 **타일 분류 + 픽셀별 층 목록 합성(compute)**: 화면을 타일로 나눠 덮는 층 목록을 만들고, 픽셀마다 레지스터 안에서 위 1·2·3 을 적용하며 한 번만 쓴다.

GPU 마다 반올림이 다를 수 있으므로 **게임 시작 때 사용자 GPU 에서 자체 검사**(ROP 결과와 흉내 결과 대조)를 하고 다르면 원래 길로 — 이것도 설계에 넣는다.

## 할 일 (게임 실행 금지. 게임은 Claude 가 벤치로 쓰는 중)
### A. 블렌드 정확도 실험실 (오프라인, 독립 프로그램)
- `tools/blendlab` 에 독립 D3D11 프로그램(기존 tools/framegenlab 또는 native/sfnative 빌드 방식 재사용 가능).
- 대상 블렌드 상태: 실제 장식·타일이 쓰는 것. GpuDeco 셰이더/코드와 게임 셰이더(Sprites-Default 류: 프리멀티플라이 후 `Blend One OneMinusSrcAlpha` 인지, `SrcAlpha OneMinusSrcAlpha` 인지, 가산 `One One` / `SrcAlpha One`)를 코드·에셋에서 확인해 목록을 만든다. 알파 채널 블렌드 식도 따로.
- R8G8B8A8_UNorm RT 에 dst 0..255 × 소스 색 × 소스 알파(0..255 및 셰이더가 실제로 내는 float 값들) 전수 ROP 블렌드 → 결과 읽기.
- 같은 입력으로 compute 흉내(후보 식 여러 개: float 계산 후 round-half-even / +0.5 floor / 고정소수점 9·10비트 등)를 돌려 **불일치 0 인 식**을 찾는다. 찾으면 그 식, 못 찾으면 불일치 표.
- k층 반복: 같은 층 k=1..255 ROP 실제 결과와 f^k LUT 결과 대조(불일치 0 확인).
- 고정점 분포: 실제 쓰이는 알파(예: HELLO 원 5.1/255)에서 f(d)=d 인 d 목록.
- 결과는 RTX 4060 Ti 한 대 기준임을 명시.

### B. 앞쪽 층 캐시 센서스 명령 (AUTOTEST 전용, 구현만)
- ZCull.cs 의 그리기 목록 열거(정렬 순서, 조각 수 추정)를 재사용해 `gpuexact census <프레임수>`:
  매 프레임 주 카메라 그리기 목록의 각 항목 서명 = (화면 행렬 = VP×localToWorld 비트값, 스프라이트/텍스처, 재질/MPB 색·알파, 활성, 블렌드 상태, 정렬 키).
  지난 프레임과 같은 **맨 아래부터 연속 구간**(카메라 clear·배경 포함, 카메라 자체가 움직이면 월드 층은 다 바뀜)의 조각 비율 평균/분포, 그리고 참고로 "변화 없는 층 전체" 조각 비율.
- 같은 명령에 `runs` 항목: 연속한 층 중 같은 텍스처·같은 색·같은 알파·같은 블렌드인 묶음의 조각 비율(LUT 대상 상한), 그중 텍셀 알파 1 내부 비율 추정(스프라이트 텍스처 알파 히스토그램 사용).
- 매 프레임 비용이 있어도 되는 진단이지만, 결과 출력은 끝에 한 번. bench_v14.py 에 쓸 CFG2 항목(`gxCensus`, rlNR 복제, CFG_MID 에 census 시작)과 실행 예시를 결과 문서에 적는다. 실행은 하지 않는다.

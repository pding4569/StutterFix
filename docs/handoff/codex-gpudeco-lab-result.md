**선택: Unity 6000.3.10f1의 기존 AssetBundle 경로를 유지한다. 직접 D3D11 실행에서 수치·Raw 메시 그리기·번들 생성/재로드가 통과했다. 실제 Arche export는 0개이고, 1,000구간 메시의 제출 2.723905ms는 목표 0.3ms를 초과했다. 게임 연결은 진행하지 않았다.**

## 실행과 원인 수정

- 첫 Start-Process 직접 호출은 샌드박스에서 Package Manager IPC 실패, 권한 검토 후에는 라이선스 exit 198이었다. 지시서와 같은 **직접 호출 + -batchmode -quit** 형태는 Successfully resolved entitlement details를 기록하고 실제 fixture에 진입했다. 로그인·라이선스 활성화·소프트웨어 설치는 하지 않았다. -quit 하나가 원인이라고 단정하지 않으며 성공한 전체 호출을 README에 남겼다.
- -nographics 실행은 Null Device여서 GPU fixture가 의도대로 거부했다. GPU 시험에는 이를 빼고 -force-d3d11을 썼다.
- 최초 이징 대조는 **101,475개, 최대 0.00165259838104, 평균 4.02213904572e-7, 2e-5 초과 526개**였다. [이징별 진단](../../tools/gpudeco-lab/evidence/smoke-r2.txt)에서 Circ 경계와 Elastic 위상에 집중됐다. 끝점/중간점 분기를 명시하고 HLSL asin 근사를 축소 구간 유리식으로 대체하고 precise를 적용했다. CPU 정답은 게임의 실제 DOTween.dll의 EaseManager.Evaluate다.
- 1,000개 Raw 버퍼의 복사가 맞아도 처음에는 그리기가 비었다. CPU 사본 폐기·submesh 바운드 명시·동기 셰이더 컴파일만으로는 해결되지 않았다. 같은 실행의 단일 메시 대조군은 1,573픽셀이었다. 분할 메시의 인덱스를 단일 대조군과 같은 **UInt32**로 바꾼 최종 실행에서 1,573픽셀·exit 0을 확인했다. 이 조합의 관측이며 Unity 전체의 UInt16 결함으로 일반화하지 않는다. 실패 증거는 runs-r1.txt~runs-r5.txt, 최종은 runs.txt다.
- 최초 번들은 생성됐으나 재로드에 실패했다. 일반적인 버전 호환 오류 옆에 **AssetBundleManifest의 AssetBundle module disabled** 로그가 있었다. prepare.ps1의 독립 프로젝트에 **기존 내장 AssetBundle 모듈 참조**를 명시하고 강제 재생성한 뒤 재로드·이징 대조가 통과했다. 실제 게임의 번들 호환성은 미검증이다.

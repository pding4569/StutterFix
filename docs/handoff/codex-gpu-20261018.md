# Codex 작업: Arche 90 FPS 구간의 GPU 시간 줄이기 연구 — 게임 실행·설치·커밋 금지

Claude 가 게임 측정을 맡는다. 너는 코드·IL 조사, 측정 도구 구현, 오프라인 빌드만 한다. Mods 폴더에 복사·git commit 금지.
빌드 셋 다 오류 0: `dotnet build -c Debug -p:Edition=Player -p:AutoTestBuild=1`, `dotnet build -c Debug -p:Edition=Player`, `dotnet build -c Debug`.
네이티브를 바꾸면 `native/build-sfnative.bat` 로 빌드하고 managed 내장 리소스까지 다시 빌드(문서 CLAUDE.md 참고). 가능하면 네이티브 변경 없이.
결과: `docs/handoff/codex-gpu-20261018-result.md` (한국어). 추측은 "추정".

새 측정 코드는 새 파일(예: `GpuProbe.cs`)에 두고, AutoTest.cs·StutterFix.csproj 에는 최소 줄만 더한다(다른 작업 FuseLate 와 같은 파일을 건드린다 — 먼저 `git diff` 로 그 변경을 확인하고 덮지 말 것).
측정 도구는 자동 시험/개발자용에만 컴파일(`'$(Edition)' != 'Player' Or '$(AutoTestBuild)' == '1'`, FuseProbe.cs 와 같은 조건). 켜지 않으면 비용 0. 측정 코드 자체가 끊김을 만들지 않게(매 프레임 GPU 대기·ReadPixels 금지, 쿼리는 몇 프레임 뒤 DONOTFLUSH 로 회수).

## 알고 있는 것 (Arche FULL, 곡 270초 구간, 3440x1440 165Hz, D3D11, RTX 4060 Ti)

- 10초 구간: 98 FPS, 메인 10.2ms, 렌더 스레드 4.4ms, **GPU 6.5ms**(모드 프레임 통계의 GPU 시간). 메인 쪽은 FuseLate 로 줄이는 중이고 그 뒤 상한은 GPU (약 150 FPS).
- 그 순간 애니메이션 도는 이미지 장식 1,970개(보임 1,900), 장식 전체 2만 8,828개(대부분 잠듦/안 보임). 이미지 1만 442장, 자동 한도로 긴 변 1024 까지 줄여 올림(VRAM 7.85/8GB 였던 맵).
- 카메라: BGStaticCam(3440x1440 RT, 깊이 -1.63), BGMovingCam(3440x1440 RT, -1.11), Camera(3440x1440 RT, -1), OverlayCam(화면). 필터(CameraFilterPack_*)가 맵 이벤트로 켜질 수 있다.
- 기존 도구: `tools/filtergpu`(필터별 GPU 타임스탬프, FilterGpuProbe.cs + filtergpu.dll — 지금 Mods 에 dll 없음), `native/sfnative/effects_gpu.h`·`framegen.h` 의 D3D11 타임스탬프 쿼리, 자동 시험 `bigrend`(큰 렌더러), `filtergpu`, `countmats`, `shot`.

## 할 일

1. **GPU 시간 나누기 도구** (`gpuprobe on|state|off`): 카메라마다(그리고 켜진 필터·OnRenderImage 마다) GPU 시간을 D3D11 타임스탬프로 잰다. 기존 sfnative/filtergpu 쿼리 코드를 재사용할 수 있으면 재사용. 결과: 카메라별 평균·최대 ms, 프레임 전체 GPU 와의 합 대조.
2. **그리는 것 조사** (`gpucensus`): 그 순간 각 카메라가 그리는 렌더러(컬링 마스크·enabled·forceRenderingOff·activeInHierarchy 반영)를 재질/셰이더/텍스처(실제 GPU 크기·형식·mip 유무)/정렬 층별로 묶어:
   개수, 화면에 덮는 픽셀 합(경계 상자를 카메라 화면 좌표로 투영해 화면과 겹친 넓이 합 → 겹쳐 그리기 배수 = 합/화면 넓이), 색 알파 0 인데 그리는 것, 정렬 순서대로 재질·텍스처가 바뀌는 횟수(배치 끊김 = 그리기 호출 추정), 셰이더 키워드.
   카메라 RT 크기·형식·MSAA·HDR, 그 카메라에 걸린 OnRenderImage 컴포넌트.
3. **줄일 방법 후보를 근거와 함께 정리**(구현은 확실히 같은 그림이 나오는 것만, 나머지는 후보로만):
   - 그림이 똑같이 유지되는 것: 알파 0 이라 아무것도 안 그리는 렌더러 건너뛰기, 화면 밖, 다른 불투명 물체에 완전히 가려지는 것, 같은 내용인 배경 카메라 RT 다시 그리기 생략, 배치 늘리기(같은 텍스처·재질 순서), 필터 중 결과가 원본과 같은 설정(강도 0 등).
   - 그림이 조금 바뀌는 것(옵션 후보로만, 기본 끔): mipmap, 텍스처 더 줄이기, 해상도 낮춘 RT, 필터 반 해상도(FilterHalf 기존 연구 참고).
   각 후보: 예상 GPU 절약(조사 수치 근거), 같은 그림인지 근거, 위험.
4. Claude 가 게임에서 돌릴 자동 시험 명령 순서를 결과 파일에 적어라. 예: Arche `auto on`, `game <경로>`, `press`, `wait 150`, `wait 115`, `gpuprobe on`, `wait 5`, `gpucensus`, `gpuprobe state`, `gpuprobe off`. 비교용으로 곡 240초(222 FPS)와 290초(414 FPS) 지점도.

# 이번 실행의 측정 절차 관찰

- sfmeasure.sf_quit 및 fresh 경로에는 taskkill fallback이 있다. 강제 종료 금지 임무는 kill_game을 실패 함수로 교체하고 quit 명령 뒤 프로세스 소멸을 직접 확인해야 한다. 정상 quit 중 프로세스가 먼저 종료되면 _batch가 '묶음 도중 게임이 꺼짐'으로 보고할 수 있으므로 프로세스 상태로 종료 성공을 구분한다.
- Camera.enabled를 한 번 바꾸기 전에 게임의 Update가 다시 쓰는지 IL과 중간 상태로 확인한다. scrCamera.camobj는 다시 켜진다. cullingMask 차단은 렌더 및 필터 전체 제거와 같지 않다는 범위를 기록한다.
- wait 단계의 시간 기준이 직전 단계 소요 시간을 포함한다. A/B에 서로 다른 단계 수를 넣으면 재생 길이가 달라진다. 공통 log 단계 뒤 같은 길이 wait로 맞춘다.
- 별도 실행기가 autotest.end를 바로 지우면 이전 _batch의 마지막 0.5초 로그 정리 중 끝 이유가 '?'가 될 수 있다. 병렬 진행 없이 이전 프로세스가 반환한 후 새 묶음을 시작한다. 최초 탐색 로그의 끝 표시는 원시 로그와 단계 수로 검증한다.
- 정확한 RT 결과는 요청한 RenderTextureFormat이 아니라 실제 format/graphicsFormat/depthStencilFormat으로 확인한다. 지원 여부만으로 더 작은 버퍼가 만들어졌다고 단정하지 않는다.

전역 관찰 로그는 읽기만 했다. 이번 임무의 측정 근거는 이 작업 폴더에 남긴다. 메모리를 수정하지 않았다.

- 필터 비율은 전체 로그의 표본을 무조건 나누지 않는다. OnLandOnPortal 이전 구간만 집계하고 실제 IL 타입 목록에서 Color_*와 Colors_* 이름을 모두 검토한다. '색 필터 3개 동시'와 '같은 카메라에서 연속된 색 필터 3개'는 별개의 조건이다.

## 할 일
1. **프레임 기록** `dropscan begin|end`(AUTOTEST): 미리 잡은 배열(최대 60만 프레임)에 프레임마다 곡 시각(conductor songposition_minusi, 재생 전은 음수 가능), 프레임 시간(Stopwatch, 이전 프레임 같은 지점과의 차), 가능하면 메인 스레드 CPU 시간 몫(PerfOverlay 가 이미 재는 cpu/gpu 값이 있으면 재사용)을 적는다. 매 프레임 할당 0. `end` 에서 모드 폴더 `dropscan-frames.csv` 로 쓴다.
2. **전곡 표본** ProfSamp 확장: `begin <hz> native full max=<n>` 같은 모드. 표본마다 곡 시각(메인 스레드가 매 프레임 정적 volatile 변수에 써 두고 표본 스레드가 읽음)과 프레임 번호를 같이 저장. 표본 배열은 begin 때 한 번 잡는다(250Hz × 10분 = 15만 표본 × 깊이 32 정도를 기본 상한). 링/끊김 보관도 상한을 500개로. 출력 줄 앞에 `T:<곡초>;F:<프레임>;` 를 붙인다. 기존 형식 사용처(ring, frames)와 호환 유지.
3. **오프라인 분석** `tools/dropscan/analyze.py`(파이썬 3.12, 표준 라이브러리만 + 위 symb_lib 를 경로 인자로 로드):
   - 입력: 맵별 `dropscan-frames.csv`, 표본 파일, Player.log(끊김 분류 줄).
   - 끊김: 프레임 > max(20ms, 중앙값×2.5). 드랍 구간: 0.5초 창 FPS 가 그 맵 곡 중앙값의 80% 미만이 1초 이상 이어지는 곳. 곡 시작 5초·끝은 따로 표시.
   - 각 끊김/구간의 표본과 그 맵 정상 구간 표본의 **포함 비율 차이**(on/off 프로파일 비교처럼)로 원인 후보 상위 함수를 뽑는다(관리 M: 과 네이티브 U: 모두, 우리 모드 함수·게임 함수·엔진 함수 구분).
   - 같은 원인(대표 함수/스택 접두)끼리 맵을 가로질러 묶어, 원인별 "초과 시간 합(ms) = Σ(구간 프레임시간 − 정상 프레임시간) × 그 원인의 초과 비율"과 해당 맵·구간 목록을 낸다.
   - 결과 `dropscan-report.md`(한국어, 원인별 표 + 맵별 끊김·구간 목록)와 `dropscan-report.json`.
4. 측정 오버헤드: 250Hz 표본·프레임 기록 자체가 끊김을 만들지 않는지 설명(메인 스레드 정지 시간 추정). 표본 스레드는 BelowNormal 이 아니라 기존 ProfSamp 방식 유지.
5. 빌드 3종 오류 0, LoadCheck 오류 0. 분석 스크립트는 가짜 입력으로 자체 시험.
